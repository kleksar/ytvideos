# Структура проекта

Каноническая карта каталогов описана ниже. Выпускные реестры и материалы не входят в source-only клон; их передают отдельно по согласованному хранилищу.

```text
ytvideos/
├── channels/
│   ├── paper_detour/       # Paper Detour: videos, brand, docs, automation
│   ├── nuviko_history/     # Nuviko History: videos, brand, docs
│   └── nuviko_stories/     # Исторические Stories RU/EN и их библиотека
├── projects/
│   └── borisenko/          # Отдельный проект дубляжа
├── automation/             # Общие TTS, YouTube, FFmpeg, субтитры
├── Shared/                 # Общие ассеты и инструменты
├── .agents/skills/         # Единые процедуры
├── .agent/                 # Реестр, карта владельцев и bootstrap
└── archive/
    ├── unclassified_episodes/  # Выпуски с каналом UNVERIFIED
    └── legacy_stories/         # Смешанные исторические записи и маршруты
```

В рабочем дереве внутри каналов сохранена структура выпусков, но сами папки выпусков в начальную Git-выборку не входят. Paper-материалы из прежнего смешанного `stories/videos/` находятся в `channels/paper_detour/legacy/`; перед их использованием получить конкретный episode bundle. Не создавать выпуск по номеру без проверки исходников.

`nuviko_stories` хранит прежние Stories RU/EN. Новый русскоязычный канал коллеги ещё не сопоставлен с этой коллекцией; перенос не назначает ему бренд, голос, рекламу или разрешения. См. [COLLABORATION](../COLLABORATION.md).

Общая автоматизация не содержит канальных исходников. Старые Stories `pipeline.py`, `voice_run.py` и `runs/` находятся в `channels/nuviko_stories/automation/`, а ElevenLabs, YouTube и рендереры — в корневом `automation/`. Существующие права, ID, статусы и условия заморозки не изменены.

## Совместимость

В текущей рабочей копии временно сохранены старые корневые ссылки `new_channel`, `stories`, `borisenko` и несколько путей `automation/`; они нужны незавершённым сценариям и открытым сессиям. Они исключены из Git и остаются только локально. В клоне использовать канонические пути из `channels/`, `projects/` и общей `automation/`.

Исторические журналы и квитанции могут сохранять прежние абсолютные пути как сведения об исходной среде. Новые инструкции и команды должны быть относительными/переносимыми. Не удаляйте временные ссылки из рабочей копии до завершения зависимых сессий.

## Добавление канала и выпуска

1. Установить идентичность канала по поручению и фактическим материалам; создать каталог `channels/<channel_id>/` с собственным AGENTS и профилем.
2. Добавить канальную документацию отдельно после подтверждения нового канала. Общие процедуры находятся в `.agents/skills`; используйте их напрямую из корня репозитория, не создавайте symlinks.
3. Перед подключением выпускных каталогов согласовать место хранения, доступ, медиа-манифест и переносимость путей.

Локальные планы миграции, резервные копии и сверки медиа не входят в source-only клон. Не удаляйте и не переносите их без отдельной проверки активных сессий и появившихся после миграции файлов.
