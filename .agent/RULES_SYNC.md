# Публикация и проверка изменений правил

Эта процедура обнаруживает опубликованные изменения; она не доставляет сообщения работающим сессиям и не даёт новых полномочий. Канонические правила остаются в своих документах. Публикуйте только проверенные и согласованные изменения после сверки связанных действующих документов; незавершённые рабочие правки и противоречия не публикуйте как готовые правила. Снимок содержит точные байты, в том числе незакоммиченные. Публикация не меняет Git и выпуски.

Общее хранилище на этом Mac: `/Users/diplomat/.codex/ytvideos-rules`. Все worktree должны использовать один и тот же путь. Доступ к нему необходим для проверки; отсутствие, ошибка чтения или нарушение целостности — неизвестное состояние, а не отсутствие изменений. Проверить источник и продолжать независимую работу; не выполнять затронутый следующий шаг, пока не восстановлена проверка. Снимки и реестр не содержат секретов или материалов выпусков.

## Проверка

Из своего корня ytvideos, с уникальным и стабильным для сессии ID (не общим для разных сессий):

```sh
python3 .agent/scripts/rules_sync.py check --store /Users/diplomat/.codex/ytvideos-rules --session SESSION_ID --channel paper --format long --stage render
```

Использовать фактические `channel`, `format`, `stage` задачи; значения должны совпадать с применимой записью. Общие записи используют `*`. Если контекст неизвестен, сначала установить его; при сомнении проверить оба возможных значения. Статус 0 — подходящих непрочитанных записей нет, 2 — есть записи, 1 — ошибка. Для каждой записи прочитать указанные `snapshot_path`, сверить канонические файлы и применимость по scope/решениям и определить действие. Снимок — точный опубликованный источник, локальный worktree может отличаться. Несоответствие не исправлять слепым merge или подменой чужих файлов. Если работающей команде нужен код или инструкция, которой в её worktree нет, согласовать безопасную адресную интеграцию, не перезаписывая незакоммиченные изменения.

После фактического чтения и оценки отметить ровно прочитанные ID, используя `manifest_sha256` из результата проверки:

```sh
python3 .agent/scripts/rules_sync.py ack --store /Users/diplomat/.codex/ytvideos-rules --session SESSION_ID --manifest-sha256 HASH --read-and-assessed CHANGE_ID
```

Если публикация изменилась, повторить проверку. Отметка индивидуальна и не доказывает качество оценки; ни она, ни реестр не меняют `FLOW_STATE.json`, принятый сценарий, версию MP4, права, разрешения или внешний статус. `future` — применить к будущей подходящей работе; `review` — оценить затронутый результат; `hold` — отложить относящееся к изменению действие до разрешения противоречия; `unclassified` показывается всем для ручной оценки. Указания пользователя и действующий scope имеют приоритет. Сохранить принятые версии и реальные решения.

Проверять на старте/возобновлении, перед новым этапом, перед запуском рендера и после завершения перед QA, перед upload/публикацией и между пакетами долгой генерации. Активные рендеры не останавливать и их замороженные входы не менять. После окончания оценить результат и при необходимости создать новую версию. Выполнять проверку также для узких задач по их реальному scope. Существующие активные сессии и выпуски не мигрировать автоматически; они увидят изменения только когда действительно вызовут проверку или получат явное сообщение через поддерживаемый канал.

## Публикация

Подготовить JSON-массив записей. `id` уникален навсегда: для правки или отмены создаётся новая запись с новым ID и ссылками на актуальных владельцев. `channels`, `formats`, `stages` — непустые массивы точных значений или `*`; нельзя использовать пустое поле для неизвестного scope — выбрать `unclassified`. `files` — относительные пути внутри source, `summary` кратко описывает область и действие. Пример:

```json
[{"id":"example-001","summary":"Описание принятого изменения","channels":["paper"],"formats":["long"],"stages":["storyboard","render","qa"],"impact":"future","files":["channels/paper_detour/AGENTS.md"]}]
```

После проверки владельцев и классификации явно выполнить:

```sh
python3 .agent/scripts/rules_sync.py publish --store /Users/diplomat/.codex/ytvideos-rules --source /ABS/PATH/TO/YTVIDEOS --changes /ABS/PATH/TO/CHANGES.json
```

Публикации сериализуются общей блокировкой, снимок и указатель записываются атомарно. Скрипт проверяет стабильность файлов во время чтения; при одновременной правке или конфликте сначала согласовать владельцев. Незавершённый снимок без опубликованного указателя не является действующим. Первую публикацию выполнять только после проверки согласованности текущих правил. `publish` с новым ID не заменяет предыдущую запись; при отмене объяснить её в новой записи. Резервировать общее хранилище вместе с историей снимков; не чистить его во время работы сессий.
