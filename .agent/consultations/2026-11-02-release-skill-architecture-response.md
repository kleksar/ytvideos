Рекомендация: оставить существующий `ytv-youtube-release`, не создавать новый skill и не переносить всю стратегию Paper в общий релизный механизм. Лучше разделить универсальную процедуру выпуска и политику конкретного канала.

## 1. Распределение ответственности

| Компонент                         | Что является его ответственностью                                                                       |
| --------------------------------- | ------------------------------------------------------------------------------------------------------- |
| `ytv-youtube-release/SKILL.md`    | Общая маршрутизация, выбор канала, порядок релиза, контроль разрешений и результата                     |
| `ytv-youtube-release/references/` | Подробная общая процедура подготовки, проверки готовых материалов, планирования и публикации            |
| Paper channel docs                | Динамическая политика календаря Paper, правила отбора производных, частота и редакционные ограничения   |
| Nuviko channel profile/docs       | Собственная политика публикаций, язык, стиль, частота и календарь Nuviko                                |
| `youtube-upload`                  | Глобальная API-first механика загрузки, изменения privacy, назначения публикации и технические операции |
| Metadata / QA skills              | Метаданные и техническая проверка — без дублирования в release skill                                    |
| Материалы конкретного выпуска     | Финальные файлы, manifest, метаданные, желаемый статус, дата, подтверждения и результаты публикации     |
| Paper Posts Playbook              | Создание и QA многокарточных бумажных историй                                                           |

## 2. Что перенести в общий release reference

Имеет смысл вынести туда только универсальную процедуру:

1. Определить канал по точному `channel_id`.
2. Прочитать его профиль и локальную release policy.
3. Проверить фактические недавние публикации и будущее расписание именно этого канала.
4. Проверить готовые материалы и локальные планы.
5. Выбрать доступный слот согласно политике канала.
6. Выполнить только разрешённые поручением действия.
7. Проверить фактический результат через YouTube API.

Это общая механика. Она не определяет, сколько фильмов или Shorts должен выпускать конкретный канал.

## 3. Что оставить в Paper-документе

`new_channel/docs/SHORTS_RELEASE_STRATEGY.md` оставить владельцем Paper-специфичной политики:

- распределение готовой партии без обязательной дневной нормы;
- отсутствие автоматической связки каждого фильма с Shorts и каруселями;
- отдельный редакционный отбор производных;
- возможность Private upload до назначения публичной даты;
- актуальная проверка календаря непосредственно перед назначением.

Nuviko не должен наследовать эти правила автоматически.

Календари разделяются по точному `channel_id`. Общий обзор нескольких каналов допустим, но не должен смешивать очереди и свободные слоты. Замороженный History остаётся замороженным.

## 4. Нужен ли новый skill?

Нет.

Существующий skill уже выполняет роль общего адаптера. Новый skill только добавит ещё один уровень маршрутизации и потенциально продублирует владельцев.

Оптимальная структура:

```
ytv-youtube-release/
├── SKILL.md
└── references/
    └── release-procedure.md

Paper channel docs/
├── SHORTS_RELEASE_STRATEGY.md
└── Paper Posts Playbook

Nuviko channel docs/
└── channel-specific release policy
```

Главное архитектурное правило: release skill отвечает за то, как безопасно выпустить материал; channel policy — что, когда и с какой редакционной частотой выпускать; uploader — как технически выполнить операцию.

Так общая архитектура масштабируется на несколько каналов без переноса Paper-специфичных решений на остальные.
