# Консультация: жизненный цикл тестовых медиа

- Дата и стадия: 2026-11-02, общепроектное рассмотрение очистки тестовых файлов.
- Координатор: личная консультация в Google Chrome, https://chatgpt.com/g/g-p-6ae147d3975481919b5bfda6935777d0-yt-video/c/6ae7efbd-75a4-83ed-ae0c-d762127296eb
- Видимая маркировка перед запросом: «Очень высокий».
- Входы: действующий lifecycle с manifests, защитой исходников и импортов, завершёнными runs и адресной очисткой.
- Промпт: «Ты — консультант в уже открытом ChatGPT Extra High. Требование внешнего координатора уже выполнено этим обращением; дай ответ здесь, не открывай рекурсивно другой ChatGPT. Одна узкая задача: предложи безопасный жизненный цикл временных тестовых видеорендеров после успешной проверки и при последующей переработке видео. Уже есть manifests, защищённые исходники и импорты, завершённые runs и адресная очистка. Как обеспечить повторное тестирование новой версии, доказательства, удаление именно ненужных тестовых файлов и защиту активной работы? Кратко.»
- Завершённый ответ: отдельный неизменяемый run для каждой версии; фиксировать входы и хеши, сохранять QA и параметры; при переработке заново проверять новую версию; защищать активную запись и зависимости; удалять адресно по manifest после dry-run, записывать результат; не определять ненужность по возрасту, размеру или расширению.
- Сверка: рекомендации совместимы с lifecycle как направление; предложенный консультантом статус superseded не является существующим статусом run в CLI. Lock сам по себе не доказывает окончание writer. Рецепт восстановления и сохранность доказательств требуют реальной проверки.
- Ограничение: консультация не проверяла фактические файлы и не даёт решения об их удалении.

## Продолжение: автоматизация завершения QA

- Видимая маркировка перед отдельным запросом: «Очень высокий»; тот же Chrome/URL. Пользователь попросил продумать быстрый скрипт для автоматизации.
- Узкий промпт: «Ты — консультант в уже открытом ChatGPT Extra High. Требование внешнего координатора уже выполнено этим обращением; дай ответ здесь, не открывай рекурсивно другой ChatGPT. Узкая задача: проверь архитектуру автоматической уборки QA-медиа. План: расширить существующий workspace.py одной командой finalize-qa; QA helper сам регистрирует точные временные кадры; после фактического review сохраняются отчёт, frame map, выбранные доказательства и проверенный рецепт восстановления из сохранённого MP4; finalize-qa проверяет identity/завершение writer/полноту обязательных проверок, сохраняет evidence, делает свежий dependency scan и адресно удаляет зарегистрированные scratch. FAIL/UNVERIFIED и pinned остаются. Для новой версии новый run, обязательный свежий decode и зависимые rechecks. Уборка вызывается в конце QA, без фонового обхода всего диска. Какие 3–5 конкретных поправок нужны для безопасности и скорости? Не предлагай писать код здесь.»
- Содержательный ответ завершён (UI: «Обработка заняла 43s»). Ответ сохранён в конспекте: (1) prepare/commit, сначала сохранить evidence, затем удалить; (2) связать run/timeline, MP4 SHA, report/frame map/evidence и рецепт с версиями инструментов; (3) удалять точные зарегистрированные пути с hash/device/inode, запрет symlinks и escape; (4) проверять зависимости, импорты, leases, pins, неизвестное KEEP; (5) журнал по каждому файлу и безопасное повторное выполнение после сбоя, новая версия требует нового decode/rechecks.
- Сверено с исходниками workspace.register/clean и inspect_video.inspect: существует адресная очистка scratch и rejected-preview, QA extraction пока не регистрирует набор автоматически. Предлагаемая автоматизация ещё НЕ реализована. Сохраняем текущую защиту всех известных packages/imports/snapshots; совет о scan по кандидатам не разрешает ограничиться одним run. Наличие lock/lease либо стабильных размера/mtime не заменяет подтверждение завершения writer. Непроверенные необязательные subjective/independent статусы не должны ошибочно блокировать профильный PASS.
