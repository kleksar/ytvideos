## 1. ChatGPT Extra High gate

Перед любым анализом, исследованием, редакционным решением или творческой работой координатор лично использует ChatGPT.com в Google Chrome в режиме **Extra High / «Очень высокий»**.

Непосредственно перед **каждым** запросом координатор лично проверяет видимую маркировку режима в интерфейсе. Точное отображаемое в этот момент название модели/режима логируется вместе с результатом, но этот файл не закрепляет конкретную версию модели.

Работа идёт последовательными узкими этапами:

1. один запрос — одна конкретная задача;
2. не объединять storyboard, image prompts, packaging, сценарий и другие самостоятельные творческие этапы в один prompt;
3. дождаться полного ответа;
4. прочитать и проверить ответ;
5. сохранить результат или принятое решение;
6. только после этого переходить к следующему этапу.

`Pro` использовать только по прямому запросу пользователя.

Skills, роли и субагенты не заменяют этот gate. Они также сами по себе не разрешают spawning. Автоматическое/proactive spawning запрещено; делегирование возможно только при прямом разрешении пользователя либо при явно применимом разрешении в `AGENTS.md`/skill и текущем runtime.

Если Chrome/ChatGPT Extra High недоступен, зависимый анализ или творчество блокируется. Уже принятые механические шаги, не требующие нового анализа или творческого решения, можно продолжать.

## 2. Bootstrap и определение канала

Проект сейчас не Git repository, поэтому не полагаться на Git root для загрузки инструкций.

Предпочтительная точка запуска — корень `ytvideos/`. При запуске из подкаталога явно прочитать этот root-файл, затем соответствующий канальный `AGENTS.md`.

`.agent/` не является механизмом автозагрузки. Документы из него читаются только по явной ссылке из `AGENTS.md`, skill или текущей задачи.

Канал и выпуск определять по [episode registry](.agent/episode-registry.md) и связанному локальному README/журналу. **Никогда не определять канал по номеру, slug или имени каталога.**

Для Paper Detour применять [new_channel/AGENTS.md](new_channel/AGENTS.md), для Stories/Nuviko History — [stories/AGENTS.md](stories/AGENTS.md).

Общий Paper-предохранитель действует независимо от физического расположения выпуска: **одна законченная цельная still-картинка на сцену; без BG/MG/FG, отдельных depth layers и parallax.**

## 3. Skills, роли и документация

Проектные skills обнаруживаются в `.agents/skills/` и применяются только по соответствующему trigger из [skill catalog](.agent/skill-catalog.md). Не загружать и не требовать все skills для каждой задачи.

`.codex/agents/` содержит роли. Роль определяет исполнителя и границы ответственности, но не является вторым источником production-правил.

Повторяемое правило должно иметь одного canonical owner. Не копировать полный workflow одновременно в root, channel `AGENTS.md`, skill и роль.

Актуальные project skills используют уникальные имена `ytv-*`. Подробное происхождение правил и normative source docs указаны в [documentation index](.agent/documentation-index.md).

Глобальный `youtube-upload` остаётся владельцем generic upload mechanics; project release workflow может вызывать его, но не копирует его checklist.

Legacy Paper skills могут оставаться только как тонкие compatibility routers к актуальным локальным `ytv-*` skills. Их архивные production-правила не являются текущим источником истины.

## 4. Состояние выпусков

Текущий status, решения, разрешения, ссылки, IDs, принятые артефакты и незавершённые действия хранить рядом с конкретным выпуском по принятому для него пути.

Root `AGENTS.md` не должен содержать каталог состояний всех видео.

Перед работой с выпуском:

1. определить его через registry;
2. прочитать локальное состояние/README;
3. применить нужный channel `AGENTS.md`;
4. выбрать только skills, соответствующие текущей задаче.

## 5. Звук

Без отдельного прямого разрешения пользователя **не создавать и не рендерить новый звук**, включая:

- narration/voice;
- музыку;
- SFX;
- тестовые и пробные генерации;
- пробные рендеры нового аудио.

Если такое разрешение уже явно получено для конкретного выпуска и конкретного scope, оно сохраняется в состоянии выпуска и продолжает действовать в этом scope.

Выбор существующих аудиоматериалов, mix QA, delivery, MP4/SRT и остальные подробности принадлежат соответствующему audio skill и здесь не дублируются.

## 6. Palmier и timeline safety

`.palmier` напрямую не редактировать.

Для MCP/API всегда передавать явные `projectId` и `timelineId`; не полагаться на UI focus.

На одном target timeline одновременно должен работать только один writer.

Перед рискованными изменениями делать snapshot. По умолчанию использовать изолированную рабочую версию timeline, если локальные правила конкретного выпуска это не запрещают.

Точное исключение: **Paper Detour `new_channel/videos/001_radio_game` использует один canonical timeline**; для него локальное правило имеет приоритет над общей схемой изолированных timeline versions.

Импортированные media assets не перемещать без **проверенной перелинковки** всех зависимостей. Если перемещение уже входит в порученную работу, отдельное новое разрешение не требуется; обязательна именно проверка корректных ссылок после изменения.

## 7. YouTube и внешние изменения

Новый upload по умолчанию создавать **Private**. После проверки устанавливать только ту visibility, которую явно запросил владелец.

Просьба подготовить видео, export, metadata, thumbnail, playlist или release plan не означает разрешения публиковать материал.

Не повторять вслепую внешний mutating request, если неизвестно, был ли предыдущий запрос выполнен. Сначала проверить фактическое внешнее состояние или честно зафиксировать неизвестность.

Не заявлять об upload, публикации, playlist/post operation, visibility change или другом внешнем изменении без проверки результата.

## 8. Truthful QA

Утверждать только то, что фактически проверено.

Успешный вызов команды, запуск background task, наличие файла или отсутствие exception сами по себе не доказывают корректность результата.

Если task требует independent review, автор изменения не считается независимым reviewer только потому, что переключена роль или название агента.

Не выдумывать ручной просмотр, completed task, проверенный export, независимый review или состояние внешней системы.

## 9. Deliverables и очистка

Deliverables текущего выпуска сохранять по уже принятому для него пути, указанному в локальном состоянии.

После проверки нового результата поддерживать **один актуальный локальный комплект каждого требуемого языка и формата**.

Пользователь уже разрешил после проверки нового комплекта удалять предыдущую локальную выдачу **того же языка и того же формата**, если она не является исходником. Для такой очистки отдельное новое разрешение не требуется.

При этом автоматически не удалять:

- source assets;
- project/edit files;
- версии на других языках;
- другие форматы;
- опубликованные или загруженные материалы;
- журналы, provenance и доказательства предыдущих действий.

Устаревший локальный export того же языка/формата может быть заменён новым проверенным комплектом по правилу выше.

Во время текущей миграции `AGENTS.md`, `.agent`, `.agents/skills` и связанных инструкций **не изменять media/production assets**.

## 10. Ограничения текущей миграции

Без прямого поручения не менять:

- Codex settings;
- permissions;
- model configuration;
- глобальные runtime settings.

В рамках **этой миграции** не создавать и не инициализировать Git repository. Это не универсальный запрет на Git для будущих задач.

Не превращать root в подробный production manual, список состояний видео или копию skills. Для повторяемой процедуры использовать [skill catalog](.agent/skill-catalog.md), а для поиска canonical source и владельца правила — [documentation index](.agent/documentation-index.md).
