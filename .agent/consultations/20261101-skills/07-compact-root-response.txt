## 1. ChatGPT Extra High

Перед анализом, исследованием, редакционным решением или творчеством координатор лично обращается к ChatGPT.com в Google Chrome в режиме **Extra High / «Очень высокий»**. Перед **каждым** запросом проверить видимую маркировку; точное показанное название модели/режима логировать, но модель здесь не фиксировать.

Один запрос — одна узкая задача. Стадии не объединять. Дождаться ответа, прочитать/проверить, сохранить результат и только затем идти дальше.

`Pro` — только по прямому запросу. Skill, роль и субагент не заменяют gate. Spawning — только по прямому разрешению пользователя либо явно применимому разрешению в `AGENTS.md`/skill и runtime.

Если Chrome/Extra High недоступен, блокируется только зависимый этап; принятые механические действия можно продолжать.

## 2. Bootstrap и канал

Проект фактически не Git repo; не полагаться на Git root. Запуск — предпочтительно из `ytvideos/`; из подкаталога явно прочитать root, затем нужный channel `AGENTS.md`.

`.agent/` не autoload: читать только по явной ссылке.

Канал/выпуск определять по [registry](.agent/episode-registry.md) и локальному README/журналу, **не по номеру или slug**. Paper: [new_channel/AGENTS.md](new_channel/AGENTS.md). Stories/History: [stories/AGENTS.md](stories/AGENTS.md).

Paper guard в любом каталоге: **одна законченная цельная still-картинка на сцену; без BG/MG/FG, отдельных слоёв, движения частей и parallax.**

## 3. Owners, skills, роли

У повторяемого правила один canonical owner; не дублировать workflow между root, channel `AGENTS.md`, skill и ролью.

Десять уникальных `ytv-*`, их triggers/owners — в [skill catalog](.agent/skill-catalog.md). Источники правил — в [documentation index](.agent/documentation-index.md). [Роли](.codex/agents/README.md) не являются вторым workflow и не разрешают spawning. Не применять все skills ко всем задачам.

Глобальный `youtube-upload` владеет generic upload mechanics; project release вызывает его через catalog без копии checklist. Legacy Paper skills — только thin routers к локальным `ytv-*`.

## 4. Состояние выпусков

Status, решения, разрешения, ссылки, IDs и принятые артефакты хранить рядом с выпуском.

Порядок: registry → локальный README/журнал → channel `AGENTS.md` → нужные skills.

## 5. Звук

Без отдельного прямого разрешения **не создавать и не рендерить новый звук**, включая voice/narration, музыку, SFX, тесты и пробы.

Ранее явно данное разрешение для конкретного выпуска и scope сохраняется, пока scope не изменён. Остальные правила звука, mix QA и MP4/SRT — в audio skill.

## 6. Palmier

`.palmier` вручную не редактировать. Для MCP/API использовать явные `projectId`/`timelineId`; UI focus не задаёт цель. На одном target timeline — один writer.

Перед рискованной правкой делать snapshot. По умолчанию использовать изолированную timeline-версию с сохранением исходника, если локальные правила не требуют иного.

Исключение: **`new_channel/videos/001_radio_game`** использует один canonical timeline; его локальные правила имеют приоритет.

Imported media не перемещать без проверенной перелинковки. Если перемещение входит в порученную задачу, нового разрешения не нужно; после изменения проверить зависимости.

## 7. YouTube и внешние изменения

Новый upload по умолчанию — **Private**; затем ставить только явно запрошенную visibility.

Подготовка видео/export/metadata/thumbnail/playlist/release plan **не разрешает публикацию**.

Не повторять неизвестную внешнюю mutation вслепую: сначала проверить фактическое состояние либо зафиксировать неизвестность. Не заявлять о внешнем изменении без проверки результата.

## 8. Truthful QA

Утверждать только проверенное. Успешная команда, background task, наличие файла или отсутствие exception не доказывают корректность результата.

Автор изменения не становится independent reviewer после смены роли/имени. Если независимая проверка требовалась и не выполнена — указать это. Не выдумывать просмотр, прослушивание, export QA, review или внешнее состояние.

## 9. Deliverables и очистка

Deliverables сохранять по принятому пути выпуска. После проверки нового результата поддерживать **один актуальный локальный комплект каждого нужного языка и формата**.

Предыдущую локальную выдачу того же языка/формата можно удалить после проверки новой, если она не source; новое разрешение для этой очистки не требуется.

Не удалять автоматически source assets, project/Edit files, другие языки/форматы, внешние/опубликованные/загруженные материалы, журналы и provenance.

## 10. Текущая миграция

В этой миграции **не менять media/production assets, не создавать/инициализировать Git repo, не менять Codex settings, permissions, model configuration или global runtime settings**.
