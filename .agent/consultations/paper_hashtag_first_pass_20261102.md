## Проверенные официальные источники

1. https://support.google.com/youtube/answer/6390658?hl=en — хэштеги связывают видео с общей темой и доступны через поиск; до трёх меток описания могут появляться рядом с названием, это не предел набора; более 60 игнорируются все; избыточность и нерелевантные метки не рекомендуются.
2. https://support.google.com/youtube/answer/12948449?hl=en — уникальное описание, полезные первые строки, 1–2 главных ключевых понятия в title/description; реальные поисковые фразы доступны в Analytics.
3. https://support.google.com/youtube/answer/11914225?co=YOUTUBE._YTVideoType%3Dshorts&hl=en — поиск учитывает соответствие метаданных запросу и просмотр; Shorts recommendations учитывают персонализацию, выбор просмотра, длительность/процент просмотра и удовлетворённость. Прямой формулы «больше hashtags = больше рекомендаций» источник не даёт.
4. https://support.google.com/youtube/answer/146402?hl=en — отдельное поле Tags отличается от hashtags; роль Tags в discovery ограничена, особенно полезны варианты ошибочного написания.

## Одна попытка получить полный результат

> Ответ обрезан на слове «изв». Выведи сам результат коротко: 6 конкретных правил полноты первого подбора хэштегов, не более 180 слов. Без вводной, без редакции документов, без отдельного набора для Jascon-4.

Завершённый видимый ответ:

1. **Сначала извлекать сущности из истории.** До поиска составлять список: герой и его варианты имени, событие, объект, место, дата/год, предметная область, уникальный исход. Не ограничиваться жанром ролика.
2. **Использовать обязательную матрицу поиска.** Проверять шесть категорий: broad, topic, hero, event, location/time, community. Для каждой применимой категории искать конкретные варианты, включая имена собственные и альтернативные формулировки.
3. **Не останавливаться на первых популярных тегах.** После общих тегов выполнять отдельный проход по именам героев, названию события, объектам и тематическим понятиям. Завершать поиск только после проверки всех применимых категорий.
4. **Оценивать каждый кандидат отдельно.** Фиксировать relevance, actual use и trend как независимые статусы. Отсутствие подтверждённого тренда не делает релевантный тег непригодным.
5. **Выдавать расширенный содержательный результат.** Не задавать искусственный оптимум количества. Сохранять все полезные, непосредственно относящиеся к сюжету теги. Для каждого исключения указывать причину: нерелевантность, неоднозначность, дублирование или неподтверждённость.
6. **Ввести release gate.** Полная строка description hashtags — отдельно от title. Хэштеги в title необязательны: проверять суммарную длину title вместе с ними в пределах 100 символов. Не сокращать содержательный набор ради title. Release readiness — только после проверки полноты категорий, релевантности каждого тега и отсутствия overtagging (>60).

## Проверка ответа и предложение координатора

- Использовать покрытие применимых сущностей и тем как критерий полноты, а не обязательное число тегов. Короткий результат не принимать автоматически без проверки пропущенных категорий.
- При доступном поиске проверять реальные варианты написания и тематическую релевантность страниц/подсказок; not_checked требует конкретного ограничения, а не заменяет весь проход. Неизвестный спрос не означает запрета релевантной метки.
- Из пункта 5 не принимать «неподтверждённость» как основание удалить тег лишь из-за неизвестного тренда. Исключать по ложному смыслу, нерелевантности, неоднозначности или бесполезному дублированию.
- Не принимать формулировку пункта 6 как доказательство отсутствия overtagging при числе <=60: официальный порог игнорирования не является безопасной целевой нормой.
- Для Paper учитывать прямое поручение на title hashtags: дать короткий поднабор после смыслового заголовка; полный полезный набор сохранить в description. Проверить полную длину и видимый смысл title.
- Уникальное содержательное описание с естественными ключевыми понятиями готовится отдельно от блока hashtags. Обычный Tags field также отдельно.
- До обновления canonical rules проверить процедуру на 031: таблица покрытия/отбора → точные title/description blocks и полные поля → механическая проверка длины и повторов → комплект упаковки с применимостью остальных полей.
- Предложение к каноническому изменению: hashtags skill — обязательный охват/отбор; Paper profile — предпочтение расширенного содержательного набора; titles/descriptions/release — только связанные требования передачи/проверки, без копирования основного workflow.
