# Paper Detour: от одного запроса до нужного результата

До процедуры прочитать [CHANNEL_BOOTSTRAP](/Users/diplomat/ytvideos/.agent/CHANNEL_BOOTSTRAP.md), указанные там root/реестр/локальное состояние и [Paper AGENTS](../../../new_channel/AGENTS.md). Для общеканальной задачи не выдумывать выпуск. Этот skill — координатор; технические процедуры остаются у владельцев в [каталоге](../../../.agent/skill-catalog.md).

1. **Зафиксировать исходную границу.** По запросу и текущим материалам установить канал, конкретный сюжет/canonical-путь, формат, язык готового продукта, принятые версии и разрешения. Paper Detour по умолчанию англоязычный; русский разговор, исходник или перевод для проверки не меняет язык narration/титров. «Сделай сюжет» заканчивается полным сценарным результатом, если пользователь не поручил больше. Не выдавать список вопросов вместо начала работы: недостающие обычные решения принять по контексту; спрашивать только о действительно критическом пробеле. Минимальный бриф и маршруты — [runbook](references/production-runbook.md).
2. **Выбрать первый незакрытый результат.** Сверить фактический файл и его статус с последней пользовательской правкой, а не выбрать самый новый filename или старую тему из slug. Если история ещё не принята/не разработана, читать [разработку сюжета](references/story-development.md); при продолжении — только нужный участок [стадий и передач](references/stages-and-handoffs.md). Сохранить принятый смысл, повороты, текст и действительные проверки; локальную правку не превращать в перезапуск выпуска.
3. **Разрабатывать узко, исполнять непрерывно.** Аналитические/творческие пробелы координатор лично решает через `$ytv-chatgpt-extra-high`: исследование, сюжет, текст, фактчек и постановка — отдельные последовательные задачи. Прочитать и сохранить содержательный ответ перед зависимым шагом. Затем выполнить соответствующий child skill. Один стартовый запрос объединяет управление процессом, а не консультации в один мегапромпт.
4. **Продолжать до исходной границы.** После каждого результата сохранить версию и проверить её зависимости; самостоятельно выполнить следующий разрешённый шаг. Не заканчивать очередным «что дальше?» или предложением сделать уже порученное. Принятие всегда имеет автора и конкретный объект; внутреннюю приёмку не выдавать за одобрение пользователя. Если процедура требует ещё не принятого входа, остановить только зависимую ветку. Уже действующее разрешение не переспрашивать. Реальные остановки и допустимая независимая работа — в runbook.
5. **Закрыть именно запрошенный результат.** Сохранить полный текст/файлы, обновить короткое текущее состояние и зависимости рядом с выпуском. Пользователю показать результат, версию, фактические проверки и существенные ограничения; для сценария дать сам сценарий, для media — правильный файл/preview. Не объявлять preview финальным, технический PASS — полным AV review, а пользовательское «отлично» о кадре — приёмкой обложки или разрешением выпуска.

Новый звук, экспорт и внешние действия выполняются только в порученной области по root и профильным skills. Полный цикл не запускается автоматически из слова «сюжет». Для разрешённого делегирования передать точные входы, ownership файлов/target timeline и критерии результата; исполнитель не отменяет чужие изменения. Автор не становится независимым reviewer после смены роли. [Роли](../../../.codex/agents/README.md) не дают дополнительных разрешений.

Один промпт должен убрать потерю контекста и ненужные остановки. Он не гарантирует отсутствие редакций, доступность инструментов, полный QA без просмотра/прослушивания или конкретный retention.
