# ChatGPT Extra High — проектный проход

Обязательный вход: до процедуры прочитать [CHANNEL_BOOTSTRAP](../../../.agent/CHANNEL_BOOTSTRAP.md) и указанные там root/реестр/локальное состояние/правила канала. Для общепроектной задачи не выдумывать выпуск.

Вход: одна конкретная задача, проверенные входы предыдущего этапа, ограничения канала, требуемый артефакт. Прочитать [корневые правила](../../../AGENTS.md).

Чисто механическая проверка уже принятых решений (например, чтение параметров файла) сама по себе не вызывает этот skill. Анализ, редакционная оценка и творческие решения требуют прохода; механическим названием их не обходить.

1. Координатор лично открывает нужный проектный чат на ChatGPT.com в **Google Chrome** через доступный инструмент управления браузером. Показанный пользователем чат изучать фактически; ссылка-заглушка `chatgpt-content-reference` не раскрывает содержимое.
2. Непосредственно перед каждым содержательным запросом проверить видимую маркировку Extra High / «Очень высокий» и записать её дословно. Pro — отдельный режим, только по прямому запросу; подписка и ползунок не подтверждают Extra High.
3. Отправить одну узкую задачу. Исследование, выбор темы, сюжет, сценарий, фактчек, раскадровка, субтитры, звук и оценка — последовательные запросы. Крупный этап разделять дополнительно. Перед зависимым запросом дождаться окончания ответа, прочитать, проверить и сохранить результат.
4. Уточнить роль консультанта: «Ты — консультант в уже открытом ChatGPT Extra High. Требование внешнего координатора уже выполнено этим обращением; дай ответ здесь, не открывай рекурсивно другой ChatGPT». Правила будущего workflow передавать как контекст, а не поручение консультанту исполнять весь конвейер.
5. Проверить ответ консультанта в пределах порученного этапа: соответствие задаче, принятому тексту и правилам; сверку с источниками выполнять в рамках порученного исследования или фактчека. Ответ модели не считается независимым первоисточником или одобрением пользователя. Исправления ответа запрашивать только в пределах этого этапа. Для уже одобренного пользователем сюжета действует [граница сохранности принятого содержания](../ytv-video-production/SKILL.md#вход-и-полномочия): консультации последующих производственных этапов используют его как зафиксированный вход. Сохранить результат и перейти к следующему порученному этапу.

Выход: сохранённые задача/промпт, точная маркировка, URL чата, завершённый ответ, принятые решения и ограничения. Запись хранить в материалах выпуска; для общепроектной задачи — в `.agent/consultations/`. Использовать [шаблон](../../../.agent/templates/consultation.md).

Если Chrome или нужный режим недоступны, остановить зависимый анализ/творчество и записать конкретное ограничение. Можно продолжать уже определённые механические действия. Субагент не выполняет этот проход за координатора; нового разрешения на уже разрешённую работу не требуется.
