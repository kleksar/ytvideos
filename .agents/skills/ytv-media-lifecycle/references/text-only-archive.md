# Архивирование завершённого выпуска

Владелец процедуры — [media-lifecycle](../SKILL.md), разрешение — root §9. Режим освобождает место и оставляет компактную текстовую историю.

## Когда запускать

- Автоматически в том же проходе этапа 27, до итогового отчёта: fresh read-back подтверждает Public и статус согласованного A/B для длинного фильма либо точное сохранённое расписание, завершённую обработку и соответствие принятому выпуску. Принятый и запущенный на YouTube A/B не требует ожидать результата перед очисткой локальных медиа; квитанция и хэши сохраняют связь с загруженными вариантами. При расписании до очистки сохранить или передать все согласованные варианты названий и обложек для будущего A/B и подтвердить их доступность; сообщить, что тест не запущен и пользователь займётся им отдельно. Shorts без A/B.
- По отдельному запросу оптимизации: проверить завершённые Public либо Unlisted, включая публикацию/доступ, установленные пользователем в другой сессии. Private, pending review и unfinished release остаются рабочими.

По реестру и receipts сопоставить canonical episode, channel_id/video_id и URL, точную принятую версию/file hash и upload. Получить актуальные visibility/processing и доступность ролика через [release](../../ytv-youtube-release/SKILL.md) и его uploader/API route. Длительность, старое имя файла, запись «uploaded» или один URL не устанавливают идентичность. Для старого выпуска использовать реальные upload/edit records либо явное указание пользователя на завершённое видео; сохранять ограничения проверки. При неустановленной идентичности продолжать обычную очистку доступного scope.

## Что оставить

Компактные Markdown/TXT/JSON/YAML/TOML/CSV/SRT/VTT и нужные текстовые конфиги/scripts: сценарий, партитура, prompts/seed/model/settings, alignment, metadata/chapters/hashtags, IDs/URL, права/лицензии, source provenance, hashes, export/upload/review/cleanup receipts. Сохранить монтажный план и полезные текстовые данные проекта до удаления его принадлежащих выпуску зависимостей. Включить settings-check и render provenance со снимками паспорта, фактических команд и кода по export owner; до завершения выпуска эти снимки защищены как release dependencies, даже если находятся в Work. Текстовый архив хранит назначение бывших путей и факт удаления; тяжёлые base64/blob/dumps выносятся из сохраняемых записей с сохранением hash/смысла и сведений об удалении.

## Что удалить

Принадлежащие завершённому выпуску картинки/обложки/PSD, аудио, MP4/пререндеры/мастера, depth/video caches, QA PNG/contact sheets, двоичные базы и завершённые монтажные пакеты/вложенные media. Текущий local final входит в scope после проверки remote release. Пустые собственные каталоги удалить. История проекта остаётся компактным текстом; копии тяжёлых файлов в другом каталоге/Trash/backup не являются завершённой очисткой.

## Исполнение точного плана

1. Зафиксировать fresh release proof, остановленные собственные writers/jobs, список retiring project/timeline IDs и собственных старых pins/current. Полные действующие материалы других работ и общую библиотеку сохранить.
2. Сделать bounded inventory эпизода и принадлежащих ему внешних cache entries. Для каждого кандидата записать exact canonical path, bytes, stat/hash, owner и consumers. Symlink не обходить; hardlinks и неизвестное владение разобрать отдельно. Внешние shared stores целиком в scope не входят.
3. Завершить собственные монтажные процессы; отметить их `RETIRED_TEXT_ONLY`. Закрыть только собственные release/review holds по квитанции завершения. Зависимость сохранённой другой работы требует сохранения consumer; при необходимости переноса из episode использовать проверенную перелинковку и canonical media store перед удалением локальной копии.
4. Сохранить текстовый exact plan и исполнить его по одному файлу с повторной проверкой identity/consumer/writer перед unlink. Соблюдать требования среды: проверяемо восстанавливаемое перемещение в корзину и перманентное удаление различаются; отдельное обязательное подтверждение безвозвратного удаления не обходить. При отсутствии подтверждения выполнить только разрешённый безопасный объём и отметить остаток как PARTIAL. Existing `workspace clean` намеренно не удаляет sources/projects/current; у CLI нет команды `archive`. Этот режим исполняется стандартными файловыми операциями по проверенному плану, без подмены ролей source на scratch. Пакет удаляется как перечисленный retiring target; его содержимое вручную не редактируется для продолжения монтажа.
5. Записать фактические удалённые/сохранённые/неизвестные entries, остаточный объём и holds. У current.json локальный путь становится отсутствующим/retired; ссылка на remote принятую версию остаётся. Повторный запуск продолжает по фактическому наличию файлов.

После сверки присвоить `storage_state=TEXT_ONLY`, сохранить remote identity, время проверки и пути текстовых квитанций в CURRENT_CONTEXT/реестре. При оставшихся тяжёлых holds, включая сохранённые локально обложки для будущего A/B, — `PARTIAL_TEXT_ARCHIVE` с причиной и точными путями. Архив не обещает восстановление прежнего изображения/голоса/монтажа без новой генерации. YouTube, shared library и другие выпуски эта операция не изменяет.
