# Редактируемая сборка

1. Прочитать [visual](../../../../docs/standards/visual.md), [audio](../../../../docs/standards/audio.md), [delivery](../../../../docs/standards/delivery.md) и профиль. Снять native read-back версии, текущего project/timeline, geometry/fps, media availability. Не менять активный чужой проект. Сохранить исходное состояние и собственные IDs; сериализовать создание/import/settings/save/render mutations. Не полагаться на неизвестные методы: проверить локальный официальный scripting API соответствующей версии.
2. Подготовить точный frame manifest с источниками, in/out, длительностями, слоями, параметрами движения и audio cues. Установить timeline fps/геометрию **до импорта**; проверенные форматы — 1920×1080/30 и 1080×1920/30. Это не отменяет более высокого/другого разрешения закреплённого профиля: его проверить отдельно, не понижать до тестового пресета. Сохранить фактический timeline read-back, а не только запрошенное SetSetting. Склейки и события движения привязать к словам и действиям по [темпу](../../../../docs/standards/visual.md#плавность-и-темп-сюжетного-движения), не к сетке фиксированной длительности.
3. Импортировать source assets и edit timeline штатным native API. Для numbered PNG Resolve может ошибочно распознать sequence. При наблюдаемом Media Offline/ошибке длины подготовить uniquely named exact-length ProRes MOV carriers (4444 для alpha); сверить первый/последний кадр, fps, длительность и alpha, затем импортировать. Не выдавать это за обязательную конверсию любого PNG; исходники сохранить. Carrier не должен запекать монтажную камеру, которую требуется редактировать.
4. Сохранить отдельные picture cuts, object/alpha overlays, narration, music и **один клип на каждый авторский SFX cue**. Для одновременных эффектов выделить необходимые неперекрывающиеся lanes, не фиксированное число дорожек. Проверить trim/position/gain/fades/ducking по фактической слышимости, clips/channel map и sync. Старый baked master допустим лишь как явно подписанный legacy underlay: из него не возникают отдельные editable voice/music/SFX; отсутствие stems записать, не обещать полную раздельную правку.
5. Монтажная камера: static — полноценный выбор; где движение выбрано, native keyframes/эквивалентная проверенная editable конструкция линейны от первого до последнего отображённого кадра без ease/edge holds. Проверить interpolation фактически, не по имени preset. Применять актуальные правила общего visual/channel без ослабления: обычный zoom не более примерно ±5% от исходного скомпонованного framing, более строгий cap имеет приоритет; выбранные zoom в соседних движущихся планах чередуются. Проверять реальный видимый crop относительно fit, не одни Inspector numbers. Статику предпочитать при быстрых склейках без смысловой причины движения; pan в каждом из четырёх направлений выбирать по задаче reveal/action/travel, не ради квоты. Сохранить safe crop; направление artwork противоположно перемещению camera. Событийная анимация предмета имеет свой смысловой старт, не обязана двигаться весь кадр. Первый/средний/последний кадры и непрерывные соседние склейки проверять на clipping, скачки и повтор псевдо-нового плана.
6. Субтитры: канальные single-line/word highlight/safe area сохраняются. Можно импортировать проверенный alpha karaoke слой; он baked относительно текста/тайминга, не нативно редактируемая subtitle track. Сохранить word map, cue map, source текста и способ пересборки. **SRT в Media Pool или sidecar не означает применённую subtitle track.** Для новых речевых выпусков импортировать финальный EN SRT (иной язык — только по явному языковому поручению) на отдельную **native editable subtitle track**, не только в Media Pool. Учитывать export origin/timeline offset; сверить текст, cue count и первый/последний cue, затем выполнить [проверку sync](#быстрая-проверка-синхронизации-субтитров) после всех trims. Проверить, что cues действительно доступны для редактирования, и повторно экспортировать отдельный timed SRT; прочитать его обратно и сравнить текст/таймкоды с финальным монтажом. Для `no_speech` не создавать фиктивную речь. Native CC track хранить отдельно от burned/alpha captions: явно выбрать видимость при render, чтобы оба слоя не отображались одновременно. Не считать импорт файла проверкой native-track применения. Для History-подобного hold сохранять текущую фразу до следующей, neutral highlight в паузах, только если это правило применимо каналу.
7. SaveProject и повторный read-back: project/timeline IDs, frame count, cut/track/item counts, offline state, endpoints, source hashes, editable vs baked components. При поручении «только проект» закончить здесь, не запускать export. Для export перейти к delivery reference.

## Быстрая проверка синхронизации субтитров

1. После всех trims, пауз, изменений скорости и перестановок читать фактический conformed VO из нужного сохранённого timeline. В существующий manifest/QA receipt записать SHA-256 источников речи, timeline ID/revision, точную FPS (дробной парой), start frame/timecode, положение начала SRT/проверяемого диапазона и source in/out, record in/out, speed (включая ранее применённую к исходнику скорость) каждого речевого клипа. Если есть точный финальный VO stem, сохранить его SHA-256; иначе fingerprint конформа — источники и упорядоченная карта placements/trims/rates, не hash прежнего WAV. При несовпадении fingerprint не использовать старую карту как доказательство. Привести word map и read-back **установленных** экранных титров/нативной SRT-дорожки к одной шкале record frames. Не прибавлять старт timeline или intro второй раз. Для экранного karaoke сравнивать начало подсветки **того же слова**, для SRT — речь первого/конец последнего слова cue, а не длительность удержания строки.
2. На каждой проверяемой дорожке выбрать различимые слова около начала, середины и конца **речи**; добавить пары до/после каждой речевой склейки, вставленной паузы или изменения скорости. Сверить с финальной картой слов и скраббингом waveform/фактическим воспроизведением в Resolve. Записать для каждого anchor слово/cue ID, точку `voice_frame`, фактический `caption_frame` и разницу `caption_frame − voice_frame` (плюс = титр опоздал). Предел числового smoke test — один кадр на anchor после правильного округления. Это быстрый поиск проблем, не покрытие всего фильма. Автоматический результат по карте/ASR — только числовой; он не подтверждает, что слово действительно услышано. Можно подать измеренные anchors одной дорожки в [SRT helper](../../../../automation/helpers/srt/scripts/srt_tool.py): `python automation/helpers/srt/scripts/srt_tool.py check-sync --anchors ANCHORS.json` (JSON-массив объектов `{ "label": "cue 1 onset", "voice_frame": 100, "caption_frame": 101 }`, в порядке речевых кадров). Helper не читает Resolve и ничего не переносит.
3. Один общий shift допустим только при доказанном общем сдвиге origin/позиции (одинаковая разница на всех anchors с точностью до кадра, конформ речевых клипов и скорость совпадают): сдвинуть титры один раз на обратное смещение, не одновременно править SRT offset и позицию трека. Если разница растёт к концу, скачет на склейке либо происхождение сдвига неизвестно, не подгонять титры общим сдвигом. Пересчитать по точной карте конформа или заново выровнять по финальному VO; пересобрать word map, экранные титры и SRT и повторить check/read-back. Если точные времена слова не подтверждены, локально проверить спорный участок по waveform и слуху; близкие оценки ASR сами по себе недостаточны.
4. Для playback QA проиграть эти окна на обычной скорости в Resolve Viewer с включённой только проверяемой subtitle-дорожкой, речью и итоговым миксом; затем отдельно повторить для второго слоя, если он есть. Для быстрого прогона не нужен рендер или очередь Deliver. В receipt отдельно указать фактические интервалы, дорожки, метод, исполнителя и результаты числового сравнения и playback. Если среда не даёт реально услышать звук и видеть титры одновременно, playback остаётся `UNVERIFIED`, не `PASS` по waveform, SRT, ASR или запуску плеера. Собранный проект и быстрая проверка не заменяют [полный финальный review](../../../../docs/standards/delivery.md) разрешённого exact export.

## Главы длинного видео

Для применимого Long поставить **timeline markers**, не clip markers, по окончательному монтажу. Выбрать и записать один chapter color, названия и позиции; QA/служебные markers других цветов в главы не включать. Пересчитать относительно начала экспортируемого диапазона, после trim/intro снова сверить. Сохранить рядом с проектом список timestamp + title и read-back marker type/color/position. Для Short chapter toggle остаётся выключенным. Публикация глав и selectable CC — по [delivery](delivery.md), а не по одному наличию track/markers в проекте.
