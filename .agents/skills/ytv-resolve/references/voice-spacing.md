# Нормализация пауз по слышимой речи

Использовать, когда нужно убрать разную тишину слева и справа у отдельных речевых клипов и получить ровные паузы. Cue должен быть одной утверждённой репликой одного спикера. Не применять к готовому миксу, музыке, игровому звуку, SFX, репликам с намеренными внутренними паузами или к нескольким голосам, сведённым в один файл.

1. Сверить активные проект/таймлайн, порядок реплик, исходные WAV и хеши, реальную скорость, pitch correction и границы источника. Выбрать целевой зазор между концом речи и началом следующей: явный запрос → профиль/проект → согласованная настройка текущего монтажа. Не считать одинаковое расстояние между краями клипов гарантией одинаковой паузы.
2. На точных исходниках запустить offline planner [voice_spacing.py](../../../../automation/resolve_subtitles/voice_spacing.py). Он выдаёт измеренные границы речи в samples, защищённый source trim и положение в record frames; сначала проверить план без правок проекта. Проверить тихие согласные, вдохи и границы по доступной карте и waveform. При неясной границе оставить этот край или остановить cue для проверки; не вырезать по одной жёсткой отсечке и не удалять внутреннюю тишину.
3. В отдельном редактируемом таймлайне обрезать только внешнюю тишину, оставив защищённый запас у начала/конца. Сохранить WAV, темп, высоту тона, уровни и роли. Если native trim неприменим, допустимы отдельные lossless PCM WAV, вырезанные строго по плану, с исходными WAV и хешами рядом. Не пересинтезировать голос ради пауз и не собирать речь в один нераздельный файл.
4. Поставить следующий клип относительно **слышимых границ**, а не физического края, и отдельно сдвинуть картинку/титры по новой покадровой шкале. Не добавлять второй раз уже учтённые handles. Пересобрать все языки с одной картой реплик; не двигать SRT общим offset.
5. Перечитать сохранённый таймлайн: IDs, все retained samples/источники, скорости, gain, новые паузы, отсутствие overlaps и необъяснённых дыр, границы титров. Проверить слышимый результат на выборочных переходах, в том числе на самых тихих краях; если прослушать не удалось, записать это отдельно. Без рендера и публикации, если их не заказывали.

```bash
python3 -m automation.resolve_subtitles.voice_spacing cues.json \
  --fps 30 --gap-ms 700 --guard-ms 40 --output voice-spacing-plan.json
```

Вход: массив объектов с `cue`, `wav` и `speed` (проценты), в монтажном порядке. Подставить точный fps и паузу своего проекта; 700 мс здесь пример, не правило для всех видео. Опциональный `--materialize-dir` создаёт отдельные PCM-файлы; без него команда только строит план. Команда не подключается к Resolve и сама ничего в проекте не меняет.

Если после консервативной обрезки остались видимые почти пустые края, отдельно проверить край по waveform и speech/word evidence. Для такой правки можно явно попробовать `--edge-mode tight --guard-ms 20` на копии плана: режим ищет связанный тихий хвост и помечает отделённые всплески для проверки, а не автоматически отбрасывает их. Если утверждённые паузы и синхронизация уже хорошие, брать из нового плана только проверенные source trims, а не заново расставлять реплики: скомпенсировать левую обрезку сдвигом record start, сохранив прежние положения речи, картинки и SRT. Если тихий звук может быть частью речи, оставить его и оговорить ограничение.
