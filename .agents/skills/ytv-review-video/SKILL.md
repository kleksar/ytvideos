# Проверить и представить MP4

Для проверки отдельных исходных клипов выполнить [общую процедуру](../ytv-produce-video/references/video-clips.md) и применять [критерии решений](../../../docs/standards/delivery.md#проверка-исходных-клипов). Не выдавать приёмку клипа за финальный review выпуска.

При подозрении на дефект открыть точный участок и сравнить исходник с результатом в сопоставимом масштабе. Разделить наблюдение, интерпретацию и монтажное решение. Если крупный просмотр опроверг предварительный диагноз, явно исправить его в evidence и сообщении пользователю.

До действий выполнить [обязательную процедуру](../ytv-start/references/task-execution.md): прочитать pinned skill/требования/точные входы и проверить описанный способ. Пробел или неразрешённый конфликт — blocker затронутого этапа; не подставлять свои defaults и не менять правила ради продолжения.

Для run прочитать context `review`: `task_guide`, `production_requirements`, выбранные документы, профиль/рецепт и уже выполненные checks. Открыть точный MP4 из `inputs` и принятые script/audio/storyboard из `supporting_inputs`. Для узкой проверки без run использовать предоставленные файлы и применимые правила; runtime-команды и запрос MP4 approval ниже относятся к production run. Проверять hash и фактическое содержание; критерии — [delivery](../../../docs/standards/delivery.md) и [editorial](../../../docs/standards/editorial.md).

1. Проверить decode/streams/каденцию/геометрию/цвет/аудио, каждую сцену, склейки, движение, титры и применимый end screen. Для иллюстрированного рассказа сверить полный exact MP4 с картой речи и [плотностью отдельных смыслов](../../../docs/standards/visual.md#плотность-отдельных-смыслов): каждый смысл действительно получает назначенную самостоятельную постановку, а crop/zoom/дубликат не маскирует отсутствие следующего кадра. Проверка действует и для полного черновика с временной озвучкой; низкая плотность — дефект к исправлению, не допустимая экономия на draft.
   Для нарезки исходной речи сверить расшифровку со звуком точного MP4 по [редакционному стандарту](../../../docs/standards/editorial.md#монтаж-исходной-речи).
2. Для Short просмотреть начало без звука, затем со звуком. При непрерывном просмотре всего MP4 отметить конкретные замечания к темпу по [критериям начала и темпа](../../../docs/standards/delivery.md#понятность-начала-и-темп). Для любого формата проверить, что монтаж сохранил развитие, кульминацию и развязку принятого текста по [editorial](../../../docs/standards/editorial.md#драматургия-для-всех-каналов); не исправлять сюжет самовольно. По [narration](../../../docs/standards/narration.md) проверить фактическую речь: не съедены ли причинные связи, не появились ли рубленые паузы и служебное чтение; это проверка озвучки, не разрешение менять принятый текст. Для Short проверить холодное начало, отдачу до повтора и воспроизвести последние → первые секунды по [delivery](../../../docs/standards/delivery.md#петля-shorts-проверка-точного-mp4). Зафиксировать timecodes/hash, смысл, речь, музыку и subtitle seam. Раздельно отметить измерения, просмотр кадров, прослушивание и player playback: contact sheet/word map не доказывают AV sync всего ролика.
3. Связать каждую проверку с hash, методом, coverage, reviewer и evidence. Если упаковка готова, сверить полную карточку, тон, первое подтверждение и payoff по [thumbnail QA](../../../docs/standards/thumbnails.md#qa-файла-и-пары); сохранить timecodes MP4. Позднюю упаковку проверяет release. Невыполненное — `UNVERIFIED`, неприменимость требует причины; self-review не является independent review.
4. Исправить подтверждённые дефекты описанным способом с сохранением остальных inputs/cache, повторить затронутые checks и получить новый exact MP4. После устранения конкретного риска не расширять проверки без причины.
5. Сохранить receipt и показать готовый файл. Приложить готовую упаковку, если она есть; не удерживать MP4 ради неё. Запросить одобрение точного файла.

Локальный координатор регистрирует явное решение владельца по [контракту](../../../docs/operations/task-contract.md#approval-и-продолжение), связывая его с показанными revision/hash MP4. Ключи/hooks не требуются. Reviewer не принимает своё видео и не выдумывает согласие. После принятия MP4 продолжить `next` в разрешённом scope; upload и публикация требуют прямого поручения на выпуск по [workflow](../../../docs/workflow.md).
