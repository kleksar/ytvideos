# Scene images

Use the current project instructions, episode state and channel profile. For Paper Detour explicitly read the [Paper profile](references/paper-detour.md) before preparing prompts, generating, editing or reviewing scenes, both for a direct image request and a full-production handoff. References are not loaded automatically. For Nuviko read the [Nuviko visual profile](../../../channels/nuviko_history/brand/VISUAL_PROFILE.md). Both channels follow the [same production flow](../ytv-video-production/SKILL.md); other channels supply their own visual contract. The core does not prescribe a medium, aspect ratio, palette, scene count or approval of every image. Read the applicable image-generation skill for tool mechanics; do not copy its API procedure here.

## Establish the actual selection

For every ytvideos channel, apply the [shared bold visual staging standard](../../../.agent/VISUAL_STAGING.md) when developing, generating and reviewing images. Obtain the first-glance focal idea, expressive device and meaningful supporting details from the staging brief; retain the channel's own medium and identities. At actual-file review check whether that idea reads in reduction and whether full-size details support it. Material fidelity or photorealism alone does not accept an inert image; return a weak idea to staging rather than merely increasing texture or resolution.

Read the accepted storyboard revision, current scene selection and acceptance evidence before choosing files. Record the image's narrative job, depiction status (evidence/reconstruction/metaphor), composition, recurring identities, object state and relevant source constraints. Resolve missing creative decisions with the storyboard owner from the accepted material and channel profile. A scene-image task does not rewrite narration or invent another event.

For each recurring character, carry forward the storyboard's presence decision and narrative role. For a recurring presenter, require a completed [storyboard presence check](../ytv-video-production/references/visual-storyboarding.md#проверка-присутствия-ведущего) before preparing the affected image prompt. Return missing or unclear staging to the storyboard owner before generation. In a presenter shot, carry the approved visible action into the prompt. Build the identity, costume and reference block only for shots with that character. In an absent-character shot omit that block and the character-reference images.

When revising a recurring-character defect across a film, first inspect every actual selected image in the scoped sequence, including shots marked character-absent. Record planned versus observed presence, exact file/version and time range in the existing image log. Storyboard tags and filenames are intentions, not an inventory of visible people. An unintended character appearance requires removal or a revised staging decision within the user's scope; changing its style alone does not authorize its role. Resolve the full affected set before declaring the character fixed.

For Paper/Nuviko the release coordinator owns meaning and shot selection through [visual storyboarding](../ytv-video-production/references/visual-storyboarding.md), with the channel's staging profile. Obtain a concrete visible situation and narrative purpose before preparing a prompt. For a recurring presenter, require the completed presence and removal check before generation. Return a beat that fails it to the storyboard owner. A noun, generic workstation, standing presenter or unnamed geometric object is not a complete staging brief.

Before media search, reuse or generation, check the project's asset library and dedupe records where present. Reconcile actual paths and hashes, editorial suitability, provenance and rights separately. An identical file or public source is not permission or visual acceptance.

For scenes depicting recognizable real people, companies, products, names/logos, interfaces, buildings, machines or artifacts in any period, apply [visual references](references/historical-visual-references.md) before generation. Inspect and supply real visual anchors for identity/construction and the appropriate date or version, then create the planned viewpoint and action under the channel profile. This is production reference work, not a new fact-check of the accepted narration. Carry the storyboard's chosen story-specific anchors into the prompt and actual frame; if the identity anchor or meaningful detail is missing, resolve it rather than silently substituting a generic object. An intentionally generic or metaphorical scene remains valid when its staging calls for it.

Resume at the first missing or invalid result. Preserve accepted images whose relevant dependencies still match. Do not select the highest filename version or treat review of the same scene ID as review of a different image. Do not migrate every historical manifest just to use this skill; the [handoff contract](references/scene-handoff.md) maps existing records without replacing them.

## Motion-safe composition

Before generating an image intended for permitted whole-image movement/zoom, obtain the planned camera envelope and protected faces, action objects and text from the storyboard. Compose for the whole path: source aspect, delivery fill crop, whole-image zoom/horizontal pan and overlay regions together. Choose a wider composition or reduce planned motion before generation when needed; do not reserve a universal percentage. Check the actual selected PNG against that envelope before import, including intermediate extrema. Start/middle/end samples alone do not establish containment throughout motion. A static image passing its own review does not establish motion safety. Changed framing or motion requires a targeted recheck and the actual composite is reviewed before the stage-16 MP4 handoff; export checks follow the shared QA profile.

At acceptance of each actual image, finalize and save its motion decision once: subject, focus point, direction/zoom, start/end center and scale, and narrative reason under the [motion owner](../ytv-image-motion/SKILL.md). Use the observed composition and spoken beat, considering the adjacent scene. This handoff is reused directly during montage; do not reselect movement by scene number.

## Produce only the needed change

Declare generation versus editing per asset. For a request to change only one element of an existing image, inspect and supply that image as the edit target alongside the required character/style references. State the preserved background, camera, props, action and text, and compare the result with the actual target. References alone do not preserve an existing scene. Do not silently replace a scoped edit with a new composition. For an explicitly requested complete visual rebuild, create new scenes from the revised staging; prior images can serve only the specific reference roles assigned to them.

Fix identity/material/location invariants in the episode's visual bible, anchored to actual accepted reference files. Visually inspect the required accepted anchors before preparing related prompts; reading filenames or a text description does not establish their appearance. Pass the appropriate files as image references in every related generation/edit, identifying their roles. Check the actual outgoing request includes every required reference; a manifest entry or a promise to use it is not evidence that it was supplied. If a required anchor is unavailable, resolve that input before the affected generation instead of silently substituting prose. A style reference defines appearance; the current storyboard defines whether an object has moved, disappeared or changed. Never reset an event to match the reference. Compare with the original accepted anchor and current state instead of accumulating drift from the latest generation.

When the channel combines different rendering styles, describe the recurring character and environment separately with the profile's concrete visual traits. A general realism instruction must not override an illustrated character. Matching identity or clothing alone does not establish matching rendering style; apply the actual channel profile rather than a cross-channel ban on photorealism.

Separate identity/style from pose and composition whenever the reference contains a character. Do not assume a reference image's stance, gaze, arm/hand positions, gesture, prop grip or framing are identity invariants. Before generation, state each visible hand's intended action and relation to the body/props; make the action differ from the reference when the story calls for it. If the hands have no story purpose, frame or occlude them naturally, or omit the character. Do not rely on a generic “vary the pose” instruction or a negative prompt alone: specify a concrete replacement action for this shot. Inspect both hands against that brief in the full image and reject an inherited/repeated pose when it conflicts.

Execute the accepted composition and profile, preserving unaffected content. Specify requested image quality, aspect and resolution in every generation/edit brief. Use any targets defined by the channel profile. Set targets the profile leaves open in the episode brief before generation, using the delivery geometry and planned crop and zoom. Set corresponding tool controls explicitly when available. Otherwise express the targets in the prompt and record which controls were available. Record the requested generation target, measured native source dimensions and video delivery geometry separately. Get the video delivery geometry from the export contract and its owner.

Save an immutable new version, exact prompt, requested and actually applied controls, available generation/source provenance, actually supplied reference paths/hashes and their roles, and measured native dimensions. Distinguish required references from those actually supplied. Unknown parameters stay unknown. Keep imported assets at their existing paths; do not overwrite or move them. A repeated shot may reuse the exact opening file if the storyboard requires it.

If the user requested only a first style sample, make and check that sample, show it with the actual reference and record the user's decision before the rest of the series. This is conditional on that request. For an authorized full series, continue through remaining scenes and internal checks without inventing per-image approval gates. A draft is not a newly approved channel reference.

For a new scene series or a substantive visual-direction revision, produce a small representative subset first, selected for contrasting narrative jobs and the hardest composition/material/text risks. Review those actual files at full and intended viewing size before scaling the approach across the series. Use already suitable images when they provide that evidence. This is an internal early check within the authorized work, not a new user approval gate or a fixed scene count. Record selected IDs, findings and resulting brief corrections in the existing image log; a useful single sample does not establish sequence variety.

For a recurring character in a mixed-style world, include a shot with that character in this early check and verify the rendering-style boundary before scaling character shots. A successful environment-only sample does not establish character fidelity.

Finish and inspect the early subset before launching the remaining batch. Starting all calls together and reviewing their outputs later does not satisfy the early check.

## Review the exact files

For each selected scene, record in the existing image log a scene-level comparison before montage: storyboard revision and scene ID, exact asset path and SHA-256, assigned text and its carrier or an explicit intentional absence, other essential visual requirements, what is actually visible, reviewer, decision and evidence. Preserve the storyboard's distinction between exact wording and reconstructed incidental text; an unspecified assignment remains UNVERIFIED, not an implicit absence. Inspect the selected image individually at a readable size and its intended crop; a contact sheet or OCR may help locate problems but cannot certify the result. A missing or unreadable assigned text or other essential requirement is a blocking defect; correct it or return the scene to staging. A replacement file requires a new comparison and decision. Do not hand an unaccepted or unverified selected asset to montage as accepted.

Open every selected image individually, full-frame, against the actual applicable reference; magnify consequential details. Check the readable action/state, identity, number of people, era, clothing/prop continuity, faces, fingers, jewelry, head/body proportions, perspective, supported plants/objects, contact and natural shadows. Inspect connected bodies/objects across transparent surfaces and occlusions; a hidden limb and a generatively missing limb differ. Apply the profile's material and defect criteria.

For recurring characters record separate observed findings for presence/role, rendering style, identity and costume against the accepted anchors. For a presenter, confirm that the assigned visible action reads in the actual image. Describe visible style evidence, such as drawn contours and colored shading where required, rather than inferring a pass from familiar clothing. An unexpected presenter, a missing or unreadable assigned presenter action, a photorealistic substitute for an illustrated host, or another required-style mismatch is a blocking defect even if the image is otherwise attractive.

For mixed-style profiles, assess the environment independently from the character, then their physical integration. Check foreground props and items in the character's hands as well as the background; neither side inherits a pass from the other. Use the channel profile's actual material/rendering criteria.

First assess whether the actual image delivers the storyboard's visual purpose in context: the focal action/state is apparent, significant details support it, the setting is credible for the task, and its contribution differs meaningfully from adjacent shots. Inspect the full image and a reduction at the intended viewing size. Correct anatomy, rich texture, dramatic light or adherence to the prompt do not establish semantic acceptance. A polished image with no readable purpose returns for staging revision rather than passing on technical merit.

Identify the observed focal point and supporting detail in the review, rather than copying the intended purpose from the prompt. Return the image when an intended relation is absent, the dominant empty area has no staging purpose, competing details hide the main event, or required text loses meaning at the viewing size. A quiet or sparse image can pass when its actual composition serves the assigned mood, scale or transition; do not add objects merely to satisfy a detail count.

When a book, page, card or screen is meant to convey information, inspect whether the actual image conveys it. A meaningless blur, generic code texture or empty page cannot stand in for information the scene needs. Plausible reconstructed content is allowed when its meaning fits the accepted story without claiming authentic telemetry, precise measurements or original quotations. Check required lettering, historical symbols and quotes against the accepted content and sources; use the channel profile for incidental text. Record reconstruction/provenance internally; do not bake service badges such as “Conceptual diagram” into scene art. Applicable mandatory disclosures/credits remain separate requirements. Missing required information, unsupported objects and broken anatomy block import until repaired.

Measure decodeability, native size, format and alpha. Record fit to the delivery frame: proportional scaling, crop and any padding. Inspect the actual crop at target viewing size; do not stretch to force a ratio or call an upscale native detail. If an image doubles as a cover, invoke the thumbnail owner for that separate use.

Check the language, script and content of visible interfaces, papers, labels and signs against their place, date, institution and users. The language of the production brief does not set the language of objects in the scene. Distinguish in-world text from editorial captions, whose language follows the content profile. Specify needed visible wording before generation and inspect the actual result at readable size; unsupported language, invented operational states or era-inappropriate interfaces require correction. Do not hide a required meaning behind blur to avoid this check.

Before handing off a newly produced or revised scene set for montage, inspect a contact sheet of the actual selected files in edit order, labeled with scene IDs and exact versions. Cover the full scoped sequence, including relevant unchanged neighbors after a replacement. Compare recurring composition, subject scale, silhouettes, background, narrative contribution and emphasis. Return the specific range when different story beats remain visually interchangeable and the repetition has no intended function; do not pass the sequence solely because every file is attractive in isolation. Keep intentional motifs and pauses. A contact sheet does not establish timing or final-film playback quality.

In that actual sequence, check whether the selected real-world identities and story-specific objects are recognizable where needed and whether the images contribute actions, relationships or consequences in addition to text. A run of generic backgrounds with changing labels is a staging defect; identify the affected shots and return them for revision. Check important logos, product marks and interfaces against their inspected references at intended viewing size, including any crop and overlays. Fix distorted or misleading significant identity marks; do not claim a generated mark is accurate merely because it was requested. Meaningful text and intentional minimalism remain valid.

Reject a blocking defect, describe it concretely, repair the affected version and recheck the whole replacement plus relevant neighboring continuity. Contact sheets do not replace full individual inspection. In the existing image log/manifest record exact files, sheet path, covered IDs, observed sequence findings and corrections; uninspected details stay unverified. Technical checks and SHA do not prove style, rights, caption fit or final-film QA.

## Hand off and resume

Return the exact selection with versions/hashes, dependencies, acceptance author/evidence, rejection reasons, checks performed and limitations using the [handoff contract](references/scene-handoff.md). Internal acceptance, user approval and independent review are separate evidence; preserve their actual scope. Self-review is not independent review.

Refreshing a hash, subtitle contract or export-settings receipt only restores that technical binding. It does not perform image review, close a visual defect or establish acceptance of new pixels. Carry the actual image findings and unresolved coverage into the handoff.

Only currently accepted assets are ready for import, except a clearly labeled draft explicitly requested for review. That exception does not waive a known mandatory-profile defect: `DRAFT` or `UNVERIFIED` and a general request to continue or deliver MP4 do not accept that deviation. Repair it within the authorized production scope before normal montage handoff; only an explicit user request to inspect the identified defective draft permits its scoped review handoff. Do not invent another routine approval gate. A partial set remains partial. Changed relevant storyboard content, reference requirements, source bytes or framing requires targeted recheck; unchanged dependencies keep their evidence. Editing an unused future prompt alone does not invalidate an accepted PNG. A replacement invalidates dependent crop/caption-fit/edit/export checks until rechecked, not unrelated narration or the entire series.

Storyboard controls scene meaning/sequence; subtitles owns the narration line and cue fit; editor owns import, permitted motion, timing and export; final QA owns the actual film. Pass framing and text areas as constraints, not proof that later composites work. This skill grants no new audio, publication, timeline mutation or delegation authority.
