# Paper Detour SRT profile

Read [bootstrap](../../../../.agent/CHANNEL_BOOTSTRAP.md), its required root/registry/current-state inputs and [Paper AGENTS](../../../../channels/paper_detour/AGENTS.md). Missing analysis/editorial choices go through the coordinator's personal [Extra High](../../ytv-chatgpt-session/SKILL.md) pass. This is a project dependency, not a requirement for another channel using the core.

For each applicable new Paper film and Short prepare a separate SRT in the actual accepted audio language, normally English. The separate on-screen narration layer is owned by [ytv-paper-subtitles](../../ytv-paper-subtitles/SKILL.md); it does not replace the uploadable sidecar. Chapters remain with [chapters](../../ytv-youtube-chapters/SKILL.md).

Use the actual English narration/retained dialogue and existing word alignment. For ElevenLabs the project adapter is [word_timings.py](../../../../automation/captions/word_timings.py): `--text`, `--alignment`, `--language en`, `--output` (new JSON). It validates character alignment against the text; its RU/EN limitation belongs to that adapter, not to the portable SRT core. For other languages/providers use an applicable supported aligner and prepare the same neutral cues. Do not recreate or request another voice take merely for subtitle timing.

Keep the exact source audio/hash and current narration text/hash. Prepare clause-based cues from the actual timed words, preserving punctuation/case from narration; use current scene/edit timing only to conform them, not to guess speech. An optional starting review setting is two lines and 42 characters per line from the legacy project helper; these are configurable heuristics, not platform requirements. Inspect line breaks on decoded final-MP4 frames at phone size. The MP4 need not be opened in a player. Other reading-density/time thresholds should be explicit, not silently inherited.

The older `make_narration_srt.py` helper is legacy automatic grouping code and is not included in this source-only clone. Its output is a draft: it clamps cue ends to audio duration and assumes source-time placement. New SRT work uses this skill's strict serializer/validator and explicit conform evidence; do not treat old helper success as final sync or copy its clamping into new procedures. Existing outputs remain valid only to their actual evidence; this refactor does not change or rerender them.

For the required SRT, follow the [core final timing and playback rule](../SKILL.md#serialize-and-check). Use decoded frames when checking cue placement and readable wrapping. Record exact frame or playback coverage. A user viewing of burned-in subtitles establishes that viewing only; use the final audio and word map to verify sidecar conform separately.

Store the final sidecar in the episode's accepted `Deliverables/`; label development examples as work/research files. [Audio delivery](../../ytv-audio-delivery/SKILL.md) owns audio production and export settings; [video QA](../../ytv-video-qa/SKILL.md) owns final audio/video verification and the [Paper offline QA profile](../../ytv-video-qa/references/paper-detour.md). SRT owns its transcript, segmentation/conform and sampled-frame subtitle checks. [Release](../../ytv-youtube-release/SKILL.md) calls the existing uploader for an explicitly authorized subtitle upload/association and checks the saved target language/track; creating an SRT alone grants no external change.
