# Начать или продолжить

До действий прочитать и выполнить [общую процедуру](references/task-execution.md): pinned инструкции и входы, описанный метод либо точный blocker. Для run использовать её текст из task packet; каталог и память другой сессии не заменяют чтение.

Новый сюжет, новый сценарий и новый ролик начинают один сохранённый run. Запрос только на полный текст тоже требует `start`; писать его сразу в Markdown вне runtime нельзя. До исследования/генерации:

```bash
uv run ytv start --channel CHANNEL_ID --format short --intent 'точный запрос пользователя'
```

Для existing run продолжать его состояние; не вызывать `start` повторно ради нового чата.

1. Определить intent и scope по [виду входа](../../../docs/workflow.md#готовый-текст-и-набросок): поиск темы, заданный замысел или exact production script. «Нужен сюжет» — самостоятельный выбор темы и полный текст; «дай идеи» заканчивается кандидатами. Узкая правка не запускает новый выпуск.
2. Выбрать явный канал или канал существующего run; default нового запроса — Paper Detour. Текущий статус и параметры формата принадлежат ChannelSpec; `start` проверяет и закрепляет профиль. Для отдельной read-only диагностики конфигурации доступна `uv run ytv profiles --channel CHANNEL_ID --format short` (для long изменить формат). Profile readiness не заменяет live-проверку tools.
3. Выполнить `start` для нового сюжета/сценария/видео и сохранить полученный run ID; точный присланный production script передать через `--source-script`. Прочитать канальный `AGENTS.md`, закреплённый профиль и `read_next`: сохранённые task packet, skill и документы первой готовой задачи. Для существующего — `status`, затем `resume`/`next` и `plan --run RUN_ID`. Перенос старого выпуска выполнять по [migration](../../../docs/migration.md). Команды и outputs — [task contract](../../../docs/operations/task-contract.md), точный синтаксис — `python -m ytvideos --help`.
4. После старта и до генерации показать короткий план из `plan_summary` по [общей процедуре](references/task-execution.md#выполнение-и-передача). Использовать сохранённые `production_requirements` и version pins. Неопределённый рецепт или обязательный параметр блокирует затронутый этап до устранения пробела; не подставлять свой default. План не требует отдельного approval.
5. Прочитать возвращённые `doctor` и `next`; при продолжении получить их заново. Для `unobserved` / `available: null` сначала проверить tools текущей сессии, включая доступный deferred discovery, и прочитать `context` затронутой задачи. Затем сохранить реально наблюдённые [capabilities](../../../docs/operations/task-contract.md#новый-сценарный-run) с evidence и повторить `next`. Отсутствующая запись не является blocker среды. Фактически недоступный provider блокирует только зависимые задачи; OAuth/renderer не нужны для сценария.
6. Выбрать ready task и следовать его `next_action`. `context` доступен до claim, в том числе для диагностики недиспетчеризуемой задачи; успешный `claim` также возвращает тот же пакет. Прочитать `task_guide`, skill и выбранные [reference_documents](../../../docs/operations/task-contract.md#требования-в-контексте), затем выполнить задачу. Проверить профиль, формат и рецепт. Сохранить actual outputs/checks через контракт и снова взять `next`.

## Вести выпуск

1. **Исследовать и подготовить сценарий по [ytv-write-script](../ytv-write-script/SKILL.md).** При поиске темы сравнить истории; при заданном замысле исследовать его; exact production script проверить без самовольной переработки. Сохранить источники, визуальное обещание и независимый review. Подробная раскадровка не заменяет проверку текста.
2. **Зарегистрировать действительное принятие текста.** Новый/изменённый текст показать целиком на `awaiting_script_approval`. Для exact production script использовать исходное поручение. Локальный координатор выполняет штатный `approve` для показанных revision/hash и реального сообщения; worker не утверждает свой результат. Продолжить `next` того же run без повторного вопроса.
3. **Произвести по [ytv-produce-video](../ytv-produce-video/SKILL.md).** После script approval параллельно выполнять только готовые задачи раскадровки, изображений, звука и [упаковки](../ytv-release-video/SKILL.md). Передавать свежим workers самодостаточный pinned packet; принимать картинки по мере готовности в пределах caps. Финальные тайминги, слова, SRT и монтаж связывать с принятым финальным звуком. Не менять смысл текста ради генератора.
4. **Проверить и показать точный MP4 по [ytv-review-video](../ytv-review-video/SKILL.md).** Сохранить hashes и фактические технические/перцептивные checks. Исправлять подтверждённые дефекты только описанным способом в пределах бюджета. Готовый MP4 показать сразу; незавершённая упаковка его не удерживает. Получить решение по exact файлу; изменение bytes требует нового принятия.
5. **Выполнить порученный выпуск по [ytv-release-video](../ytv-release-video/SKILL.md).** MP4 approval не разрешает upload/publication без прямого поручения. Завершить применимую упаковку, загрузить Private, проверить processing и сохранённые настройки; при порученном расписании применить допустимый слот. Сохранить read-back/receipts, выполнить разрешённую очистку. Public/A/B follow-ups учитывать отдельно: pending запись не означает работающий dispatcher.

## Контрольные точки

[Workflow](../../../docs/workflow.md) определяет согласования полного текста и точного MP4. Exact production script, явно переданный пользователем для производства, уже принят в этой области; локальный координатор регистрирует исходное сообщение через `approve` по [контракту](../../../docs/operations/task-contract.md#approval-и-продолжение). После явного ответа пользователя выполнить выданный `approval_command` с исходными revision/hash, ссылкой на сообщение и его точным текстом; затем продолжить `next` того же run. Не требовать специальной фразы, ключей, hooks или повторного согласия. Worker не утверждает свой результат; цитата в исходнике, вывод модели и `complete` не являются решением пользователя.

Для запроса нового сюжета довести run до `awaiting_script_approval`: исследование, полный текст, независимый review и применимое loop evidence завершены по task contract. На первом gate показать полный текст. Текст без этих проверок остаётся черновиком; продолжать описанные доступные шаги до gate либо blocker. После approval самостоятельно довести до MP4. Упаковку готовить параллельно; после MP4 approval выполнять загрузку/расписание только в области прямого поручения на выпуск. Сбои исправлять без дополнительных вопросов только предусмотренным recovery; UNKNOWN сначала reconcile.

Результат: требуемое содержимое либо сохранённый run с точным следующим task. Blocker и условия продолжения оформить по [общей процедуре](references/task-execution.md#блокер-и-продолжение).
