# Начать или продолжить

CLI и точные outputs/receipts: [task contract](../../../docs/operations/task-contract.md).

1. Определить intent и scope по запросу. «Нужен сюжет» — полный новый выпуск, начиная с самостоятельно найденной темы и полного текста. «Дай идеи» заканчивается кандидатами. Узкая редактура не начинает производство.
2. Выбрать явный канал или канал существующего run; для нового запроса без канала — Paper Detour. Проверить `channels/<id>/channel.json` и `AGENTS.md`. Paper Detour, Scenes on Repeat и Nuviko History активны. Stories остаётся ручным архивом вне автоматической очереди и не является новым каналом коллеги.
3. Для нового выпуска вызвать `create`: ID выделяет приложение, старый bundle не требуется. Для существующего — `status`, `resume`/`next`; при переносе — `import-legacy` по [migration](../../../docs/migration.md). Команды и обязательные аргументы проверить через `python -m ytvideos --help`.
4. Выполнить `doctor` для действительного окружения. Сообщить существенные блокеры один раз с затронутым этапом; продолжить независимую работу. Не требовать OAuth, renderer или image tool для написания сценария.
5. Получить `next`, затем `context` конкретного task. Прочитать выданный skill и только перечисленные references. Claim task до исполнения. После результата сохранить outputs и реальные checks по машинному контракту, снова взять `next`.

## Контрольные точки

[Workflow](../../../docs/workflow.md) задаёт два обычных согласования: полный текст и точный MP4. Полный сценарий от пользователя для производства уже содержит разрешение в его scope; bridge записывает подлинное событие. Текстовая запись агента «пользователь согласен» не заменяет approval envelope.

Показать полный сценарий при первом gate; после его approval самостоятельно довести до MP4. После MP4 approval завершить упаковку и расписание по политике канала. Решаемые проблемы и routine choices исправлять без дополнительных вопросов. Не создавать новую сессию как способ обойти UNKNOWN, лимит или блокер.

## Результат

Сохранённый run, точный следующий task/context либо полное требуемое пользователю содержимое на одной из контрольных точек. При остановке назвать stage, evidence, границу доступной работы и единственное необходимое действие пользователя.
