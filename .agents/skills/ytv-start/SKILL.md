# Начать или продолжить

1. Определить intent и scope. «Нужен сюжет» — самостоятельный выбор темы и полный текст; «дай идеи» заканчивается кандидатами. Узкая правка не запускает новый выпуск.
2. Выбрать явный канал или канал существующего run; default нового запроса — Paper Detour. Прочитать его `AGENTS.md` и проверенный `channel.json`. Текущий статус принадлежит ChannelSpec; замороженный, архивный или неподключённый канал не объявлять активным по старой инструкции.
3. Для нового выпуска вызвать `create`; для существующего — `status`, затем `resume`/`next`. Перенос старого выпуска выполнять по [migration](../../../docs/migration.md). Команды и outputs — [task contract](../../../docs/operations/task-contract.md), точный синтаксис — `python -m ytvideos --help`.
4. Выполнить `doctor` действительного окружения. До claim записать реально наблюдённые [capabilities](../../../docs/operations/task-contract.md#новый-сценарный-run). Если инструмент доступен, но наблюдение отсутствует, сохранить evidence и повторить `next`; отсутствие записи не равно отсутствию инструмента. Недоступный provider блокирует только зависимые задачи. OAuth/renderer не нужны для сценария.
5. Выбрать ready task, получить его `context`, прочитать skill и выбранные [reference_documents](../../../docs/operations/task-contract.md#требования-в-контексте), затем claim. Проверить профиль, формат и рецепт. Сохранить actual outputs/checks через контракт и снова взять `next`.

## Контрольные точки

[Workflow](../../../docs/workflow.md) определяет согласования полного текста и точного MP4. Сценарий, явно переданный пользователем для производства, уже принят в этой области; trusted bridge записывает подлинное событие. Самоотчёт модели не является approval.

На первом gate показать полный текст. После его approval самостоятельно довести до MP4. Упаковку готовить параллельно; после MP4 approval выполнять загрузку/расписание только в области прямого поручения на выпуск. Решаемые сбои исправлять без дополнительных вопросов; UNKNOWN сначала reconcile.

Результат: требуемое содержимое либо сохранённый run с точным следующим task. При blocker назвать этап, evidence, уже сделанные попытки, доступную независимую работу и единственное необходимое действие пользователя.
