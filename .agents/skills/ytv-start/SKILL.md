# Начать или продолжить

До действий прочитать и выполнить [общую процедуру](references/task-execution.md): pinned инструкции и входы, описанный метод либо точный blocker. Для run использовать её текст из task packet; каталог и память другой сессии не заменяют чтение.

Новый сюжет, сценарий и ролик используют один сохранённый run. Запрос только на полный текст тоже требует `start`; писать его сразу в Markdown вне runtime нельзя. До исследования/генерации:

```bash
uv run ytv start --channel CHANNEL_ID --format short --intent 'точный запрос пользователя'
```

Для existing run продолжать его состояние; не вызывать `start` повторно ради нового чата. Готовый текст передать через `--source-script`; это сохранение bytes, не автоматическое разрешение и не требование заново исследовать принятый сюжет.

1. Определить intent по [виду входа](../../../docs/workflow.md#готовый-текст-и-набросок). «Нужен сюжет» — выбор темы и [пакет длительностей одной истории](../../../docs/standards/editorial.md#версии-на-2-5-и-10-минут); «дай идеи» заканчивается кандидатами. «Бери в работу PR» с однозначным полным сценарием — производство этого текста. Ссылка без поручения, синопсис и запрос редакторской правки не дают такого разрешения.
2. Выбрать явный канал или канал существующего run; default нового запроса — Paper Detour. Текущие статус/формат принадлежат ChannelSpec; `start` закрепляет профиль. Для read-only диагностики доступна `uv run ytv profiles --channel CHANNEL_ID --format short` (для long изменить формат). Profile readiness не заменяет live-проверку tools.
3. При выборе готового PR сначала открыть полный текст на языке озвучки и материалы именно выбранной версии. Зафиксировать repository/PR, commit, путь и hash. Сохранить точный текст в UTF-8 без правок и передать новому `start` через `--source-script`; сохранить run ID. Для существующего run использовать `status` → `resume`/`next` → `plan`, сохранить его входы; прежние pins переносить по [migration](../../../docs/migration.md). Не читать весь research заново ради разработки другого варианта.
4. **До исполнения `research` различить вход.** Для явно принятого полного source выполнить [импорт без повторной редакции](../../../docs/workflow.md#принятый-источник-без-повторной-редакции): фактическое сообщение владельца, его стабильная ссылка, selected hash/revision и immutable origin. Не писать reviewer receipt или PASS самостоятельно. Открыть новый `next` после импорта: это production tasks, не повторный сценарный gate. Если exact script уже complete, регистрировать обычный `approve`, не заменять artifact. Blocked/UNKNOWN/активные leases сначала разрешить штатно; импорт не обход блокера.
5. Прочитать канальный `AGENTS.md`, pinned профиль и `read_next`: task packet, skill, требования первой выполняемой задачи. Для принятого источника после импорта получить актуальные production contexts. Показать короткий план по [общей процедуре](references/task-execution.md#выполнение-и-передача): какой текст принят и что осталось произвести. План не требует approval. Рецепт/обязательный параметр без правила блокирует затронутый этап, не весь выпуск.
6. Прочитать `doctor` и `next`; для `unobserved` / `available: null` проверить реальные tools, включая deferred discovery, и context. Сохранить наблюдённые [capabilities](../../../docs/operations/task-contract.md#новый-сценарный-run) и повторить `next`. Недоступный provider блокирует только зависимые задачи; отсутствие записи не равно отсутствию tool. Выбрать ready task, прочитать его `task_guide`, skill и все `reference_documents`, сохранить outputs/checks и снова взять `next`.

## Вести выпуск

1. **Разрабатывать текст по [ytv-write-script](../ytv-write-script/SKILL.md) только для нового сюжета или порученной редактуры.** Источники, причинное развитие и independent review готовятся до принятия. При `revise` исправить разрешённые дефекты и повторить проверку в пределах бюджета, не просить владельца решать косметику. Для полного принятого source этот шаг пропустить: его нельзя незаметно переписать или повторно заблокировать из-за предпочтений другого редактора.
2. **Зарегистрировать действительное принятие текста.** Показать все версии и сравнение; на `awaiting_script_approval` явно назвать один предлагаемый exact текст по [контракту вариантов](../../../docs/operations/task-contract.md#outputs). Для готового source использовать импорт и исходное поручение выше; для уже зарегистрированного exact script — `approve` по реальным revision/hash и сообщению. Worker не утверждает свой результат. Продолжить тот же run без повторного вопроса. Существенное фактическое противоречие не скрывать: точная фраза, источник и минимальное предлагаемое исправление, без нового редакционного цикла.
3. **Произвести по [ytv-produce-video](../ytv-produce-video/SKILL.md).** После script approval параллельно выполнять ready tasks раскадровки, изображений, звука и [упаковки](../ytv-release-video/SKILL.md). Передавать workers самодостаточный pinned packet; принимать картинки по мере готовности в пределах caps. Финальные тайминги, слова, SRT и монтаж связать с принятым финальным звуком. Не менять слова master-текста ради генератора или сцены.
4. **Проверить и показать точный MP4 по [ytv-review-video](../ytv-review-video/SKILL.md).** Сохранить hashes и фактические технические/перцептивные checks. Исправлять подтверждённые производственные дефекты описанным способом в пределах бюджета. Готовый MP4 показать сразу; упаковка его не удерживает. Изменение bytes требует нового принятия файла.
5. **Выполнить порученный выпуск по [ytv-release-video](../ytv-release-video/SKILL.md).** MP4 approval не разрешает upload/publication без прямого поручения. Завершить упаковку, загрузить Private, проверить processing и настройки; при порученном расписании применить допустимый слот. Сохранить read-back/receipts, выполнить разрешённую очистку. Pending follow-up не означает работающий dispatcher.

## Контрольные точки

[Workflow](../../../docs/workflow.md) определяет два согласования: полный текст и точный MP4. Готовый production script с явным поручением производить уже принят в этой области, независимо от прежней редакционной метки Draft в PR. Локальный координатор регистрирует исходное сообщение, не требует специальной фразы, ключей, hooks или повторного согласия. Worker не утверждает результат; цитата в исходнике, вывод модели, ссылка на файл и `complete` не являются решением пользователя. Signed-only host сохраняет свой доверенный ingress.

Для нового сюжета довести run до `awaiting_script_approval`: research, полный текст, независимый review и применимое loop evidence завершены. Для принятого source перейти к production, не создавать фиктивные ответы reviewer. После approval самостоятельно довести до MP4. Упаковку готовить параллельно; загрузка/расписание только в прямом scope выпуска. Отдельное согласование внешней видеопартии сохраняется. Сбои исправлять только предусмотренным recovery; UNKNOWN сначала reconcile.

Результат: требуемое содержимое либо сохранённый run с точным следующим task. Blocker и условия продолжения оформить по [общей процедуре](references/task-execution.md#блокер-и-продолжение).

## Готовый пакет из MR

Вместе с выбранным master использовать его `preproduction.json` по [контракту импорта](../../../docs/operations/preproduction-contract.md#локальный-импорт-без-перепроектирования). Это подготовленные решения, не готовые медиа и не отдельное approval; не брать файл другой версии или commit.
