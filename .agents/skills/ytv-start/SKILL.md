# Начать или продолжить

Новый сюжет, новый сценарий и новый ролик начинают один сохранённый run. Запрос только на полный текст тоже требует `start`; писать его сразу в Markdown вне runtime нельзя. До исследования/генерации:

```bash
uv run ytv start --channel CHANNEL_ID --format short --intent 'точный запрос пользователя'
```

Для existing run продолжать его состояние; не вызывать `start` повторно ради нового чата.

1. Определить intent и scope по [виду входа](../../../docs/workflow.md#готовый-текст-и-набросок): поиск темы, заданный замысел или exact production script. «Нужен сюжет» — самостоятельный выбор темы и полный текст; «дай идеи» заканчивается кандидатами. Узкая правка не запускает новый выпуск.
2. Выбрать явный канал или канал существующего run; default нового запроса — Paper Detour. Прочитать его `AGENTS.md` и проверенный `channel.json`. До нового run проверить формат через read-only `uv run ytv profiles --channel CHANNEL_ID --format short` (для long изменить формат). Текущий статус принадлежит ChannelSpec; замороженный, архивный или неподключённый канал не объявлять активным по старой инструкции. Profile readiness не заменяет live-проверку tools.
3. Выполнить `start` для нового сюжета/сценария/видео и сохранить полученный run ID; полный присланный narration передать через `--source-script`. Прочитать `read_next`: сохранённые task packet, skill и документы первой готовой задачи. Для существующего — `status`, затем `resume`/`next` и `plan --run RUN_ID`. Перенос старого выпуска выполнять по [migration](../../../docs/migration.md). Команды и outputs — [task contract](../../../docs/operations/task-contract.md), точный синтаксис — `python -m ytvideos --help`.
4. После старта и до генерации показать короткий план из `plan_summary` по [workflow](../../../docs/workflow.md#первый-ответ): выбранный канал/формат, принятые материалы, этапы до результата, художественные требования и существенные блокеры. Использовать сохранённые `production_requirements` и version pins, не память другого выпуска. Если рецепт неоднозначен, назвать конкретный недостающий выбор. План не требует отдельного approval.
5. Прочитать возвращённые `doctor` и `next`; при продолжении получить их заново. Для `unobserved` / `available: null` сначала проверить tools текущей сессии, включая доступный deferred discovery, и прочитать `context` затронутой задачи. Затем сохранить реально наблюдённые [capabilities](../../../docs/operations/task-contract.md#новый-сценарный-run) с evidence и повторить `next`. Отсутствующая запись не является blocker среды. Фактически недоступный provider блокирует только зависимые задачи; OAuth/renderer не нужны для сценария.
6. Выбрать ready task и следовать его `next_action`. `context` доступен до claim, в том числе для диагностики недиспетчеризуемой задачи; успешный `claim` также возвращает тот же пакет. Прочитать `task_guide`, skill и выбранные [reference_documents](../../../docs/operations/task-contract.md#требования-в-контексте), затем выполнить задачу. Проверить профиль, формат и рецепт. Сохранить actual outputs/checks через контракт и снова взять `next`.

## Контрольные точки

[Workflow](../../../docs/workflow.md) определяет согласования полного текста и точного MP4. Exact production script, явно переданный пользователем для производства, уже принят в этой области; trusted bridge связывает исходное подлинное событие с сохранённым artifact/hash. Не просить того же решения повторно. Без подключённого bridge сохранять подготовленные материалы и сообщать технический blocker регистрации; самоотчёт модели и `complete` не являются approval.

Для запроса нового сюжета довести run до `awaiting_script_approval`: исследование, полный текст, независимый review и применимое loop evidence завершены по task contract. На первом gate показать полный текст. Текст без этих проверок остаётся черновиком; продолжать доступные шаги, пока не достигнут gate либо подтверждён реальный blocker. После approval самостоятельно довести до MP4. Упаковку готовить параллельно; после MP4 approval выполнять загрузку/расписание только в области прямого поручения на выпуск. Решаемые сбои исправлять без дополнительных вопросов; UNKNOWN сначала reconcile.

Результат: требуемое содержимое либо сохранённый run с точным следующим task. При blocker назвать этап, evidence, уже сделанные попытки, доступную независимую работу и единственное необходимое действие пользователя.
