# Выполнить задачу по действующим инструкциям

Обязательная процедура для каждого production task, восстановления и узкой правки, включая отдельного worker без предыдущего разговора. Требования к результату принадлежат выбранным standards и профилю; формы данных и команды — [task contract](../../../../docs/operations/task-contract.md).

## До действия

1. Координатору для нового сюжета/видео выполнить [ytv-start](../SKILL.md); для существующего run получить `status`, затем `resume`/`next` и `plan`. Не создавать дубликат и не повторять принятый результат ради нового чата. Изолированному worker использовать выданный packet в пределах своей роли. Для узкой работы без run прочитать выбранный skill и применимые references; отсутствие run не отменяет эту процедуру.
2. Прочитать **текст** назначенного skill и все требования своей формы задания по таблице ниже, включая эту процедуру, профиль и рецепт. Каталог, название skill, plan и память другой сессии не заменяют чтение. Координатор проверяет pins, channel/format, revision, scope, approvals, бюджет и внешние операции; worker соблюдает выданную версию и область задачи.
3. Открыть точные нужные артефакты указанным для своей роли способом, включая actual references. Descriptor, пример JSON и описание картинки не заменяют содержимое. Для следующего этапа или после изменения входов читать его новый пакет; не переносить параметры предыдущей сцены или канала.
4. Найти в прочитанных правилах основание для текущего действия: способ, допустимые tools/adapter, обязательные параметры или правило их получения, нужные входы, выход и проверки. Явный default, диапазон или разрешённый выбор использовать только в указанной области. Недостающий файл, метод, параметр, вход либо неразрешённое противоречие — **blocker до выполнения**, даже если агент знает правдоподобный способ.
5. Проверить наблюдаемые capabilities по выданному discovery. `unobserved` не означает недоступность: проверить прямые tools и deferred registry, сохранить фактическое evidence. Доступный tool сам по себе не разрешает новый метод или замену provider. При подтверждённой недоступности остановить зависимый этап.

| Форма задания | Обязательное чтение и входы |
|---|---|
| Обычный runtime task | `context` до claim либо пакет успешного `claim`: pinned skill, `task_guide`, `production_requirements`, все `reference_documents`; точные `inputs`/`supporting_inputs` через `artifact_root` |
| Изолированный native image worker | `TASK.json`, локальный `SKILL.md`, все файлы `requirements` по `reference_manifest`, `scene`, `channel`, `format`, `required_checks`; артефакты из `local_inputs`. Coordinator-only `task_guide`, `production_requirements`, `artifact_root`, `supporting_inputs` и workflow CLI здесь не требуются |
| Узкая правка без run | Текущий выбранный skill, применимые standards/профиль/recipe и предоставленные точные артефакты. Не требовать runtime packet, pins или claim и не создавать production run для расширения узкого запроса |

Не придумывать производственные шаги, параметры, defaults, fallback, порядок обхода checks или неподдержанный маршрут. Не подбирать «обычный» шрифт, голос, размер титров, длительность кадра, схему таймкодов, способ монтажа, название/описание вне заданных правил. Не подменять отсутствующее правило практикой другого выпуска, найденной статьёй, примером либо успешным CLI exit.

Авторский выбор допускается только там, где его предусматривают действующие инструкции: например, выбрать проверенную тему, написать narration/title или AI prompt по editorial/visual/release и профилю. Это не разрешает выдумывать факты, угадывать таймкоды или подтверждения. Измеренные данные получать описанным способом из точного артефакта; гипотезы и черновики не выдавать за evidence.

## Выполнение и передача

После `start` и до генерации показать короткий план из `plan_summary`; для продолжения — из `plan`: канал/формат, принятые входы, оставшиеся этапы, важные требования и реальные blockers. Для сценария назвать путь до полного текста и script gate; для продолжения — текущий этап и сохранённые артефакты. План не требует дополнительного согласования.

На каждом этапе выполнять только выданный task в пределах своей runtime role и tool scope. Координатор использует current claim и точные token/input_hash из ответа runtime, сохраняет outputs, hashes, provider handles и реальные проверки через `complete`, затем получает `next`. Изолированный worker возвращает artifact/evidence или blocker host; он не вызывает запрещённый ему workflow CLI и не выдумывает token. Успешная команда не доказывает художественное качество, прослушивание или read-back. Существующие approvals, required checks и UNKNOWN reconciliation обязательны. Для узкого scope выполнять только относящуюся к запросу часть.

## Блокер и продолжение

При пробеле инструкции или подтверждённой невозможности остановить затронутый task **до** generation/tool dispatch/`complete`; не запускать зависящие этапы. Сохранить точный результат и существующие операции. Продолжать только независимые готовые задачи, для которых все инструкции и входы доступны.

Сообщить: run/task/stage и артефакт, что именно отсутствует или конфликтует, прочитанные пути/разделы, наблюдаемое evidence и фактические попытки, какие действия остановлены, какое конкретное правило/вход/доступ нужен для продолжения. Не придумывать попытки. Действие пользователя указывать только если требуется его решение; «доделайте документацию» без точного пробела недостаточно.

До claim не брать lease только ради записи отказа: сохранить сообщение blocker с доступными evidence и не исполнять этап; не утверждать, что runtime уже записал `blocked`. С current claim координатор сохраняет причину штатным `fail` по [контракту блокировки](../../../../docs/operations/task-contract.md#блокировка-и-разблокировка); изолированный worker возвращает blocker host. При возможном external dispatch сохранить UNKNOWN и сначала выполнить описанную reconciliation; `--known-not-sent` не заменяет проверку факта отправки.

Production worker не меняет docs, skills, профиль, code, checks или version pins ради обхода blocker. `resolve_production_policy` означает найти и сообщить недостающее правило, а не разрешение придумать его. Исправление правил выполнять через [ytv-maintain](../../ytv-maintain/SKILL.md) в пределах отдельного поручения на изменение; новое прямое решение владельца учитывать в его точной области и сохранять подлинный источник.

Возобновлять только после проверенного устранения причины: перечитать исправленный контракт и входы, сохранить resolution evidence и выполнить `unblock` для `blocked` task, затем `next` → новый context/claim. Изменение checkout не меняет pinned run: при смене правил применить [migration](../../../../docs/migration.md), а не заменить snapshot/версию вручную. Для UNKNOWN сначала reconciliation. Не создавать новое согласование для уже разрешённого неизменённого результата.
