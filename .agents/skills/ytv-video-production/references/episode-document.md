# Единый рабочий документ выпуска

Владелец структуры и ведения — [production](../SKILL.md). Для новой разработки и нового производства ytvideos использовать один `EPISODE.md` по [шаблону](../assets/EPISODE.md) в установленном рабочем каталоге истории/выпуска. Если выпуск ещё не зарегистрирован, хранить документ рядом с порученной разработкой; не назначать номер или создавать episode bundle ради шаблона. Документ растёт по мере работы: узкое поручение заполняет только нужную часть. Пустые будущие разделы не блокируют предыдущий этап.

При продолжении активного выпуска сначала сверить его текущие документы, версии, решения и владельца. Перенос в EPISODE выполнять только в согласованных пределах; не переписывать автоматически текущие выпуски, медиа, реестр или принятую историю. Ссылки на существующие документы сохраняются. Новый формат не запускает замороженный канал и не создаёт разрешений на звук, генерацию или публикацию.

## Один источник содержания

EPISODE хранит текущий замысел, сюжет, точный narration, постановку, сценовый текст, звуковые намерения и ссылки на выбранные результаты. Порядок и полномочия задаёт production, рассказ — [storycraft](../../ytv-storycraft/SKILL.md), сцены — [visual-direction](../../ytv-visual-direction/SKILL.md), промпты/PNG — [scene-images](../../ytv-scene-images/SKILL.md), звук — [audio](../../ytv-audio-delivery/SKILL.md). Шаблон собирает их результаты, не копирует процедуры.

Текст диктора редактируется только в разделе narration. Полный сюжет/тритмент — отдельный вид материала с собственной редакцией и решением о принятии, а не вторая копия narration. После принятия сюжета и подготовки narration не поддерживать вручную два параллельных дикторских текста. Если исходник уже является точной речью, раздел сюжета может содержать замысел и ссылку на narration. Языковые версии обозначать раздельно; производственную версию выбирать по языковому правилу production. Служебные заголовки и идентификаторы не попадают в озвучку.

Использовать устойчивые ID: `N001` для блока narration, `S001` для сцены, `M001` для звукового отрезка; удалённые ID не назначать новому содержанию. Сцены ссылаются на редакцию/язык narration и начало/конец диапазона: ID блока, точные короткие слова-якоря и номер их вхождения внутри блока, если фраза повторяется. Для диапазона через несколько блоков указать обе границы. Границы включают указанные слова; после alignment им соответствуют технические интервалы `[start_frame,end_frame)`. Цитата для удобства — производное отображение, не редактируемая копия. Номера слов допустимы как дополнение только с указанным правилом токенизации и точной редакцией. Без речи указать `NO_SPEECH` и назначение/интервал; не придумывать словесный якорь заставке или паузе.

## Ведение и версии

- Один координатор вносит согласованные изменения в общий документ; при разрешённом делегировании исполнители передают изменения своих разделов, не перезаписывают файл параллельно.
- У документа есть общая редакция, у narration, постановки и звукового решения — отдельные редакции. Запись результата QA или смена картинки не меняет редакцию неизменного narration.
- Перед передачей в TTS, генерацию и монтаж сохранить точную использованную редакцию/снимок в материалах выпуска. Текст TTS, промпты, cue sheet и render plan — производные; указать источник, раздел/ID, редакцию и hash точного входа. Они могут готовиться разрешёнными файловыми средствами, автоматического экспортёра шаблон не предоставляет. Не редактировать их как независимые сценарии. Исправление содержания сначала вносится в EPISODE, затем обновляются затронутые производные.
- Для зависимостей использовать снимок нужного раздела/блоков или производного входа, а не hash всего постоянно дополняемого EPISODE. Иначе добавление QA-записи сделает ложным образом устаревшими narration и все сцены. Снимок и цепочка до текущей редакции должны позволять проверить, какие байты были использованы.
- Принятое содержание сохраняется по production. Новая редакция не наследует автоматически оценки изменённых частей. Изменение реплики затрагивает соответствующие TTS/alignment/субтитры/сцены/звуковые границы; замена изображения — его проверку, кадрирование и зависимый монтаж. Неизменённые части сохраняют свидетельства после сверки зависимостей.

## Состояние и доказательства

План, созданный файл и проверенный результат — разные вещи. У сцены отдельно фиксировать готовность постановки, состояние изготовления (`PLANNED`/`CREATED`) и решение о выбранном файле (`ACCEPTED`/`REJECTED`/`STALE`); отсутствие файла или проверки оставлять явным. Принятие пользователем, авторская и независимая проверки имеют разные записи. Проверки используют `PASS`/`FAIL`/`UNVERIFIED`/`N_A` с версией, методом, покрытием и ссылкой на свидетельство; пустой шаблон не содержит PASS.

Права, источники, реальные референсы, alignment, медиа, подробные QA и публикационные квитанции остаются отдельными файлами. EPISODE хранит ссылки на их текущие результаты и открытые вопросы. Источники и исследовательские сведения — внутренние по root §11; не выгружать служебный раздел как публичный текст.

`CURRENT_CONTEXT.md` остаётся компактной точкой входа: ссылка на EPISODE и текущий следующий шаг, действующие ограничения и внешнее состояние. При полном flow `FLOW_STATE.json` сохраняет машинное состояние и доказательства этапов по [своему контракту](episode-flow-state.md). Не дублировать их независимыми статусами: в EPISODE ссылаться на записи и при необходимости показывать явно производную сводку.

Для новой серии выбранный asset и его приёмку ведёт один image manifest по [scene-handoff](../../ytv-scene-images/references/scene-handoff.md); EPISODE ссылается на записи по S-ID. Ссылку/миниатюру текущего файла можно отображать производно, не создавать второй редактируемый список выбранных версий. Аналогично точные параметры микса и права ведёт audio handoff, а EPISODE связывает его с замыслом M-ID.

## Проверка перед передачей

Проверить только нужный следующему действию scope: точную производственную версию и решение по ней; уникальность ID; однозначность всех словесных границ; порядок/покрытие речи и мотивированные интервалы без неё; существование указанных актуальных файлов; совпадение редакций и реальных зависимостей. Для генерации дополнительно завершить постановочный и операторский проходы visual-direction, для монтажа — фактическую приёмку выбранных PNG, времени и звука по их владельцам. Ссылка на будущий файл не означает его наличия.

Не создавать обязательные отчёты на каждое поле и не заполнять неприменимые разделы выдумкой. Записывать конкретный результат, существенные дефекты и пределы проверки в соответствующей карточке/общей записи. Этот документ не заменяет художественную проверку формальной заполненностью.
