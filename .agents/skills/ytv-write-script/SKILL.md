# Найти историю и написать полный текст

До действий выполнить [обязательную процедуру](../ytv-start/references/task-execution.md); для run читать её закреплённый текст из task packet.

CLI и точные outputs/receipts: [task contract](../../../docs/operations/task-contract.md).

Для `research` и `script` прочитать профиль канала, [editorial](../../../docs/standards/editorial.md), [thumbnail promise](../../../docs/standards/thumbnails.md) и [формы начала](references/hook-patterns.md). На `script` дополнительно прочитать [живую речь](../../../docs/standards/narration.md); `research` не включает речевую редактуру. Для run использовать pinned context и бюджет. Для узкой правки без run — предоставленные артефакты и применимые правила; runtime-команды и gates ниже относятся к run.

Различить вход по [workflow](../../../docs/workflow.md#готовый-текст-и-набросок). **Полный source, явно принятый для производства, не проходит этот цикл повторно:** координатор выполняет [импорт](../../../docs/workflow.md#принятый-источник-без-повторной-редакции) и продолжает production. Сама ссылка/наличие текста не являются approval. Для нового сюжета или порученной редактуры шаги 1–4 относятся к `research`, 5–7 — к `script`. Использовать принятый research из `inputs`, не выбирать другую тему без конкретного дефекта; worker не меняет approvals и не выдаёт чужое решение за собственный receipt.

Для `music_first` результат script — [typed edit plan](../../../docs/operations/task-contract.md#outputs): законченный замысел, точный вариант и ordered segments с вокальными словами либо пустой речью инструментального отрывка. Исследовать запись, права и развитие визуального ряда по рецепту; дикторский текст не добавлять. Независимый review оценивает новый план, применимый аудиовизуальный стык — финальный MP4.

1. Прочитать историю тем/углов, отказы владельца и наблюдения удержания. Сопоставимую гипотезу со ссылкой включить в research. Определить аудиторию и причину смотреть; источники и удобство производства сами не доказывают интерес.
2. Только при самостоятельном поиске выполнить [отбор до полного сценария](../../../docs/standards/editorial.md#отбор-до-полного-сценария): разные истории → проверенные заявки → сравнение с сильнейшей альтернативой. Проверить «почему остановится / останется / что получит» и возражение к каждому финалисту. При заданном замысле исследовать его; при порученной проверке готового narration — точный текст без новой темы. Если достойного кандидата нет, сохранить отказ; не создавать сценарий/PR/Issue ради расписания и не выдумывать `selected_topic`.
3. Сохранить в существующей research note выборку, сравнение, угол, аудиторию, источники/места, неопределённость, пересечения и сигналы спроса отдельно от гипотез. Самооценка не прогноз просмотров. Успешный `research` заканчивается проверенным выбором либо проверкой заданной истории, затем перейти к `script`; отказ не помечать успешным результатом.
4. Рано определить thumbnail promise/payoff: зритель, verified объект/факт, обещание, открытый вопрос, жанр/настроение, первое подтверждение и полный payoff. Выбрать причину интереса по [thumbnail standard](../../../docs/standards/thumbnails.md); при референсе связать переносимый приём со своим фактом и отметить узнаваемое действие/предмет интро для обложки. Заметка вне narration и strict packaging JSON; сохранить внутри research output через `supporting_inputs` либо явно передать packaging по artifact ID/path. Точный timecode уточнить после монтажа.
5. Проектировать сценарий по [editorial](../../../docs/standards/editorial.md): отдача → главный вопрос → начало/конец → причинная середина → устная редактура → первый слушатель. Начало сверить с [формами](references/hook-patterns.md); для Long исполнить [обещание в начале](../../../docs/standards/editorial.md#обещание-в-начале-long). При переработке сохранить исходник и сравнить сильные функции версий. Выполнить [речевую редактуру](../../../docs/standards/narration.md#порядок-правки): действия вместо пустых оценок, естественный ритм, никакой выдуманной конкретики, один смысл EN/RU. Сохранить evidence в существующих артефактах. Для повествовательного Short с `narrative_loop: required` обязательна естественная петля с ответом до повтора; проверить её после развития, кульминации и развязки. Long не обязан зацикливаться.
6. Проверить текст по [ограниченному review](../../../docs/standards/editorial.md#ограниченный-review): ожидание, развитие, payoff, факты, причинность, конец → начало и обещание обложки. Для Long reviewer сначала читает начало и самостоятельно формулирует ценность, затем сверяет её с историей. Не выдавать оценку длительности за измеренную озвучку. Использовать [свежего независимого reviewer](../../../docs/operations/task-contract.md#доступ-к-независимому-reviewer): точный текст без авторского вердикта, исходник после первого чтения. Попросить причину досмотра и место потери интереса; допустим отказ от темы. `revise` — самостоятельно исправить разрешённые дефекты и повторить проверку в пределах attempts/time budget, а не запросить согласие на каждую косметическую правку. При новой теме слабый замысел вернуть к отбору; существенный дефект принятого текста показать точно, не переписывать без поручения. Невыполненный review — UNVERIFIED. Подробные prompts и сюжетный PR не заменяют эту проверку.
7. Подготовить пакет helper-командой из [task contract](../../../docs/operations/task-contract.md#receipt). Reviewer сам сохраняет `ytv-script-review-v1`; ответ хранить дословно, не дописывать за него выводы. Для повествовательного Short передать весь текст два раза и точный стык; проверить, не звучит ли повтор новым вступлением или тематическим возвращением. `independent_review` и `narrative_loop` ссылаются на один ответ. Сохранить полный текст и output receipt. Показать пользователю текст целиком, для английского выпуска — также полный RU, ценность и существенные ограничения. Новый/изменённый текст остановить на script gate. Принятый неизменённый source маршрутизировать через координатора по workflow, не писать фиктивный review. Не отдавать меню тем вместо требуемого сценария.

Внутренние sources и служебную attribution не добавлять в narration; существенную неопределённость не скрывать. Принятый сценарий не переписывать под видом технического шага. При порученной правке сохранять version/hash и обновлять только зависимые результаты.
