# Найти историю и написать полный текст

До действий выполнить [обязательную процедуру](../ytv-start/references/task-execution.md); для run читать её закреплённый текст из task packet.

CLI и точные outputs/receipts: [task contract](../../../docs/operations/task-contract.md).

Для `research` и `script` прочитать профиль канала, [editorial](../../../docs/standards/editorial.md), [thumbnail promise](../../../docs/standards/thumbnails.md) и [формы начала](references/hook-patterns.md). На `script` дополнительно прочитать [живую речь](../../../docs/standards/narration.md); `research` не включает речевую редактуру. Для run использовать task context с закреплёнными ревизией и бюджетом. Для узкой правки без run использовать данные артефакты и применимые правила, сохраняя scope; команды и gates ниже — для run.

Различить поиск темы, заданный сюжет/набросок и точный production script по [workflow](../../../docs/workflow.md#готовый-текст-и-набросок). На `research` выполнять подходящий scope проверки и отбора в шагах 1–4; шаги 5–7 — для `script`. На `script` использовать принятый research из `inputs`; новый выбор темы — только при конкретном выявленном дефекте. Готовый текст проверять без самовольной переработки; принятие пользователем регистрирует host, не авторский receipt.

Для `music_first` script — [typed edit plan](../../../docs/operations/task-contract.md#outputs): законченный замысел монтажа, точный вариант и ordered segments с вокальными словами либо пустой речью инструментального отрывка. По рецепту канала исследовать запись, права и развитие визуального ряда; дикторский текст не добавлять. Независимый review оценивает план, применимый аудиовизуальный стык проверяется по финальному MP4.

1. Прочитать историю тем/углов, отказы владельца и наблюдения удержания. Включить сопоставимую гипотезу со ссылкой в research. Определить аудиторию и причину смотреть; источники и удобство производства не доказывают интерес.
2. Только при самостоятельном поиске темы выполнить [отбор до полного сценария](../../../docs/standards/editorial.md#отбор-до-полного-сценария): разные истории → короткий список проверенных заявок → сравнение с сильнейшей альтернативой. Для каждого финалиста проверить «почему остановится / останется / что получит» и возражение. Исследовать заданный замысел; при готовом narration проверять точный текст без отбора новой темы. Без достойного кандидата сохранить отказ в research notes; не создавать сценарий/PR/Issue ради расписания, не выдумывать `selected_topic`.
3. В существующей исследовательской записке сохранить фактическую выборку, сравнение, выбранный угол, аудиторию, источники/места, неопределённость, пересечения и сигналы спроса отдельно от гипотез. Не выдавать самооценку за прогноз просмотров. Успех `research` — проверенный выбор или проверка заданной истории; перейти к `script`. Отказ не считать успехом.
4. Рано определить thumbnail promise/payoff: зритель, verified объект/факт, обещание одним предложением, открытый вопрос, ожидаемый жанр/настроение, первое подтверждение в кадре/реплике и отдельный полный payoff. Выбрать конкретную причину интереса по [thumbnail standard](../../../docs/standards/thumbnails.md); при использовании референса связать его переносимый приём с фактом своего сюжета и отметить узнаваемый предмет/действие интро для будущей обложки. Заметка — вне narration и strict packaging JSON. Её можно сохранить внутри research output, доступного через `supporting_inputs`; отдельный файл передать packaging явно по artifact ID/path. Отметить сцену, timecode уточнить после монтажа.
5. При написании или разрешённой переработке пройти порядок из [editorial](../../../docs/standards/editorial.md): отдача → главный вопрос → начало/конец → причинная середина → устная редактура → первый слушатель. Прочитать [формы и условия отказа](references/hook-patterns.md). Для Long применить [обещание в начале](../../../docs/standards/editorial.md#обещание-в-начале-long): в первом фрагменте сформулировать конкретную ценность, связать главный вопрос с полной отдачей и сразу начать ответ; для монтажа без речи не выдумывать диктора. Применить драматургический каркас к формату канала; при переработке сохранить исходник и сравнить его сильные функции с новой версией. Перед первым слушателем выполнить [речевую редактуру](../../../docs/standards/narration.md#порядок-правки): действия вместо пустых оценок, естественный ритм, никакой выдуманной конкретики; сохранить смысл EN/RU. Сохранить evidence в существующих research/script артефактах. Для повествовательного Short с `narrative_loop: required` нужна естественная петля с ответом до повтора; проверять после развития, кульминации и развязки. Long не обязан зацикливаться.
6. Проверить текст по [ограниченному review](../../../docs/standards/editorial.md#ограниченный-review): ожидание от начала, его развитие, решающая реплика/сцена и отдача; отдельно факты/модель, подразумеваемую причинность и конец → начало. Проверить первое подтверждение обещания обложки, тон и прямой payoff. Для Long попросить reviewer прочитать только начало и самостоятельно назвать, что узнает зритель; сверить ожидание с полной историей и первым содержательным шагом. Не выдавать бумажную оценку длительности за измеренную озвучку. Использовать [свежего независимого reviewer](../../../docs/operations/task-contract.md#доступ-к-независимому-reviewer); передать текст без подсказки ожидаемой оценки, исходник — после первого чтения. Попросить причину досмотра и точное место потери интереса; reviewer может отвергнуть тему, а не только поправить фразы. Исправить дефекты в пределах scope и attempts/time budget. При поиске слабый замысел вернуть к отбору; дефект принятого текста показать конкретно, не подменяя другим сюжетом. Невыполненный review — UNVERIFIED. Не заменять проверку подробными scene prompts или сюжетным PR.
7. Подготовить пакет независимого чтения helper-командой из [task contract](../../../docs/operations/task-contract.md#receipt) и передать свежему reviewer без вердикта автора. Reviewer сам сохраняет `ytv-script-review-v1`; ответ сохранить дословно, без дописанных выводов. Для повествовательного Short пакет содержит полный текст дважды подряд и точный стык: reviewer проверяет, не звучит ли повтор как новое вступление или тематическое возвращение. `independent_review` и `narrative_loop` ссылаются на один ответ. Сохранить текст и output receipt. Показать пользователю полный текст, для англоязычного выпуска — полный русский перевод, краткую ценность и существенные ограничения. Новый или изменённый текст остановить на script gate. Для exact текста, уже переданного в производство, host регистрирует исходное решение без повторного вопроса; при blocker сохранить результат и указать blocker. Не подменять сценарий меню тем.

Не добавлять внутренние sources и служебные attribution в публичный текст; существенную неопределённость не скрывать. Явно принятый сценарий не переписывать под видом технического шага. При порученной правке сохранять точные version/hash и обновлять только зависимые результаты.
