# Найти историю и написать полный текст

CLI и точные outputs/receipts: [task contract](../../../docs/operations/task-contract.md).

Прочитать task context, профиль канала и [editorial](../../../docs/standards/editorial.md). Если запрос узкий, сохранить его scope. Работать с закреплённой ревизией и доступным бюджетом.

1. Проверить историю тем/углов и доступные материалы. Получить реальные источники и, если полезно и доступно, сигналы спроса. Данные провайдера не заменяют фактическую основу и зрительскую ценность.
2. Самостоятельно сравнить кандидатов/углы и выбрать тот, который даёт понятную ценность, развитие после хука и содержательный финал. Не ждать отдельного выбора темы, если пользователь просил сюжет. При слабой основе сменить ещё не принятую тему.
3. Сохранить исследовательскую записку: выбранный угол, аудитория, ценность, источники/места, существенная неопределённость, отличие от существующих выпусков. `research` заканчивается этими данными, затем сразу перейти к готовому `script` task.
4. Рано определить thumbnail promise/payoff: целевой зритель, verified объект/факт, обещание одним предложением, открытый вопрос, ожидаемый жанр/настроение, первое подтверждение в кадре/реплике и отдельный полный payoff. Применять рекомендации практика по [thumbnail standard](../../../docs/standards/thumbnails.md), сохраняя связь с реальным сюжетом. Это рабочая заметка вне narration, не поле packaging JSON, не новый обязательный output/check и не гарантированный downstream input; при packaging передать нужный artifact ID/path. Для сценария отметить сцену, точный timecode уточнить после монтажа.
5. Пройти порядок проектирования из [editorial](../../../docs/standards/editorial.md): отдача → главный вопрос → начало/конец → причинная середина → устная редактура → первый слушатель. Сохранить компактное evidence в существующих research/script артефактах. Для каждого Short обязательна естественная петля с ответом до повтора; написать точный стык и проверить холодный вход. Long не обязан зацикливаться.
6. Проверить точный текст: понятны ли первые секунды, причины событий и отдача; отдельно сверить факты/модель и конец → начало. Проверить первое подтверждение обещания обложки, ожидаемый тон и прямой payoff. Не объявлять бумажную оценку длительности измеренной озвучкой. Использовать свежего независимого reviewer, когда он доступен/требуется policy; передать текст без подсказки ожидаемой оценки. Исправить реальные дефекты в пределах attempts/time budget. Невыполненный review сохранить UNVERIFIED.
7. Сохранить полный текст и output receipt через task contract. Показать пользователю текст целиком, краткую формулировку ценности и только существенные ограничения. Остановиться на script gate. Не показывать одно меню тем вместо требуемого сценария.

Внутренние sources и служебные attribution не добавлять в публичный текст; существенную неопределённость не скрывать. Явно принятый сценарий не переписывать под видом технического шага. При порученной правке сохранять точные version/hash и обновлять только зависимые результаты.
