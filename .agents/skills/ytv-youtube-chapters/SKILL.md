# Главы YouTube

Вход: профиль канала/язык, принятый монтаж/revision/длительность и фактическая запись либо конкретный MP4/версия/SHA-256 при аудите готового файла; применимые video ID/метаданные, текст/SRT/alignment.

1. Установить идентичность материала: в [общем production flow](../ytv-video-production/SKILL.md) — по принятой edit-версии и карте речи; для существующего видео — по file/hash/upload receipt и параметрам. Сохранить доказательства/ограничения; неустановленная версия остаётся draft.
2. Разделить фильм на самостоятельные темы/этапы, не каждую склейку. Названия описывают следующий сегмент без неподтверждённых обещаний и поискового спама. Сценарий, SRT и старые главы — ориентиры, не источник точного времени.
3. Проверить речь и контекст до/после каждой границы на выбранном материале. Для нового фильма использовать фактический монтаж и проверенную карту записи до этапа 16. Для аудита MP4 доступны ASR его дорожки и кадры границ. Сохранить временные привязки, выводы и реально применённый метод.
4. Выбрать начало нового раздела, при необходимости передвинуть черновую отметку. Не присваивать старому draft новый статус без проверки. Указывать точность/неуверенность; целые секунды не означают покадровую точность. ASR может выдавать конец сегмента за пределами файла: не принимать его за длительность, сверять с измеренным MP4. После смены монтажа перепроверять главы.
5. Сверить [актуальную справку YouTube](https://support.google.com/youtube/answer/9884579?hl=en): начало 00:00, минимум три возрастающие отметки, каждая глава от 10 секунд, включая последнюю. Запустить `python3 scripts/validate_chapters.py CHAPTERS.txt --media FINAL.mp4` из каталога навыка либо по абсолютному пути скрипта. Валидатор проверяет только форму/интервалы; успешная команда не подтверждает смысл.
6. Вернуть полный блок и `media_identity, boundary_evidence, verification_method, coverage, version, status`. Статусы: draft, machine-checked, playback-checked; последний требует фактического воспроизведения и содержательной проверки, не просто открытого плеера. Не объявлять проверку глав полным AV QA.

Владелец описания объединяет блок со свежими повествованием, ссылками, оговорками и метками. Заменять только установленный прежний блок, при неоднозначности подготовить diff и выяснить границы. Повторный вызов не создаёт дублей. Запись/read-back — через действующий release/upload workflow по поручению; этот навык не меняет YouTube, не рендерит новый звук или видео. Наличие отметок в API не доказывает глав в плеере: проверить отдельно, учитывая функции канала.

Выход рядом с выпуском: точный блок, свидетельства/покрытие/метод/ограничения, результат валидатора и handoff описания. Автономное продолжение зависит от доступного материала и средств проверки.
