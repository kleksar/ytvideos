# Выпуск на YouTube — проектный адаптер

Обязательный вход: до процедуры прочитать [CHANNEL_BOOTSTRAP](../../../.agent/CHANNEL_BOOTSTRAP.md) и указанные там root/реестр/локальное состояние/правила канала. Для общепроектной задачи не выдумывать выпуск.

Входы: канал и ID, актуальный файл/его статус final или preview, готовые метаданные, обложка, SRT и запрошенный доступ/расписание. Проверить [реестр каналов](../../../automation/channels.json) и текущую запись выпуска.

По root §7 подготовить комплект к выпуску, но выполнять upload или публикацию только после прямого поручения пользователя; отдельное одобрение упаковки не запрашивать. По такому поручению довести выпуск до запрошенного доступа: полный файл, метаданные, обложка, плейлист, применимые дорожки/декларации и конечная заставка. Проверить обработку и сохранённый доступ, передать ссылку на проверку. Не менять доступ на Public и не назначать расписание без прямого решения пользователя. Принятый review export использовать без повторного export; обязательная приёмка файла описана ниже.

Для Paper/Nuviko сверить технический receipt точного media/hash/edit по [общему QA-профилю](../ytv-video-qa/references/export-review.md). Для `Private` разрешён [этап загрузки](../../../automation/youtube/README.md#готовность-нового-mp4-papernuviko) после полного декодирования и технической проверки, пока приёмка или отдельная дорожка готовятся. До выхода из `Private` сверить [приёмку точного MP4 и её охват](../ytv-video-qa/references/export-review.md#приёмка-финального-mp4) и применимые проверки. Для отдельного SRT сверить проверенный файл и статус ручной дорожки по процедуре ниже. Существенные дефекты, несовпадение hash и отсутствие требуемой технической проверки блокируют загрузку. Прямое поручение «залить/выпустить в открытый доступ» связывает разрешение и пользовательскую приёмку с точным файлом и упаковкой по root §7. Принятый файл загружается без повторного экспорта. Metadata-only действие сохраняет действующую media-приёмку.

Для загрузки, замены обложек, сохранения метаданных и работы с плейлистами применить существующий глобальный global `youtube-upload` skill (when available in the active Codex runtime): он владеет выбором API-first и границей перехода к Studio. Его полный чеклист не копировать сюда. Если он недоступен, сначала найти реальный навык, а не утверждать, что чеклист выполнен.

До открытия Studio прочитать [инструкцию API-адаптера](../../../automation/youtube/README.md): разделы «Рабочий вход в API», покрытие нужной операции и OAuth своего канала. Существующий Python uploader находится в `automation/youtube/`, окружение — `~/.local/share/story-youtube/venv`; ID и путь токена брать из [channels.json](../../../automation/channels.json). Особенность авторизации Paper Detour и точная команда `set-thumbnail` записаны в README адаптера. Для операции вне текущего CLI проверить доступный API-метод по глобальному навыку; не объявлять готовой несуществующую команду.

- До загрузки вызвать [playlists](../ytv-youtube-playlists/SKILL.md), проверить актуальный полный список плейлистов целевого канала и тематическую пригодность; для Paper прочитать [профиль](../ytv-youtube-playlists/references/paper-detour.md) и реестр. Подходящий существующий плейлист добавить в разрешённый план загрузки: после получения video ID выполнить добавление и проверить сохранённый состав. Если лучше новый, прямо предложить пользователю конкретное название и причину, не создавая без необходимого разрешения. Нерешённое предложение или недоступный список сами по себе не блокируют остальной разрешённый выпуск: зафиксировать состояние и продолжить. При возобновлении сверить video/playlist ID и membership перед записью, не дублировать неизвестный исход. Сохранять существующий порядок, privacy ролика и видимость плейлиста; не наследовать старое private из исторической квитанции.
- Исторические выпуски вести по [History pipeline](../../../channels/nuviko_history/docs/HISTORY_STORY_PIPELINE.md); Paper Shorts — по [стратегии](../../../channels/paper_detour/docs/SHORTS_RELEASE_STRATEGY.md). Ориентиры времени и частоты не разрешают автоматическую публикацию. Сверять дату, время и пояс на стороне YouTube; для принятого flow итог новых загрузок — Unlisted; начальное private допустимо только как промежуточное состояние до проверенного разрешённого доступа.
- Перед назначением/изменением времени либо немедленным открытым выходом любого канала выполнить [динамическое планирование](references/dynamic-scheduling.md). Применить редакционную политику именно целевого канала; его календарь и очередь отделять по точному channel ID. Подготовка и порученная загрузка Unlisted могут предшествовать этой контрольной точке. Для metadata-only действия без изменения выхода перепланирование не требуется.
- Для всех каналов применять [глобальное правило публичных материалов](../../../AGENTS.md#11-подача-всех-сюжетов): исследовательские ссылки, источники и библиографии по умолчанию остаются внутри проекта; обязательные кредиты/раскрытия и явно запрошенные функциональные ссылки обрабатываются отдельно. Настройку платформенной декларации изменённого/синтетического контента определять по ролику и актуальным правилам YouTube.
- Для постеров и самостоятельных/связанных с фильмом каруселей **Paper Detour** прочитать [порядок подготовки](../../../channels/paper_detour/docs/YOUTUBE_POSTS_PLAYBOOK.md). Для других каналов использовать их собственные принятые правила постов, не наследовать Paper стиль или комплект производных. Навык не даёт разрешения отправить пост; выполнять только явно порученное внешнее действие. Упаковку Paper Detour разрабатывать через [titles](../ytv-youtube-video-titles/SKILL.md), [thumbnails](../ytv-youtube-thumbnails/SKILL.md) и [descriptions](../ytv-youtube-descriptions/SKILL.md); для остальных каналов — через `$ytv-video-packaging`. Не сочинять неподтверждённые обещания в форме загрузки.
- При неизвестном исходе сначала перечитать API и журнал; для UI-only операции — сохранённое состояние Studio. При замене старой публикации сначала проверить новую, затем только явно указанную операцию над старой с учётом действующих требований подтверждения.

Перед новым выпуском и порученным аудитом заполнения применить [ytv-youtube-metadata](../ytv-youtube-metadata/SKILL.md) для полного пакета и проверки применимых полей.

Для всех каналов проверять принятый результат [hashtags skill](../ytv-youtube-hashtags/SKILL.md) с профилем канала, статусом покрытия и полным блоком в итоговом описании. Для длинного фильма любого канала получить принятый [A/B-пакет](../ytv-youtube-ab-testing/SKILL.md#стандартный-пакет-длинного-фильма) из трёх названий и трёх проверенных сгенерированных обложек с обязательным текстом; для Shorts — обычную упаковку; зафиксировать фактическую доступность запуска и не считать неподтверждённый запуск выполненным. Сверять hashtag tail с итоговым названием; поднабор названия не заменяет блок описания. Набор меток не заменяет полноценный текст описания. При обновлении видео сверять свежие поля с подготовленной версией; объединять изменения по конкретному video ID, сохраняя принятые главы, хэштеги и обязательные disclosures. Не возвращать исследовательские ссылки/источники в описание. Механика записи и проверка сохранённых полей остаются у глобального uploader.

Для каждого нового длинного фильма и Short выбрать явную [категорию выпуска](references/video-categories.md) и проверить её после загрузки. Для порученного аудита существующих видео использовать тот же стандарт и его отдельную процедуру сверки каталога. Для **Paper Detour** также применить [канальные настройки выпуска](references/paper-detour.md).

Для применимого **нового длинного Nuviko History** получить план и пройти [канальный стандарт конечной заставки](../ytv-video-production/references/nuviko-end-screens.md).

Для применимого **нового длинного Paper** получить `Packaging/EndScreen/END_SCREEN_PLAN_v*.md` и пройти [канальный стандарт конечной заставки](../ytv-video-production/references/paper-end-screens.md#нативная-заставка-в-youtube-studio) в порученном релизе. Он задаёт состав, UI-only исполнение при подтверждённом API gap и отдельный saved read-back; отсутствие доступа — явный блокер, не PASS. Shorts и оставленные пользователем старые/текущие фильмы исключены. Одной приёмки фона в MP4 недостаточно для готовности нативной заставки; сохранение элементов не разрешает публикацию.

Выход: журнал с video/playlist/post IDs, ссылками, сохранёнными метаданными и фактическим доступом, обработкой/SRT, применимым результатом конечной заставки и оставшимися проверками. Недоступный шаг или незавершённая проверка не считаются успехом.

Для каждого применимого нового выпуска со звучащей речью, включая Shorts, получить у [ytv-srt](../ytv-srt/SKILL.md) проверенный SRT, hash, язык фактического принятого аудио, final media/edit и раздельные свидетельства. При разрешённой загрузке выпуска добавить именно этот файл как отдельную ручную дорожку после получения video ID; вшитые и автоматические ASR-субтитры её не заменяют. Проверить сохранённый video ID, ID дорожки, язык, тип и статус обработки; при возможности сопоставить содержимое и воспроизведение с принятым SRT, отдельно указать непроверенное. Сохранить квитанцию и результат в состоянии выпуска. При отсутствии прав, неподдерживаемом языке или состоянии видео, ошибке обработки либо неподтверждённом результате зафиксировать блокер и сообщить пользователю; не объявлять дорожку готовой и не переводить выпуск в Public/расписание до разрешения проблемы. При неопределённом результате сначала проверить YouTube и квитанцию, не загружать повторно вслепую. Текущий `upload_caption_language.py` ограничен RU/EN и private-видео с квитанцией; использовать подходящий разрешённый инструмент или явно сообщить блокер, не считать его универсальным. Для отсутствующей речи указать N_A и основание. Переводы автоматически не создавать; опубликованные ранее видео не менять без отдельного поручения. Локальный SRT не подтверждает загрузку; создание SRT само по себе не даёт разрешения на отдельное внешнее действие вне разрешённого выпуска.

При эксперименте получить контракт/актуальное состояние у [A/B owner](../ytv-youtube-ab-testing/SKILL.md), для Paper — с [профилем](../ytv-youtube-ab-testing/references/paper-detour.md). Самостоятельно не выбирать победителя и не останавливать тест побочной title/thumbnail-записью. Native A/B использует Studio при зафиксированном отсутствии публичного API-метода; это не fallback при ошибке OAuth/квоты. Журнал порученного изменения передать [analytics](../ytv-youtube-analytics/SKILL.md) для baseline и сопоставимых окон, без запуска незаказанного мониторинга.

Если передаются главы, получить принятый блок и метод проверки у [chapters](../ytv-youtube-chapters/SKILL.md). Наличие строк в сохранённом описании и отображение глав плеером — разные проверки. Не повышать статус проверки материала по одному успешному videos.update.

После проверенной загрузки передать точные file/hash/video ID/channel ID/URL и фактические processing/access в [media-lifecycle](../ytv-media-lifecycle/SKILL.md). При немедленном Public длинного фильма запустить согласованный A/B и проверить статус; Shorts без A/B. После проверки результата загрузки и обработки автоматически завершить очистку по lifecycle в том же проходе до итогового отчёта. Получить cleanup receipt и фактический storage_state; при незавершённой очистке явно передать оставшиеся пути и blocker. При расписании проверить дату, время, часовой пояс и обработку, сообщить, что A/B не запущен и пользователь займётся им отдельно, и перед очисткой сохранить или передать все согласованные варианты названий и обложек для будущего теста. При Unlisted/Private сохранить выбранную упаковку и не запускать A/B. Применять требования среды к подтверждению безвозвратного удаления. Отдельная оптимизация завершённого Public/Unlisted использует свежий read-back, даже если доступ ранее менял сам пользователь; процедура архивирования принадлежит lifecycle.
