# Динамическое планирование публикаций

Общая процедура [ytv-youtube-release](../SKILL.md) для выбранного канала. Редакционная политика, язык, форматы и особенности поддержки остаются у канального владельца; механика API-first и внешней записи — у глобального youtube-upload. Эта процедура не задаёт общую для каналов частоту или обязательный комплект производных.

## Вход и момент проверки

Установить точный channel ID по [реестру каналов](../../../../automation/channels.json), применимые канальные правила из bootstrap, готовые проверенные версии материалов и порученную область: локальный план, назначение времени, изменение расписания либо немедленный выход. Соблюдать действующие ограничения [root AGENTS](../../../../AGENTS.md); общий навык не отменяет их и не расширяет поручение.

Проверять календарь после готовности материала и перед сохранением даты/времени либо немедленным открытым выходом. Подготовку и порученную загрузку Private можно выполнить раньше. Если план выбран до длительной загрузки, проверить актуальность состояния перед назначением выхода. Metadata-only правка без изменения выхода не запускает перепланирование.

## Процедура

1. **Получить состояние нужного канала.** Прочитать фактические недавние публикации и сохранённое будущее расписание: IDs, типы материалов, даты/время/пояс, доступ. Охватить применимые длинные фильмы, Shorts и посты/карусели; доступность каждого типа проверить отдельно. Video-only список не подтверждает состояние постов. Общего числа опубликованных фильмов недостаточно: важны даты и уже занятые будущие места. Сверить готовые проверенные материалы без назначенного выхода и ещё не исполненные локальные планы.
2. **Выбрать даты по канальной политике и поручению.** Выбрать место нового материала либо распределить готовую партию по подходящему горизонту. Учитывать плотность публикаций, соседние темы, поддержку уже вышедших/назначенных фильмов, доступность ссылок и готовность материалов. Готовность партии не требует её выхода в тот же день. Не назначать универсальные интервалы или дневную норму; не переносить уже назначенные материалы за пределами действующего поручения. Для нескольких каналов вести отдельные календари и очереди по channel ID: общий обзор не объединяет их слоты, разрешения или редакционные правила.
3. **Сохранить план и основание.** Рядом с выпуском или порученной партией записать channel ID, время/источник и охват проверки состояния, точные файлы/версии, целевые video/post IDs при наличии, даты/время/пояс, зависимости ссылок и основание внешнего действия. Различать локальный план, сохранённое расписание и проверенную публикацию. Существенные неизвестные отметить явно; не создавать фиктивные IDs.
4. **Исполнить и проверить порученное.** Передать записи глобальному uploader по доступной механике; для операций без API-покрытия использовать разрешённый UI-путь владельца. Проверить фактические channel/IDs/даты/пояс/доступ после сохранения и вернуть квитанцию. В партии учитывать каждый уже сохранённый слот перед назначением следующего. При неизвестном исходе сначала прочитать фактическое состояние, затем решать вопрос повтора; локальная запись даты не доказывает внешнего результата.

## Неполное состояние

Если часть календаря недоступна, записать точный пробел. Продолжать независимую подготовку и порученную загрузку Private; не представлять непроверенную дату как свободную и неполный календарь как полностью сверенный. Не обходить ограничения авторизации или неизвестный исход сменой инструмента.

Процедура сама по себе не создаёт фоновый мониторинг, не разрешает публикацию дополнительных материалов и не требует повторного разрешения для уже порученного действия в том же scope.
