## Что хранить

Git подходит для правил и skills проекта, сценариев, раскадровок, исследований и ссылок, заметок о правах, манифестов, небольших конфигураций и исходного кода автоматизации.

Локально остаются медиакэш, виртуальные окружения, загруженные модели, монтажные сессии, промежуточные рендеры и секреты. `.gitignore` исключает закодированные аудио- и видеофайлы, потому что общее место их хранения ещё не выбрано. Игнорирование не удаляет эти файлы, но чистый Git-клон сам по себе не воспроизведёт готовый фильм. До общего рендера выберите Git LFS либо согласованное хранилище медиа с манифестом и контрольными суммами. Не добавляйте медиа через `git add -f`, пока команда не выбрала этот способ.

Не коммитьте ключи, токены, `.env`, OAuth credentials, персональные chat exports, файлы сессий монтажа или доступы к YouTube/TikTok. Публикационные ID, URL и статусы храните у выпуска только с учётом доступа к репозиторию; пароли, API keys и refresh tokens остаются в локальном хранилище секретов.

## Рабочий цикл

1. Обновите основную ветку и создайте узкую рабочую ветку: `work/<channel>/<episode>-<scope>`. Для общей документации используйте `work/docs/<scope>`.
2. Перед правкой проверьте `git status --short`; чужие локальные изменения оставьте нетронутыми.
3. Добавляйте конкретные пути, а не весь проект: `git add path/to/file`. Проверьте `git diff --cached --name-only` и `git diff --cached --stat`, затем прочитайте `git diff --cached`.
4. Делайте небольшие коммиты с понятным действием: `story: clarify hook`, `paper: update storyboard`, `docs: explain release handoff`, `automation: pin ffmpeg inputs`.
5. Отправьте только свою ветку на согласованный remote и откройте merge request в `main`. В описании укажите канал/выпуск, изменённые входы и требуемую проверку. Дождитесь ревью.
6. После слияния обновите локальную `main` и удалите завершённую ветку.

Репозиторий `git@github.com:kleksar/ytvideos.git` приватный; опубликованная ветка `main` служит базой для совместной работы. Владелец должен отдельно пригласить коллегу. После настройки доступа защитите `main` и ведите изменения в коротких topic branches с pull request. До выбора общего хранилища медиа не включайте медиа в Git.

## Переносимость клона

Канонические инструкции должны использовать относительные ссылки от репозитория. Исторические аудиты и заметки могут сохранять абсолютные пути как свидетельства исходной среды; не используйте их как рабочие команды. Навык YouTube upload предоставляется внешним runtime Codex и не поставляется в этом репозитории; проектный адаптер описан в `automation/youtube/README.md`.

Репозиторий содержит source-only набор инструкций, процедур, кода и стабильных правил каналов. Материалы выпусков, исходники/экспорты, кэши и локальные credentials передаются отдельно, если они нужны для конкретной задачи.
