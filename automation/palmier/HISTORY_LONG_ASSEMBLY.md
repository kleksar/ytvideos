# Сборка исторического фильма в Palmier

`assemble_history_long.py` — инструмент для **длинного фильма**, проверяющий отдельный манифест выпуска. По умолчанию он читает только локальные файлы и не подключается к Palmier. Сборка и рендер не выполнялись при подготовке этого инструмента. Стандарт: горизонтальный таймлайн 1920×1080/30, уникальный кадр на сцену, английский WAV уже ускорен ровно на 1,05×, отдельный SRT. Автоматическая валидация не заменяет фактическую проверку изображений, содержания, качества озвучки и синхронизации.

Манифест располагается в `<выпуск>/Edit/Long/manifest.json`, материалы — внутри `<выпуск>/Source/Long/`. Все пути к материалам должны быть абсолютными; `frames` — `ceil(фактическая длительность WAV в секундах × 30)`. Интервалы сцен указываются в кадрах как `[start, end)`; они должны покрыть весь фильм без пропусков и пересечений. Каждый кадр должен быть уникальным файлом и содержимым, с отдельным именем внутри медиатеки Palmier. Субтитры в формате SRT не могут выходить за длительность WAV или пересекаться друг с другом. Вот схема, а не готовый к запуску пример (имена и хеши условные):

```json
{
  "status": "ready",
  "timeline": "016_en_marseille_long",
  "fps": 30,
  "frames": 18000,
  "voice_speed_applied": 1.05,
  "voice": "/ABS/PATH/016_marseille/Source/Long/Voice/voice_105.wav",
  "srt": "/ABS/PATH/016_marseille/Source/Long/Voice/voice_105.en.srt",
  "sha256": {"voice": "WAV_SHA256", "srt": "SRT_SHA256"},
  "missing_assets": [],
  "scenes": [
    {"start": 0, "end": 9000, "cue": "Narrative cue", "path": "/ABS/PATH/016_marseille/Source/Long/Images/001.png", "sha256": "IMAGE_1_SHA256"},
    {"start": 9000, "end": 18000, "cue": "Next narrative cue", "path": "/ABS/PATH/016_marseille/Source/Long/Images/002.png", "sha256": "IMAGE_2_SHA256"}
  ]
}
```

Кадры в схеме намеренно показаны для объяснения интервалов; это **не** рекомендуемая раскадровка готового фильма. В реальной раскадровке подбирать смену изображений по смыслу, ориентируясь на 4–6 секунд, а не растягивать два изображения на десять минут. `status: ready` ставить только после подготовки, проверки содержания и записи точных хешей всех материалов.

Сначала выполнить проверку без Palmier:

```sh
python3 automation/palmier/assemble_history_long.py \
  archive/legacy_stories/videos/016_marseille/Edit/Long/manifest.json \
  --series archive/legacy_stories/videos/016_marseille
```

Для реального монтажа после проверки материалов и состояния Palmier добавить `--execute --project /ABS/PATH/PROJECT.palmier`. Скрипт требует, чтобы указанный проект был одновременно активным и видимым, активный таймлайн — 1920×1080/30, свободно не менее 8 ГиБ и не было выполняющихся экспортов. Этот порог относится только к сборке, **не гарантирует** достаточный запас для последующего рендера и ремультиплексирования. Новый таймлайн создаётся в указанном активном проекте; другие проекты и таймлайны скрипт сам не переключает. Возможная параллельная работа в том же Palmier требует отдельной предварительной проверки: отсутствие экспорта не доказывает, что другой монтажёр не редактирует проект.

Все запросы на изменение предваряются записью `pending` в `<выпуск>/Edit/Long/palmier_receipt.json`, подтверждённые шаги добавляются в `steps`. При неожиданном ответе, обрыве, созданном таймлайне или существующем журнале повторный запуск блокируется: сначала вручную изучить журнал и фактическое состояние проекта. Не удалять журнал для слепого повтора. Скрипт **не рендерит** фильм и **не загружает** его; валидация манифеста также не подтверждает эти этапы.

Офлайн-тесты, включая запуск CLI на реальных WAV/PNG и имитацию действий Palmier без подключения:

```sh
python3 -m unittest discover -s automation/palmier -p 'test_assemble_history_long.py' -v
```

## Точечная ревизия Marseille 016

Скрипт `revise_history_long.py` предназначен для замены только сцен 030 и 031
в исходной собранной версии Marseille. Он требует проверенные 16:9
`Source/Long/Images/030_corrected.png` и `031_corrected.png` и первоначальные
manifest и assembly receipt без изменений. В Palmier должен быть открыт тот же
проект и таймлайн; экспорт должен закончиться. Проверяются все клипы и все
ключи до изменений, затем новый клип размещается на том же треке и интервале,
и его scale keyframes восстанавливаются. Каждая из шести мутаций имеет свой
отдельный журнал с состоянием до запроса и подтверждением после. Повторный
запуск при существующем журнале запрещён; при сбое сверить журнал с Palmier
вручную, не удаляя доказательства. После ревизии сохранён отдельный снимок
таймлайна, исходные manifest и receipt не переписываются.

```sh
python3 automation/palmier/revise_history_long.py --series channels/nuviko_history/videos/016_marseille_1720
python3 automation/palmier/revise_history_long.py --series channels/nuviko_history/videos/016_marseille_1720 --execute
```

После проверки кадров и разрешения на рендер можно подготовить и запустить
отдельный экспорт v2. Проверяются исходные файлы, оба журнала ревизии, снимок
изменённого таймлайна, активный проект, отсутствие экспорта и свободное место.
Выход `Deliverables/016_en_marseille_long_palmier_v2.mp4` и отдельный журнал
не должны существовать. Запрос экспорта выполняется ровно один раз с
`overwrite=false`. При неопределённом результате сверить очередь Palmier и
выходной файл вручную, не создавать новый журнал вслепую. Оригинальный экспорт
остается нетронутым. Готовый v2 необходимо отдельно проверить и прослушать.

```sh
python3 automation/palmier/export_history_revised.py --series channels/nuviko_history/videos/016_marseille_1720
python3 automation/palmier/export_history_revised.py --series channels/nuviko_history/videos/016_marseille_1720 --execute
```
