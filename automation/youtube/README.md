# Загрузка видео в YouTube

Модуль подготовлен для будущего подключения к общей автоматизации. Он **не запускается автоматически**, сам не публикует видео и без отдельной команды ничего не загружает. Каждая версия загружается только как `private`; публикации и расписания в нём нет.

## Готовность нового MP4 Paper/Nuviko

До первого API-запроса, включая resume, `upload.py upload` проверяет [delivery receipt](../ffmpeg_montage/README.md#приёмка-и-загрузка). По умолчанию путь `VIDEO.mp4.delivery.json`, иной путь задаёт `--delivery-receipt`. `--stage-private` разрешает загрузку при подтверждённой технической проверке и полном декодировании точного MP4, пока просмотр или SRT готовятся. Хранить локальный MP4 и квитанции до выхода из Private. При продолжении той же загрузки указывать тот же режим и путь к квитанции. При переходе из Private использовать исходную квитанцию загрузки. Для staging передать проверенный `--srt`, `--language` и `--caption-receipt` в `publish_public.py`, `schedule.py set` или `prepare_unlisted.py privacy`; они сверяют принятие точного файла, SRT и статус ручной дорожки. Точный разрешённый доступ определяется [правилами выпуска](../../.agents/skills/ytv-youtube-release/SKILL.md).

## Рабочий вход в API

Порядок выбора API и допустимого перехода к Studio задаёт внешний глобальный навык `youtube-upload` (если он доступен в текущем Codex runtime); проектный вход — [ytv-youtube-release](../../.agents/skills/ytv-youtube-release/SKILL.md). Эта справка описывает фактические команды, авторизацию и ограничения адаптера.

Готовое окружение: `~/.local/share/story-youtube/venv`. Перед новой операцией сверить channel ID из [channels.json](../channels.json) и точный файл/ID из отдельно согласованного episode bundle. Локальную авторизацию настроить отдельно; credential files и token paths не входят в этот репозиторий. Затем проверить текущий канал через API. Реестр и прежняя квитанция не доказывают сегодняшнюю авторизацию; содержимое токена не выводить. Проверить доступные команды можно без входа в браузер:

```sh
~/.local/share/story-youtube/venv/bin/python automation/youtube/upload.py --help
```

| Операция | Текущее покрытие адаптера | Авторизация |
|---|---|---|
| Новый MP4 или QuickTime MOV, только private | `upload.py upload`, отдельный state версии; MIME определяется по расширению (`video/mp4` / `video/quicktime`) | `youtube.upload` + `youtube.readonly` для preflight |
| Канал, принадлежность видео, доступ и обработка | `upload.py status` | В текущем CLI используется та же пара scopes |
| Стандартный thumbnail asset существующего ролика | `upload.py set-thumbnail`; API acceptance/read-back не доказывают выбор отдельного Shorts poster — см. [границу поддержки](#отдельная-custom-обложка-shorts) | `youtube.upload` + `youtube.readonly` |
| Название/описание/tags и другие поля существующего видео | Универсальной команды в `upload.py` нет; метод API — `videos.update` | Нужен токен управления: `youtube.force-ssl` или `youtube` (также API допускает `youtubepartner`); upload + readonly недостаточно |
| Плейлисты | `add_to_playlist.py` принимает только private-видео; `create_unlisted_playlist.py` создаёт unlisted-плейлист | Отдельный токен `youtube.force-ssl`; ограничения команд описаны ниже |
| Native A/B названий/обложек | Перед работой проверить актуальное покрытие; если API не поддерживает нужное действие, использовать документированный интерфейс Studio только по поручению. Контракт и состояния у [A/B skill](../../.agents/skills/ytv-youtube-ab-testing/SKILL.md) | Проверить канал и поручение; UI не является обходом OAuth/квоты |
| Конечные заставки / End screens | Адаптер не предоставляет команду управления. Перед работой проверить текущую официальную документацию и интерфейс Studio; не считать локальный пример или прошлый аудит доказательством текущего покрытия | Проверить канал/поручение; saved Studio read-back, без изменения доступа. Для новых длинных Paper — [канальный план](../../.agents/skills/ytv-video-production/references/paper-end-screens.md) |
| Аналитика | Data API даёт накопленные counters; датированные отчёты/retention — отдельный Analytics API либо Studio read-only, по [analytics skill](../../.agents/skills/ytv-youtube-analytics/SKILL.md) | Проверить scopes конкретного отчёта; не расширять scopes автоматически |

Редакционная архитектура и аудит подборок — [ytv-youtube-playlists](../../.agents/skills/ytv-youtube-playlists/SKILL.md). Позиции элементов поддерживает `playlistItems.insert/update`, но default sorting mode отсутствует в схеме `playlists`: нужный Manual проверить/сохранить в Studio по глобальному uploader, затем вернуться в API. Ошибка `manualSortRequired` не оправдывает слепой повтор вставки. Перед каждой записью перечитать текущее состояние и проверить режим сортировки в Studio; не полагаться на старые снимки.

В этом же каталоге есть специализированные API-инструменты: `schedule.py`
(`plan` / `read` / `set`), `prepare_unlisted.py`, `publish_public.py` и
`upload_caption_language.py` (`prepare` / `upload`). Это отдельные процедуры
со своими обязательными receipts, состоянием и ограничениями; перед
использованием прочитать их `--help` и проверки входов. Наличие этих файлов
не означает, что они запускаются из `upload.py` или подходят любому ролику.

Для существующих метаданных использовать процедуру бережного обновления из глобального навыка и текущую схему [videos.update](https://developers.google.com/youtube/data/reference/rest/v3/videos/update). Не подменять такую операцию новой загрузкой MP4 и не переносить команды конкретного выпуска с зашитыми IDs/датами на другое видео. Отсутствующий CLI-подпункт не означает отсутствия API-метода. Права и семантика `videos.update` сверены с официальной документацией 2026-11-01.


Снимки подключений, OAuth-квитанции, video IDs и состояние прошлых публикаций хранятся отдельно с материалами соответствующего канала. Этот source-only clone не содержит эти данные. Перед любой операцией заново проверить точный channel ID, аккаунт, scope, target video и состояние через API/Studio. Токены и client secrets не копировать в Git.

## Подготовка Google Cloud

Этот раздел нужен при отсутствии подходящего подключения или подтверждённой проблеме авторизации. Существующий клиент, окружение и действующий токен переиспользуются; повторная настройка Google Cloud перед каждой заменой обложки не требуется.

1. Выбрать существующий подходящий проект в [Google Cloud](https://console.cloud.google.com/) или создать новый, только если нужного подключения ещё нет; включить YouTube Data API v3 и настроить экран согласия OAuth. Если приложение External/Testing, аккаунт канала должен быть в test users. Для YouTube scopes refresh token в этом режиме истекает через 7 дней; после истечения потребуется повторная авторизация. Это ограничение режима приложения, а не причина выполнять обновления в Studio. [Документация Google](https://developers.google.com/identity/protocols/oauth2#expiration).
2. Создать OAuth client типа **Desktop app** и сохранить JSON с его настройками за пределами этого проекта с правами только для владельца. API key или service account не заменяют OAuth владельца YouTube-канала.
3. Узнать точный **channel ID**, начинающийся с `UC`, для каждого канала через настройки своего канала в YouTube. Не использовать адрес `@handle` или имя канала вместо ID. Проверить назначение каждого ID, особенно при создании новых каналов.
4. Подготовить Python 3 и зависимости в отдельном окружении:

```sh
python3 -m venv ~/.local/share/story-youtube/venv
~/.local/share/story-youtube/venv/bin/python -m pip install -r automation/youtube/requirements.txt
mkdir -p ~/.local/share/story-youtube
chmod 700 ~/.local/share/story-youtube
```

5. Выполнить авторизацию **каждого канала отдельно**. В браузере выбрать соответствующий канал при запросе доступа. Существующие файлы токенов скрипт не перезапишет. OAuth запрашивает права загрузки и чтения канала: второе необходимо для проверки ID.

```sh
~/.local/share/story-youtube/venv/bin/python automation/youtube/upload.py authorize --client-secrets "$HOME/.local/share/story-youtube/client.json" --token "$HOME/.local/share/story-youtube/ru-token.json"
~/.local/share/story-youtube/venv/bin/python automation/youtube/upload.py authorize --client-secrets "$HOME/.local/share/story-youtube/client.json" --token "$HOME/.local/share/story-youtube/en-token.json"
```

JSON клиента, токены и файлы состояния нельзя отправлять в чат или включать в репозиторий: токен даёт доступ к аккаунту, а активное состояние содержит адрес загрузки. Скрипт создаёт такие файлы с правами `0600`; используйте защищённую папку и не открывайте её другим пользователям. При восстановлении авторизации сохранять новый токен в отдельный защищённый файл, проверить его канал и scopes, затем обновить нужный путь реестра. Не перезаписывать и не отзывать доступ других каналов по похожему имени файла. Удаление старых credentials и отзыв доступа выполняются отдельно с учётом их фактического назначения и действующего поручения.

Для повторной авторизации NuvikoHistory использовать клиент нового проекта
`yt-videos-client.json`, отдельный `history-token.json` и выбрать именно
канал NuvikoHistory в окне Google. Существующий файл токена скрипт не
перезаписывает. Подтверждать нужный канал через API перед загрузкой.

## Обложки через YouTube Data API

Для Paper Detour используется точный channel ID из Studio
`UCMVfdfaNxV3ZkI3_J3Eejzw`. Его OAuth-токен хранить отдельно от остальных
каналов: `~/.local/share/story-youtube/paper-detour/token.json`. Существующий
файл `paper-detour-token.json` не совпадает с ID Paper Detour и не используется
для этого канала. Правильный `paper-detour/token.json` создан и проверен
1 ноября 2026; при следующей работе сначала использовать его с актуальным
preflight. Следующая команда предназначена для первоначального подключения
или восстановления, когда подходящего действующего токена нет. Скрипт
откажется перезаписывать существующий файл; для восстановления выбрать новый
защищённый путь и после проверки обновить реестр:

```sh
~/.local/share/story-youtube/venv/bin/python automation/youtube/upload.py authorize \
  --client-secrets "$HOME/.local/share/story-youtube/yt-videos-client.json" \
  --token "$HOME/.local/share/story-youtube/paper-detour/token.json"
```

Поток OAuth запрашивает `youtube.upload` и `youtube.readonly`: первое нужно для
`thumbnails.set`, второе — для проверки владельца видео и результата. Выбрать
Google-аккаунт с доступом к Paper Detour; перед любой записью загрузчик требует,
чтобы `channels.list(mine=true)` вернул ровно указанный ID канала, а сам ролик
принадлежал этому каналу. Токен записывается только в защищённый локальный
каталог, не в проект и не в чат.

OAuth-приложение проекта отображается как `Nuviko` и находится в режиме
тестирования. 1 ноября 2026 Google сначала вернул `403 access_denied`, потому
что аккаунта Paper Detour не было в списке тестировщиков. Его добавили в этот
список в Google Cloud Console проекта `YT Videos`; теперь в нём есть аккаунт
Paper Detour и владелец OAuth-клиента. После отдельного согласия на оба
запрошенных scope создан токен `paper-detour/token.json` с правами `0600`.
Read-only проверка `r71aCn4p88A` подтвердила, что `channels.list(mine=true)`
возвращает `UCMVfdfaNxV3ZkI3_J3Eejzw`, а Shorts принадлежит этому каналу.
Не обходить будущую блокировку выбором другого аккаунта; сначала сверить
список тестировщиков, OAuth-клиент и принадлежность канала. Локальный OAuth
открывает системный браузер по умолчанию: в этой сессии это был Comet.
Отсутствие окна в Chrome не означает, что поток не запущен. Этот вход и
согласие Google — вспомогательный этап, сами обложки отправляет API.

Пример read-only preflight перед записью (video ID заменить на целевой):

```sh
~/.local/share/story-youtube/venv/bin/python automation/youtube/upload.py status \
  --token "$HOME/.local/share/story-youtube/paper-detour/token.json" \
  --channel-id UCMVfdfaNxV3ZkI3_J3Eejzw \
  --video-id=r71aCn4p88A
```

Установить одну обложку можно только отдельной явной командой:

```sh
~/.local/share/story-youtube/venv/bin/python automation/youtube/upload.py set-thumbnail \
  --token "$HOME/.local/share/story-youtube/paper-detour/token.json" \
  --channel-id UCMVfdfaNxV3ZkI3_J3Eejzw \
  --video-id=VIDEO_ID \
  --image /absolute/path/to/approved-thumbnail.png
```

Использовать форму `--video-id=...`, в том числе для ID, начинающегося с `-`
(например, `--video-id=-KW8jgSoEz0`); иначе argparse может принять его за опцию.

Команда принимает PNG/JPEG до 50 МБ, проверяет канал и принадлежность ролика,
вызывает [thumbnails.set](https://developers.google.com/youtube/data/reference/rest/v3/thumbnails/set), затем читает текущий thumbnail через `videos.list`.
Поле `api_set_accepted` подтверждает ответ записи; `readback: matched`
означает пересечение URL обложек в ответах записи и последующего чтения.
Это не сравнение пикселей и не доказательство читаемости текста. Для приёмки
отображения обновить фактическую карточку канала/предпросмотр и проверить
картинку по [packaging skill](../../.agents/skills/ytv-video-packaging/SKILL.md).
Старая картинка в кеше не требует повторной записи. В этом чате все шесть
Paper Shorts приняты API; результаты находятся в журналах соответствующих
выпусков. Это не обещание одинаковой доступности функции для любого аккаунта.

### Отдельная custom-обложка Shorts

Не считать подтверждение `thumbnails.set` доказательством выбора картинки на всех Shorts-поверхностях. Отдельная Shorts thumbnail selection может зависеть от Studio и текущих возможностей API; проверить официальную справку и нужную поверхность на конкретном канале. Не повторять API mutation из-за одного старого кешированного превью; сначала проверить фактический asset и целевую Shorts-поверхность.

### Диагностика авторизации и результата

| Наблюдение | Что проверить перед следующим действием |
|---|---|
| OAuth `403 access_denied`, приложение Testing | Правильный Cloud project/client, аккаунт канала и его наличие в test users. Обычный повторный вход не исправляет отсутствующего тестировщика |
| `invalid_grant` при refresh | Отзыв/истечение refresh token, в том числе семидневный срок External/Testing; восстановить авторизацию того же канала, сохранив нужные scopes |
| API 403 | Реальный канал и владелец видео, granted scopes и доступ к custom thumbnails; по одному HTTP-коду нельзя заключить, что Shorts не поддерживаются |
| API 429 `uploadRateLimitExceeded` или установленный лимит | Следовать ограничению API/канала; смена браузера не является исправлением |
| `readback: not_matched` / `unavailable`, потерян ответ записи | Сначала перечитать текущий ресурс и журнал; исход записи не подтверждён полностью |

Текущий `set-thumbnail` сообщает HTTP-код, но не выводит подробный Google
reason; не выдумывать его по коду. Если причины недостаточно, выполнить
безопасную диагностику без повторной mutation и без вывода credentials.
Новое или расширенное согласие Google выполнять по действующим правилам
подтверждения; уже предоставленные права повторно не запрашивать без причины.

## Метаданные и загрузка

В описание добавлять уместные хештеги, соответствующие ролику и языку канала. Описание должно кратко относиться к ролику и при необходимости включать главы. По глобальному правилу ytvideos исследовательские источники и ссылки на них хранятся во внутренних материалах и по умолчанию не попадают в публичные метаданные; функциональные ссылки добавлять только по явному запросу или принятому стандарту. Отдельные настройки YouTube для изменённого или синтетического контента определять по содержанию ролика и действующим требованиям платформы.

### Порядок выпуска

1. Для нужной истории, языка и формата найти актуальный согласованный MP4 в `videos/NNN_<slug>/Deliverables/` и относящийся именно к нему внешний SRT. Сверить путь с журналом выпуска и корневым `AGENTS.md`, при необходимости проверить хеш. Не подставлять более старый, альтернативный или случайный экспорт только потому, что его имя похоже. Проверить длительность, звук, полное декодирование и соответствие SRT монтажу; реальные ограничения проверки зафиксировать.
2. Подготовить для этого ролика название и содержательное описание на языке канала: о чём история, ссылку на полный ролик при необходимости и, если уместно, главы. Проверить, что данные точны и соответствуют именно этому видео. Для глав проверить порядок, время первой главы, границы и соответствие фактической версии и длительности; если синхронизация на слух не проверена, не утверждать обратное. В названии и описании не упоминать AI; настройку раскрытия изменённого или синтетического контента определить отдельно по содержанию и требованиям YouTube.
3. До загрузки проверить через YouTube API канал авторизации и его точный ID, назначение плейлиста, соответствующий OAuth-токен и область доступа. Для Nuviko History использовать `nuviko-history/token.json`; для Paper Detour — `paper-detour/token.json`, а для операций управления — его `paper-detour/manage-token.json`. Токены старых назначений не использовать для новых выпусков. При истечении токена восстанавливать авторизацию именно целевого активного канала.
4. Загрузить проверенный файл отдельной командой `upload` с собственным файлом состояния для конкретной версии, канала и метаданных. Штатный загрузчик создаёт только `private`. Проверить по video ID принадлежность каналу, реальный статус доступа и окончание обработки; если API не подтвердил результат, не объявлять загрузку завершённой. Согласованный пользователем режим доступа проверять отдельно: `private` и `unlisted` различаются, а прежний режим отдельного выпуска не даёт разрешения делать новые видео публичными. Если нужен `unlisted`, после загрузки изменить доступ отдельной операцией с подходящим разрешением и снова прочитать его через API.
5. Добавить видео в нужный плейлист этого канала и проверить состав по ID. Штатный `add_to_playlist.py` работает только для `private`; для `unlisted` требуется отдельная операция с разрешением управления и проверкой владения и отсутствия дубликата. Приватность плейлиста и видео проверяются независимо. Не повторять запрос создания элемента, пока неизвестен результат предыдущего: сначала прочитать плейлист.
6. Для каждого применимого нового выпуска со звучащей речью, включая Shorts, загрузить проверенный внешний SRT на языке фактического принятого звука как отдельную ручную дорожку с токеном и разрешениями, поддерживающими управление субтитрами, и проверить именно её статус и язык через YouTube. Для английской дорожки Помпей подтверждён статус `serving`. Для private-видео есть отдельный `upload_caption_language.py` с ручными RU/EN SRT-дорожками и обязательной квитанцией загрузки; проверить его ограничения перед использованием для конкретного канала. Для другого состояния видео нужна соответствующая отдельная API-операция. Наличие SRT-файла не доказывает загрузку или качество синхронизации. Проверить воспроизведение с субтитрами по возможности и честно сообщить, что не удалось проверить.
7. Перечитать карточку видео и зафиксировать ID, ссылку, название, описание, главы, язык аудио и метаданных, фактический доступ, обработку, плейлист и состояние субтитров. Если пользователь просил заменить конкретную публикацию, сначала убедиться, что новая версия корректна и доступна в согласованном режиме, затем удалить только явно указанную старую публикацию и проверить её отсутствие. При неизвестном результате удаления сначала проверить состояние, а не повторять операцию вслепую. Проверить отсутствие случайных дублей, сохраняя прочие публикации. Передать пользователю ссылку и фактические ограничения проверки; обновить журнал и документацию без секретов.

Каждый из этих пунктов — работа ассистента в текущей сессии: существующий загрузчик и журнал не выполняют весь процесс автоматически. Для управления доступом, плейлистом, субтитрами или удаления могут потребоваться более широкие OAuth-права, чем для загрузки; использовать только уже предоставленный доступ или пройти отдельное согласие пользователя в Google.

### Отложенная публикация серии

После загрузки и проверки пользователь может поручить публикацию в конкретное время. Длинный фильм и первый Shorts планируются вместе; поддерживающие Shorts — по одному в день в согласованное время. Для Помпей ранее использовалось 19:00, для серии 009 пользователь позднее выбрал 16:00 `America/New_York`, но затем оставил её без расписания с доступом по ссылке. Не устанавливать время автоматически без действующего запроса. Для запрошенного времени вычислять UTC из даты и IANA-часового пояса с учётом переходов на летнее и зимнее время; время в Белграде также рассчитывать по `Europe/Belgrade`.

Команда `upload.py upload` сама не создаёт расписание. Для этого существует отдельный `schedule.py set`: ему нужны токен управления, квитанция загрузки, state и подтверждённая история never-published/private. Перед применением проверить его входы и действующее поручение по глобальному навыку, затем независимо перечитать состояние через `schedule.py read`. Для ещё не опубликованного запланированного видео `privacyStatus=private` вместе с нужным будущим `publishAt` — ожидаемое состояние; один `private` без `publishAt` расписания не подтверждает. После записи возможна задержка: при неопределённом ответе сначала повторно прочитать состояние, не создавая дубликат и не отправляя изменение вслепую. Зафиксировать в журнале ID, точную дату и UTC, местное время, факт подтверждения, доступ, обработку, плейлист и субтитры. Скрипты `Edit/schedule_video.py` внутри конкретных выпусков 005–008 привязаны к их видео и датам и не являются универсальным планировщиком.

На канале Nuviko History кнопка Related Video была недоступна до дополнительной проверки; ссылка на фильм в описании Shorts может быть некликабельной. Перед новым выпуском проверить текущее состояние канала, а не считать ограничение снятым.

Создать отдельные JSON-файлы метаданных для RU и EN. Пример ниже — форма, значения надо заполнить для конкретного выпуска. Категория должна быть действительной для канала; значения `made_for_kids` и, если применимо, `contains_synthetic_media` должен определить автор. `language` относится к названию и описанию, необязательный `audio_language` — к озвучке:

```json
{
  "title": "Название выпуска",
  "description": "Краткое описание выпуска и ссылка на полный фильм",
  "category_id": "22",
  "language": "ru",
  "audio_language": "en",
  "made_for_kids": false,
  "contains_synthetic_media": false,
  "tags": ["история", "shorts"]
}
```

Подставить свои пути и точный ID русского канала. Для английского повторить команду с `en-token.json`, английскими видео/метаданными, английским channel ID и другим state-файлом. Один и тот же state-файл нельзя использовать для другого ролика, версии, набора метаданных или канала. Для безопасного повторного обращения к состоянию загрузки Помпей сохранён исторический снимок исходных метаданных `videos/002_pompeii/Deliverables/002_pompeii_youtube_metadata_uploaded_snapshot.json`; актуальный файл метаданных обновлён после изменения описания и отличается от исходного снимка.

```sh
~/.local/share/story-youtube/venv/bin/python automation/youtube/upload.py upload \
  --token "$HOME/.local/share/story-youtube/ru-token.json" \
  --video /absolute/path/001_ru_shorts.mp4 \
  --metadata /absolute/path/001_ru_youtube.json \
  --channel-id UC_REPLACE_WITH_EXACT_CHANNEL_ID \
  --state "$HOME/.local/share/story-youtube/001-ru-upload.json"
```

На каждом реальном запуске и возобновлении сначала выполняется `channels.list(mine=true)`: ответ должен содержать ровно один канал, и его ID должен совпадать с аргументом `--channel-id`. При ошибке или несовпадении загрузки не будет. Результат содержит YouTube video ID и ссылку. Он сохраняется в state, поэтому повторная команда с теми же данными возвращает сохранённый ID без новой загрузки. Это относится только к использованию **того же state-файла**. Проверьте приватность и обработку через `status`; для визуальной проверки открыть сам ролик. Успешный ответ загрузки не означает, что обработка видео уже завершилась.

`requested_privacy=private` в ответе `upload` — это запрошенный режим при
загрузке, а не повторная проверка текущей приватности. `current_privacy=null`
означает, что текущий статус этой командой не проверен; используйте `status`.

После загрузки можно отдельно запросить фактические статус приватности и обработки по ID ролика:

```sh
~/.local/share/story-youtube/venv/bin/python automation/youtube/upload.py status \
  --token "$HOME/.local/share/story-youtube/ru-token.json" \
  --channel-id UC_REPLACE_WITH_EXACT_CHANNEL_ID \
  --video-id=VIDEO_ID
```

Команда только читает API, сначала проверяет канал владельца и затем принадлежность видео этому каналу. `privacy`, `upload_status`, `processing_status` и причины ошибок отображаются в JSON; `null` означает, что Google не вернул поле, а не успешную проверку. Сам по себе статус API не заменяет просмотр ролика и не подтверждает отсутствие ограничений или претензий к нему. Эта команда не изменяет журнал выпуска и не выполняет загрузку.

### Сопоставление read-back без ложных расхождений

При проверке сохранённых полей учитывать фактическую форму ответа, сохраняя исходный ответ и точный результат сравнения:

- **Описание:** сначала сравнить буквально. Если API нормализовал только завершающий перевод строки, принять это отдельно; не применять общий `strip()` или сворачивание пробелов. Не применять общий `strip()`, сворачивание пробелов или нормализацию внутренних абзацев: они могут скрыть потерю текста.
- **Субтитры:** автоматическая дорожка `snippet.trackKind=asr` не является повторной ручной загрузкой. Сравнивать ожидаемую ручную дорожку по ID, языку, типу и статусу; для выборки уже есть `manual_tracks` в `upload_caption_language.py`. Если проверяется содержимое, скачать именно её и сопоставить текст/таймкоды с принятым SRT. Количество всех дорожек одного языка не доказывает наличие дубля; неизвестный тип не считать подтверждённым ручным.
- **Необязательные поля:** отсутствие ключа не равно проверенному `false`. Сохранять отдельно отправленное значение, факт отсутствия в read-back и доступное подтверждение сохранённого состояния. Без такого подтверждения поле остаётся непроверенным. Не повторять запись только ради появления отсутствующего ключа.

Примеры прошлых read-back остаются в отдельных release receipts. Они не заменяют чтение актуального ресурса и не повышают статус непроверенных полей.

Чтобы добавить приватный ролик в принадлежащий каналу плейлист, используется
`youtube/add_to_playlist.py` с отдельным токеном `youtube.force-ssl`. Это более
широкое разрешение, чем загрузка: оно даёт доступ к управлению YouTube,
включая изменение и удаление видео. При подключении Google спрашивает
согласие владельца канала. Скрипт сверяет канал, приватность и плейлист,
проверяет наличие ролика до запроса и повторно читает плейлист после него. Штатный скрипт принимает только видео со статусом private. Фильм о Помпеях был добавлен отдельно после явной проверки его статуса unlisted, с использованием токена `history-manage-token.json`:

Пример штатного добавления приватного видео:

```sh
~/.local/share/story-youtube/venv/bin/python automation/youtube/add_to_playlist.py \
  --token "$HOME/.local/share/story-youtube/ru-playlist-token.json" \
  --channel-id UC_REPLACE_WITH_EXACT_CHANNEL_ID \
  --playlist-id PLAYLIST_ID --video-id=VIDEO_ID
```

При неизвестном результате или задержке отображения проверяйте плейлист
перед повтором; параллельные запуски и повтор до появления результата могут
создать дубликат. Публичный плейлист не меняет приватность ролика.

## Возобновление и осторожное восстановление

Файл состояния хранит идентификатор канала, хеш файла и метаданные; скрипт сверяет их при повторном запуске. Состояние блокируется от параллельного запуска. Прерванную загрузку можно повторить той же командой: скрипт спросит сервер о принятом диапазоне и продолжит, не полагаясь на локальную оценку. Для временных ошибок сети и 500/502/503/504 предусмотрены ограниченные повторы с паузами. Истёкшая сессия, неизвестный исход создания сессии, некорректный ответ и прочие ошибки останавливают процесс. Проверьте YouTube Studio перед удалением состояния или запуском с новым файлом состояния: если запрос завершился, но ответ потерялся, слепой повтор может создать дубликат. Не изменяйте исходный MP4 в ходе загрузки.

Состояние не является общей базой данных и не гарантирует защиту от дубликата при потере файла состояния, смене пути, ручной загрузке или сбое диска. Храните его до окончательной проверки ролика. Дальнейшее управление доступом и расписанием выполняется отдельно через API с нужными правами или в Studio; после изменения состояние нужно перечитать.

Тесты используют поддельный HTTP-клиент и не подключаются к Google. ### Создание отдельного непубличного плейлиста

`create_unlisted_playlist.py` перед созданием проверяет ID авторизованного
канала и совпадения названия; до единственного POST записывает защищённый
журнал с неизвестным исходом. После успешного ответа сохраняет возвращённый ID
в этом журнале и делает не более пяти чтений (с паузами по две секунды), пока
плейлист не появится. Проверяются ID, единственность названия, владелец и
`unlisted`. Неожиданные значения, ошибка чтения или отсутствие плейлиста после
попыток оставляют исход неизвестным. Автоматического повторного POST нет.
Существующий журнал блокирует повторную попытку: сверить YouTube Studio или API
и сохранить результат отдельной записью, не удаляя исходный журнал.
