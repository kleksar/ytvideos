## Восстановление и безопасная передача

Для точного воспроизводимого reference нужен исходный принятый файл из независимой резервной копии/хранилища владельца. Не перегенерировать картинку по описанию, не экспортировать уменьшенный preview из публикации и не подменять кадром другого выпуска. После восстановления:

1. Проверить визуальное совпадение с исходным принятым материалом и подтверждение владельца.
2. Сохранить под отдельным устойчивым путём `channels/paper_detour/brand/References/<descriptive-name>.<ext>`.
3. Записать источник, назначение, дату приёмки и SHA-256 в соседний manifest; проверить, что ссылка открывается из чистого клона.
4. Добавлять только канально-общий asset; материалы текущих выпусков и их лицензии/источники остаются отдельными.

## Шрифты и бумажные буквы

[`TYPOGRAPHY_STANDARD.md`](TYPOGRAPHY_STANDARD.md) фиксирует пользовательский стиль: буквенные формы выглядят вырезанными из бумаги, а подтверждённый набор TTF/OTF и полная таблица глифов отсутствуют. Не объявлять системный или похожий шрифт точной копией бумажного wordmark. Монтажные субтитры отдельно используют файл шрифта macOS `ChalkboardSE.ttc` в [Paper-профиле](../../../automation/ffmpeg_montage/profiles/paper.json); этот системный файл в Git не включён.

Если владелец отдельно одобрит цифровой шрифтовой пробник для крупных букв, Fredoka — законно распространяемый кандидат с округлыми жирными формами: [страница Google Fonts](https://fonts.google.com/specimen/Fredoka) и [официальный SIL Open Font License 1.1 в Google Fonts](https://github.com/google/fonts/blob/main/ofl/fredoka/OFL.txt). Это только возможный пробник, не выбранный брендовый стандарт и не включённый в репозиторий шрифт. Для передачи самого файла нужно сохранить лицензию/авторские уведомления и соблюдать ограничения OFL, включая запрет продавать font software отдельно. Результат требует отдельного визуального утверждения: типографика не станет бумажной сама по себе.
