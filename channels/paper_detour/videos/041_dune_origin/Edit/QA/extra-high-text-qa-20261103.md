## Точная задача

Ты — консультант в уже открытом ChatGPT Extra High. Требование внешнего координатора выполнено этим обращением; ответь здесь без рекурсивных консультаций. Узкая задача: предложи минимальные исправления процедуры QA для четырех подтвержденных дефектов Paper Shorts. Правила уже требуют: только текущее произносимое слово желтое, предыдущее кремовеет; строка от первого до последнего кадра без gaps; верхний оптический центр для отдельного акцента; акценты — бумажные вырезанные буквы по PNG-эталону, отличный стиль от субтитров. Фактический 041: нативный karaoke накопительно окрашивает слова; фразовые клипы кончаются по SRT раньше следующего; акценты сделаны native text сбоку; QA записал PASS по 256 contact-sheet кадрам, хотя на них видны пустые строки и накопительная окраска. В required_checks не включены отдельно непрерывность, эксклюзивная подсветка, геометрия и стиль акцентов. Не утверждай неизвестную реализацию движка. Дай кратко причины сбоя и конкретные критерии PASS/FAIL и раннюю короткую пробу, чтобы повтор не дошел до полного рендера. Без нового большого workflow.

## Завершённый ответ

Корневая проблема QA: проверялось наличие и читаемость элементов, но не соответствие фактического рендера четырём обязательным визуальным инвариантам. 256 contact-sheet кадров не обеспечивают PASS, если обнаруженные нарушения не блокируют приёмку.

1. Минимальные исправления required_checks

| Дефект и подтверждённая причина | Критерий PASS / FAIL |
|---|---|
| Накопительная подсветка. Фактическое поведение native karaoke нарушает правило эксклюзивности. Внутренний механизм неизвестен. | PASS: на каждом кадре с подсветкой ровно одно произносимое слово жёлтое; предыдущие и будущие кремовые. FAIL: одновременно жёлтые два слова либо подсветка не соответствует текущему слову по word_map. |
| Разрывы субтитров. end фразового клипа берётся из SRT и оказывается раньше start следующего. | PASS: покрытие кадрами непрерывно от первого до последнего кадра видео. Каждый следующий cue начинается на кадре, следующем за окончанием предыдущего. FAIL: хотя бы один кадр без строки. Паузы закрываются удержанием предыдущей фразы. |
| Неверная геометрия акцентов. Native text размещён сбоку вместо верхнего оптического центра. | PASS: визуальный центр видимых букв совпадает с утверждённой верхней зоной и anchor с допуском по эталону. FAIL: боковое положение, смещение относительно эталона либо выход из safe area. |
| Неверный стиль. Native text заменил утверждённые бумажные PNG-буквы. | PASS: акцент использует утверждённый PNG-эталон или визуально идентичный ему материал, отчётливо отличный от субтитров. FAIL: обычный шрифт субтитров, отсутствие бумажной фактуры или заметное отличие от эталона. |

Каждая проверка должна иметь отдельное поле PASS/FAIL в required_checks. Итоговый PASS разрешён только при четырёх PASS.

2. Ранняя проба вместо полного рендера

Один тестовый фрагмент 8–12 секунд, специально выбранный так, чтобы одновременно присутствовали:

- Не менее трёх последовательных слов с переключением жёлтого цвета.
- Граница двух фраз, на которой SRT раньше создавал пустые кадры.
- Один верхний акцент с утверждённым PNG-стилем.
- Достаточная длительность после смены слова, чтобы выявить сохранение прежнего жёлтого цвета.

Проверить получившийся MP4 покадрово, сопоставляя изображение с word_map, временными границами фраз и эталонным PNG.

STOP: любое нарушение блокирует полный рендер. После исправления повторяется тот же короткий тест.

3. Исправление решения QA

Установить три обязательных правила:

1. Metadata PASS ≠ Visual PASS. Корректные delivery=word, highlight=karaoke и наличие PNG не доказывают правильного отображения.
2. Любой видимый дефект = FAIL. Если на contact sheet замечено накопление жёлтого или пустая строка, нельзя ставить PASS независимо от количества остальных корректных кадров.
3. Покрытие проверять автоматически, визуальные свойства — по декодированному видео. Для интервалов субтитров проверять отсутствие gaps; для подсветки, геометрии и фактуры использовать реальные кадры и утверждённые эталоны.

4. Минимальный критерий готовности

required_checks должен блокировать выпуск при нарушении любого из четырёх инвариантов, а короткая проба должна выявлять известные дефекты 041 до полного рендера.

Дополнительные этапы производства не нужны. Нужно сделать существующие QA-проверки обязательными, независимыми и способными выдавать FAIL на фактически обнаруженные нарушения.

## Применение и ограничения

Приняты отдельные обязательные проверки и ранняя проба. В кадровой модели проекта end исключающий: end предыдущей группы равен start следующей; формулировка консультанта о «следующем кадре» не означает прибавление пустого кадра. Фиксированные 8–12 секунд не стали общим обязательным нормативом. Консультация не является независимой проверкой MP4 или источником сведений об алгоритме Palmier.
