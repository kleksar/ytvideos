# Очередь выпусков Scenes on Repeat

Сюда складывайте принятые мастера для будущих партий. Один каталог на фильм, один подкаталог на ролик. Для первого пакета [«Грань будущего»](edge-of-tomorrow-2014/) здесь есть ссылка на уже принятые файлы. Раскладка и проверка очереди работают из корня `ytvideos`.

```text
channels/scenes_on_repeat/
├── ReleaseQueue/
│   ├── YOUTUBE.json                 # Снимок каталога канала с отметкой времени
│   └── <film-slug>/Deliverables/
│       └── <clip-id>/               # MP4, SRT и применимая упаковка
└── videos/<film-slug>/
    ├── RELEASE.json                 # Точная версия, пути, SHA-256, метаданные
    └── RELEASE_STATE.json           # Роль ролика, исходы операций и проверки
```

Чтобы добавить фильм, создайте `ReleaseQueue/<film-slug>/Deliverables/` и одноимённую папку выпуска в `videos/`. По [примеру первой партии](../videos/edge-of-tomorrow-2014/RELEASE.json) зарегистрируйте материалы и точные хэши. В `RELEASE_STATE.json` запишите состояние каждого ролика по его `id` и `mp4_sha256`. Для нового ролика без попыток загрузки это `upload: not_started` и `video_id: null`. Для ролика с речью включите проверенный английский SRT. Права на публикацию, факт приёмки и материалы проверки фиксируйте у выпуска. Храните файлы одного выпуска в одном месте. Если принятый мастер уже лежит в стабильной папке, очередь может указывать на него.

В поле `release_role` отметьте лучший принятый Short фильма как `lead` и запишите причину в `selection_reason`. Остальным принятым сценам присвойте `reserve`. На фильм допускается один `lead`. Старые записи без роли отображаются как `unassigned` и ждут решения. Роль отвечает за порядок выхода, а состояние загрузки, права и ограничения проверяются отдельно.

```sh
python3 channels/scenes_on_repeat/automation/queue_status.py --verify-files
```

Скрипт читает локальные записи и сохранённый снимок YouTube. С опцией `--refresh-token /путь/к/локальному-токену` он получает свежий каталог с YouTube и сохраняет новый снимок. Для этого используйте окружение и OAuth из [инструкции YouTube](../../../automation/youtube/README.md). Содержимое токена в очередь не помещается.

Отчёт показывает время снимка и останавливается при повторном video ID или MP4. `LOCAL` означает, что по записи передачи ещё не было. `UPLOADED_PRIVATE` и `UPLOADED_UNLISTED` требуют совпадающего video ID в снимке. `SCHEDULED` означает приватное видео с подтверждённой будущей датой. `PUBLISHED` означает публичный доступ по данным снимка. `CHECK_*` и `POSSIBLE_DUPLICATE` требуют сверки. Просроченный слот с приватным доступом отображается как `CHECK_SCHEDULE`. Права проверяются отдельно от статуса файла и платформенных ограничений.

## Как выпускать партиями

1. По команде «Покажи запас и следующие свободные слоты» обновите `YOUTUBE.json` по подтверждённому каналу, включая приватные, ролики по ссылке, публичные и `publishAt`. Сверьте уже известные video ID и неизвестные результаты. Поиск по названию сигнализирует о возможном дубликате. Привязку конкретной версии подтверждает квитанция, содержащая video ID и хэш файла. В первую волну берите по одному `lead` от разных фильмов и сверяйте, не назначен ли выход сцены того же фильма. Подготовьте локальный план с датами, временем, часовым поясом и роликами. При нехватке первых сцен предложите более короткую партию.
2. По команде «Загрузи партию для проверки» загрузите перечисленные проверенные MP4 по [канальному правилу первой загрузки](../AGENTS.md#проверка-перед-открытой-публикацией). Сразу после получения ID запишите его в состояние выпуска вместе с квитанцией. Сверьте обработку, ограничения Studio, ручной SRT, упаковку и фактический доступ. Если отправка прервалась с неизвестным исходом, записывайте `upload: outcome_unknown` и сверяйте YouTube до повтора.
3. По команде «Поставь эту партию в расписание» заново проверьте календарь, права и ограничения. Назначьте время одобренным роликам после проверки доступности этой операции для каждого video ID. YouTube назначает отложенный выход приватным видео. Запишите фактический `publishAt` только после чтения сохранённого значения и обновите снимок. Если загрузка и расписание уже разрешены одним поручением с конкретной партией, выполните их в одном проходе. Порядок проверки, хранение квитанций и очистка подчиняются [общему выпуску YouTube](../../../.agents/skills/ytv-youtube-release/SKILL.md) и [правилам канала](../AGENTS.md#проверка-перед-открытой-публикацией).

Резервные мастера остаются в очереди. Когда первая сцена фильма уже вышла, предложите конкретную резервную сцену на следующую волну. Сравнивайте результаты первых сцен за одинаковое время после публикации и учитывайте, насколько резерв отличается от уже показанного фрагмента. При планировании разносите ролики одного фильма по разным неделям.

Рабочий ориентир — три Shorts в неделю. Для первых двух недель подберите до шести разных фильмов. Свободные слоты и размер фактической партии определяются при каждом запуске с учётом календаря и лимита загрузки. [Подбор фильмов и запас](../research/20261108-eight-week-slate.md).
