# You But Weird: Short из готового Long

Канальный рецепт для порученной вертикальной адаптации **существующего You But Weird Long**. Не заменяет исторические licensed-clips форматы Scenes on Repeat, Nuviko History/Paper или их ChannelSpec. Не меняет уже принятые файлы и не разрешает публикацию. Параметры pinned run изменять только по [migration](../../../docs/migration.md).

## Монтаж и геометрия

- Использовать точный принятый Long/master и существующую английскую речь, музыку и эффекты. **По умолчанию ноль новой TTS**: не переписывать и не переозвучивать отрывок ради Short. Сохранить source hash, выбранные интервалы и карту перехода source → output. Проверить права на повторное использование музыки/изображений; исходные credits не теряются.
- Финал **1080×1920, 30 fps**. Резкая фиксированная панель **1080×1080** по центру: x=0, y=420. Весь вертикальный фон заполняет увеличенная размытая версия **того же кадра в то же время**, без отдельного движения или рассинхрона. Квадрат не растягивать и не двигать между сценами.
- Внутри постоянной панели подбирать масштаб и положение **для каждого плана** по фактическому действию: лицо, руки, ремень, дверь, вода, смысловая надпись должны оставаться понятными. Один blind center-crop для всех сцен непригоден. Сохранять пропорции, плавность исходного движения и отсутствие чёрных краёв; не добавлять произвольный zoom ради заполнения квадрата.
- Начинать прямо с понятного действия и полной фразы, без вспышки заставки/обложки на несколько кадров, случайного переходного кадра, пустой паузы или обрезанного слова. Конец выбирать по принятой драматургии отрывка и чистой склейке, а не по универсальному числу секунд. Не вводить общий обязательный хронометраж вроде «ровно 38 секунд»; общие требования Short и согласованная граница остаются применимыми.
- Rewind как конкретный пример: первый кадр — герой в затопленной машине, первая фраза **“Your car is underwater”**; конец — силуэт **до спасения**. Это выбранная граница данного отрывка, не правило обрывать развязку всех будущих историй.

## Одна строка субтитров без исчезновений

Использовать проверенный History renderer [nuviko_long_subtitles.py](../../../automation/subtitles/nuviko_long_subtitles.py), а не другой EN v5 renderer по похожему имени. Его маршрут описан в [README](../../../automation/subtitles/README.md), внешний стиль — [nuviko.json](../../../automation/ffmpeg_montage/profiles/nuviko.json): Georgia Bold, кремовый текст, выделение текущего слова, тёмная плашка. Для этой адаптации перенести **поведение одной строки**, задав actual vertical canvas/FPS, геометрию и безопасное положение по кадру; не копировать размеры длинного History видео. Сам Nuviko профиль от этого не меняется.

`resegment_map` удерживает первую группу с кадра 0, каждую следующую до начала следующей группы, последнюю до конца; `main` выбирает состояние по середине кадра. В промежутках между произнесёнными словами группа остаётся **нейтральной**, без ложного выделения предыдущего слова. Склейка картинки не сбрасывает текст. Группы смысловые, помещаются в одну строку; синхронизация относится к фактической выбранной речи, не к приблизительному тексту сценария. Renderer сам alignment не создаёт.

Должен быть **один** subtitle layer. Если captions уже запечены в исходник, брать доступный чистый мастер/слои или разрешать конкретную композицию до наложения; не рисовать вторую копию поверх первой. Сюжетные слова внутри рисунка отличать от субтитров и сохранять, когда они нужны. Проверять реальную Shorts safe area, UI справа/снизу, телефонный размер и читаемость; удачная координата одного ролика не универсальный preset. Процедура — [production examples](../../../.agents/skills/ytv-produce-video/references/production-examples.md#вертикальная-адаптация-you-but-weird-long).

## Статус метода

18.11.2026 исходный код History renderer и ссылки проверены в репозитории. Frame coverage проверяется receipt `uncovered_frames=0`, но это не доказательство правильного текста, sync или читабельности. Фактический render/playback/approval каждого Short фиксировать отдельно по exact output hash; этот документ не объявляет новый Short проверенным, принятым или загруженным. Скрипт использует Georgia Bold из macOS: на другом executor сначала проверить доступность зависимости, не подменять шрифт молча.
