# Подготовленный сюжетный пакет

Текстовый handoff для illustrated-рецепта: **сюжетный MR принимает редакторские и постановочные решения; локальный production исполняет их**. Это необязательный вход обычного run, не новый workflow, не третий approval и не обязательный bundle для «дай идеи». Схема не включает медиа; реальная проверка картинки, звука, длительности и прав остаётся после получения конкретных файлов.

Владелец требований к художественной постановке — [visual](../standards/visual.md), к рассказу/вариантам — [editorial](../standards/editorial.md), к звуку — [audio](../standards/audio.md). Процедура подготовки и использования — [production reference](../../.agents/skills/ytv-produce-video/references/preproduction.md). Здесь только структура входа, проверки и граница с runtime.

## Что должно быть готово в MR

Для каждого варианта, предлагаемого к производству, сохранять собственный `preproduction.json` рядом с exact `script.en.txt` и полным `script.ru.txt`. Варианты одной истории разделяют проверенные источники, но не автоматически одну раскадровку. В README рядом с EN/RU указать выбранный канал, **Short/Long отдельно от целевой длительности**, hashes и статус комплектности. Рекомендованный вариант не является одобрением владельца.

| Уже решено в MR | Остаётся на локальном host |
|---|---|
| Точный EN master/RU перевод, фактология, редакционная оценка, применимый независимый review | Зафиксировать выбор владельца и импортировать тот же master; не выбирать сюжет и не повторять editorial review |
| Самостоятельные композиции и полное покрытие речи, подробные scene prompts | Сгенерировать подготовленные опоры и сцены; проверить фактический результат, исправить конкретный дефект |
| Персонажи, части реквизита, локации, роли эталонов, prompts reference sheets, таблица состояния | Получить/открыть реальные reference bytes, сверить hashes, зарегистрировать artifacts и связать сцены с ними |
| Метод каждого плана, камера, склейки, начальное/конечное состояние; черновики движения и звука | Разметить фактическую запись, получить окончательные окна; сверить motion prompt с готовой картинкой |
| Звуковая дуга, accents по репликам, требования профиля; концепты упаковки | TTS/mix, word map/SRT, точный монтаж, thumbnail generation и QA; главы только по финальному времени |

Не называть простое деление текста по предложениям готовой раскадровкой. Каждый кадр обязан иметь самостоятельную визуальную функцию, геометрию и исполнимый prompt; «покажи эту реплику», одинаковый общий фон с другой цитатой или огромный повтор стилевого boilerplate этого не обеспечивают. Подробность определяется однозначностью действия/объектов, не числом слов. Для сложной сцены применять развёрнутое ТЗ по visual standard.

До медиа допустима только **оценочная** плотность/длительность. Проверить её на всём тексте; длинные биты разбить на отдельные готовые композиции уже в MR. Не выдавать число предложений за число итоговых кадров. При реальном расхождении темпа использовать подготовленные соседние/резервные композиции; нехватку покрытия исправить адресно, не сочинять заново весь фильм. Реальные intervals, цены, job IDs, результаты просмотра и audio/AV seam заранее не записывать.

## Схема ytv-preproduction-v1

Один переносимый JSON — источник production-решений, без второй расходящейся копии промптов в Markdown. Читать можно через review UI или человекочитаемый индекс в README; полный exact текст prompt хранится в JSON. Медиа/секреты/непроверенные provider handles в Git не включаются.

Обязательные верхние поля:

| Поле | Значение |
|---|---|
| `schema` | `ytv-preproduction-v1` |
| `channel_id`, `format` | ChannelSpec ID и `short`/`long`; не менять профиль ради прохождения |
| `script_sha256` | SHA-256 **точных UTF-8 bytes**, включая переводы строк, выбранного EN master |
| `profile_sha256` | `ytvideos.util.digest(profile)` того ChannelSpec, по которому подготовлен пакет |
| `assets` | Листы персонажей/деталей реквизита/локаций/стиля: поля ниже |
| `scenes` | Упорядоченные самостоятельные композиции, без пробелов/повторов покрытия речи |
| `audio_plan` | Полное текстовое ТЗ: голос/скорость из профиля, произношение без смены слов master, музыкальная дуга, шумы и accents по репликам/ID, права и неразрешённые источники |
| `packaging_brief` | Полный текст обещаний/концептов названия и обложки по профилю, early proof и payoff; не фиктивный ReleaseSpec с выдуманными run IDs |
| `edit_plan` | Правила монтажа, последовательность/склейки, локальная привязка к записи, субтитры, применимые loop/end-screen; без выдуманных таймкодов |
| `open_items` | Список `{stage, reason, resolution}`; пустой только при отсутствии известных содержательных пробелов. Планируемая генерация сама по себе не blocker |

У каждого asset есть устойчивые `id`, `kind` (например character/prop/location/style), `mode`. При `mode: generate` требуется **полный prompt листа/эталона**, состояние и перечень нужных видов внутри него. Это ещё не существующий файл. При `mode: existing` требуются repository-relative `path`, `sha256` и `role`; описание и hash не доказывают просмотр. Реальный источник, права и ограничения реконструкции сохранять в исследовании и ТЗ. Неизвестный необходимый эталон — `open_items`, а не придуманный hash. Для нескольких одинаковых предметов закреплять один тип детали и число экземпляров.

У каждой сцены обязательны:

- `id`, `visual_intent`, `prompt`: независимое полное задание на **одну** композицию. Указать канальный стиль, формат и crop, план/ракурс, положение камеры, FG/MG/BG, субъекты и их позы, собственные координаты/число/крепления предметов, свет, состояние до действия, нужный текст, неизменные признаки и ограничения. Не заменять prompt narration-цитатой. Actual reference images добавляются локально, не симулируются описанием.
- `narration: {start, end, text}`: полуоткрытые индексы **Unicode-символов**, не байтов/слов/секунд, в декодированном exact EN master. `text == script[start:end]`. Все spans подряд полностью покрывают master, включая whitespace. RU соответствия и перевод проверяются отдельно в сценарном review; эти offsets не являются SRT.
- `asset_ids`: существующие в `assets` ID нужных видов/эталонов; при пустом списке — содержательный `reference_na_reason`. Это не runtime artifact IDs. Локально разрешить их в `references` с настоящими artifact IDs до image dispatch; незагруженный эталон не подменять пустым массивом.
- `continuity`, `camera`: состояние объектов до/после, связи со смежными кадрами, изменения и причины; направление/пределы движения камеры. Согласовать всю историю, не только соседнюю пару.
- `motion: {method, brief}`: `hold`, `pan_zoom` или `flow_ingredients`. Указать зачем движение, что именно меняется и остаётся неизменным, направление, порядок, финальное состояние. Для Flow это **авторский черновик**, не утверждение о точном файле/параметрах будущей партии.
- `sound`, `checks`: шумы/акценты по репликам и список конкретных условий приёмки сцены (геометрия, количество, состояние, руки, текст, свет, связь с речью). Общий «quality PASS» не заменяет их.

`start_frame`, `end_frame`, `start_seconds`, `end_seconds` в этом исходном пакете запрещены: окончательные интервалы принадлежат локальному монтажу по реальной записи. Оценочные заметки должны быть явно названы оценочными и не уходить в renderer как измерение. Технический validator проверяет структуру, identity, coverage и буквальные дубли prompts, **не** честность исторической реконструкции, глубину текста или качество будущей картинки.

### Google Flow

Метод выбирается в MR только если его задают текущие channel/format references. Сейчас он подключён рецептом Paper Short; пакет Nuviko Long не может самостоятельно включить его. Для остальных сцен остаётся их собственный рецепт. Квоты «анимировать X%» нет: рассмотреть начало и значимые действия по [Flow recipe](../../channels/paper_detour/docs/FLOW_PRODUCTION.md#выбор-движения).

Точный animation prompt уточняется **после осмотра конкретного опорного изображения**, из его фактических предметов/положений; модель, resolution, длительность и стоимость проверяются в текущем UI. Это необходимое завершение заготовки, не новый выбор сюжета. Каждая партия требует отдельного реального одобрения до передачи файлов/промптов. Source-пакет не подключает Flow adapter: действующая ручная граница и проверки сохраняются.

## Проверка до PR

```bash
uv run python -m ytvideos.preproduction \
  --file PATH_TO_VARIANT/preproduction.json \
  --script PATH_TO_VARIANT/script.en.txt --channel CHANNEL_ID --format long
```

Подставить фактические пути/канал/формат. Команда read-only, не создаёт run и не вызывает providers. Возвращает структурный PASS либо ошибку, число сцен/опор и Flow-сцен, открытые пробелы; `content_review: UNVERIFIED`, `timing: unmeasured`, `production_authorized: false`. Структурный PASS не равен готовности пакета: проверить все смысловые требования выше и явно перечислить остаток в README/handoff. Без настоящего независимого reviewer остаётся редакционный кандидат, не поддельный script gate.

## Локальный импорт без перепроектирования

Обычный `start --source-script PATH_TO_VARIANT/script.en.txt` сохраняет exact master и возвращает run. По настоящему поручению владельца координатор использует прежний [импорт принятого source](../workflow.md#принятый-источник-без-повторной-редакции), добавив подготовленный пакет **той же версии/commit**:

```bash
uv run python -m ytvideos.source_script \
  --run RUN_ID --revision SHOWN_REVISION --sha256 SELECTED_SCRIPT_SHA256 \
  --source ACTUAL_OWNER_MESSAGE_REF --message 'точное поручение владельца' \
  --origin IMMUTABLE_PR_COMMIT_AND_SCRIPT_PATH \
  --preproduction PATH_TO_VARIANT/preproduction.json
uv run ytv plan --run RUN_ID
```

Все placeholders заменить реальными значениями. Флаг необязательный; старый source-only импорт работает без пакета. Другой master/hash/ChannelSpec или формат отвергаются **до принятия текста**. Точные bytes сохраняются в artifact store, SHA-256 — в pins и исходном событии принятия; повтор этого события с другим/исчезнувшим пакетом отвергается. Оригинальный файл после импорта не рабочая зависимость. Все task input hashes включают эти pins. Нельзя подложить пакет поверх уже принятого source или активного/UNKNOWN производства: сохраняется прежний recovery/revision flow.

Передача пакета сама по себе **не** разрешает производство: импорт требует подлинного выбранного source и сообщения владельца по прежней trust boundary. Signed-only host не получает обхода. Одно атомарное действие регистрирует обычное принятие exact текста и его заготовки, без третьего gate, fake reviewer или auto-complete production.

Локальный worker читает descriptor `task_guide.preproduction.artifact` через `artifact_root`, проверяет bytes/hash и исполняет подготовленные решения в обычных storyboard/audio/packaging tasks. `plan.source_preproduction` показывает тот же вход. Ничто автоматически не переводится в complete: разрешить реальные references, пройти прежние coverage/continuity/rights проверки, сохранить обычный storyboard JSON и receipt. Его `scenes` происходят из source-пакета, с настоящими artifact IDs в `references` вместо подготовительных `asset_ids`; окончательные тайминги дополняются отдельно по звуку. Отдельным image workers передаётся их точная сцена, не весь пакет других сцен.

После явно порученной редакции master старый пакет остаётся `stale_baseline`, его spans/prompts не применяются к новому тексту. Исправить затронутые входы обычным task/revision flow, не менять pinned bytes. Старые active runs не получают новый код/документы незаметно: [migration](../migration.md). Массовая подготовка существующих PR и реальное производство — отдельные результаты, не следствие merge контракта.
