# Рендер, технический QA и MP4

Профиль ниже применяется к новым Paper Detour/Nuviko History review/upload export. Для иного канального рецепта использовать его разрешённые настройки, сохраняя общий контракт доказательств.

## Требуемые параметры

| Свойство | Значение |
|---|---|
| Short | 1440×2560, 9:16, square pixels, без запечённых полос |
| Long | 2560×1440, 16:9; явное творческое исключение фиксируется в профиле |
| Время | 30/1 FPS, progressive, фактический end frame exclusive |
| Container / codec | MP4 / H.264 AVC |
| Pixels | `yuv420p`, SDR Rec.709; primaries/transfer/matrix `bt709`, range `tv` |
| Audio | Принятый полный mix по [audio](audio.md), без автоматической смены каналов/скорости |
| Inputs | Hashes точного текста, mix, images, word map, subtitle contract, профиля и кода |
| Outputs | Новый artifact ID, URI/path, SHA-256, render provenance и delivery receipt |

2K здесь означает короткую сторону 1440 px. Длительность выводится из фактического числа кадров; 1502 кадра нельзя округлять до 1500. Корректное преобразование цвета/диапазона не равно замене metadata tags. Изменение принятого входа делает зависимые checks устаревшими.

Нормальный renderer — FFmpeg. Для x264 стартовый quality preset CRF 18 / medium; для поддерживаемого VBR ориентир 20 Mbps. Это практические настройки, не гарантия качества. Не навязывать average bitrate поверх CRF. Проверять бумажную фактуру, градиенты и края букв в реальном output. Encoder, конкретные arguments, профиль/GOP и фактический результат записывать; предпочтение и обязательное требование различать.

Проверить Fast Start и контейнерную совместимость. Если конкретная рекомендация не поддерживается encoder, отразить ограничение и решение, а не подделывать PASS. Отсутствие шрифта — конкретный blocker; не подменять утверждённую production-гарнитуру доступным системным шрифтом. Тестовая гарнитура относится только к тестам.

## До рендера

Сформировать единый export contract из фактических входов: run/channel/language/format, точная edit revision, frame count/FPS, параметры видео/полного звука, ссылки/hashes и render destination. Применимые обязательные UNKNOWN не допускают готовность. Проверить целостность путей, отсутствие чужого writer и текущее право выполнения.

Передать тот же contract renderer и QA. Сохранить реальные command, stdout/stderr summary, код/version, fonts/profiles, frozen plan и dependencies. Профиль и документация текущей ветки не доказывают, какой код создал исторический файл.

## После рендера

Проверить точный получившийся MP4, а не только return code:

- Decode, длительность, frame count/каденция, геометрия/SAR, codec/pixel/color/range и полный audio stream.
- Первый/последний кадр, каждая сцена и её границы, движения, концы/начала subtitle групп и паузы, end-screen interval.
- Отсутствие чёрных/пустых кадров, полос, повреждённых сцен, обрезанных лиц/надписей, скачков цвета, дрожания и повторов.
- Прослушивание фактической речи и полного микса, sync слов/изображений, громкость, пики, стыки, оба канала и применимый mono fold-down.
- Соответствие narration, scenes, titles/chapters и принятым художественным требованиям.

У каждой проверки метод, coverage, reviewer, inspected artifact hash, evidence, PASS/FAIL/UNVERIFIED/N_A. Контактный лист не подтверждает каждый промежуточный кадр; `ffprobe` не подтверждает прослушивание. Непокрытое остаётся UNVERIFIED. Независимость проверяющего не создаётся переименованием роли автора.

Дефект исправлять в минимальной области и повторять только затронутые checks плюс необходимую итоговую проверку. Для video-only исправления сохранять принятый звук, когда возможно; для audio-only — принятый video stream. Перекодирование lossy-файла не восстанавливает качество.

Пользователю передать доступный точный MP4 с hash, кратким итогом QA и реальными ограничениями. Approval относится к этому файлу. Последующее изменение bytes возвращает на соответствующую контрольную точку; более новый renderer сам по себе не отменяет прежний принятый MP4.
