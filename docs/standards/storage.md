# Артефакты, сохранение и очистка

Операционное состояние хранится в транзакционном store. Media — в явно выбранном artifact storage; Git хранит код, профили, правила, небольшие текстовые материалы и права. Чистый Git checkout не содержит всех рабочих выпусков и не гарантирует воспроизведение старого MP4.

## Владение и версии

Артефакт имеет ID, run/channel, роль, revision, URI, SHA-256, размер, фактические inputs и provenance. Рабочий путь принадлежит конкретному worker; абсолютный путь одного Mac не является глобальной идентичностью. Импортированный путь сохраняется, пока verified relink не докажет новое расположение.

Не перезаписывать принятую версию. Выдача указывает на текущий artifact; предыдущие версии сохраняются/очищаются по роли и зависимостям. Не хранить один и тот же факт одновременно в нескольких вручную редактируемых документах. `EPISODE.md` и `CURRENT_CONTEXT.md` — читаемые exports состояния, а не второй источник approvals.

Cache key включает точные inputs, код/профиль, модель/настройки и разрешённые параметры. При cache hit проверить blob/hash и применимость проверки. Одинаковый prompt не гарантирует одинаковые bytes стохастической генерации. Исправление одной сцены не требует перегенерации остальных; её зависимые montage/QA checks обновляются.

## Рабочая очистка

Адресно удалять завершённые временные прогоны, отработанные previews и отклонённый MP4 после фиксации причины, сохраняя нужные montage inputs. Перед удалением проверить ownership, активные зависимости, shared assets, импортированные originals и другие runs. Не делать рекурсивный cleanup по одному имени каталога.

После проверенного расписания и обработки либо Public действующее поручение разрешает завершить локальную очистку принадлежащих выпуску media в том же проходе. Сначала сохранить текстовый архив, версии, hashes, права, approvals, IDs/URLs и receipts; для будущего A/B сохранить или передать все нужные названия/обложки. Единственную копию нужного артефакта не удалять до проверенного сохранения/передачи.

Отдельный запрос оптимизации может применять ту же политику к завершённым Public/Unlisted, если фактическое состояние, идентичность и обработка заново проверены. Внешняя публикация не удаляется локальной cleanup. Восстанавливаемая корзина и перманентное удаление различаются; обязательные разрешения среды на безвозвратное удаление не обходить.

## Архив и recovery

`TEXT_ONLY` означает текстовый архив: побайтовое восстановление прежних media не гарантируется. Если требуется точное восстановление, хранить оригинальные blobs и проверить backup/restore. Очистка локального кэша при сохранённой verified remote copy и уничтожение единственной копии — разные операции.

В cleanup receipt записать исходный manifest, holds/dependencies, конкретные удалённые/оставленные пути, время, исполнителя, ошибки и финальный storage status. Непроверенный перенос не считать резервной копией. Общее хранилище и credentials к нему выбирать явно; не выгружать конфиденциальные материалы в произвольный внешний сервис.

Архивы, фактические журналы исследований, лицензии, brand reference packs и прошлые публикационные записи не являются инструкциями для нового run. Не переписывать их под новую архитектуру.
