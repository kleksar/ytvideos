# Проверки основной модели

Машинные contract tests проверяют переходы и последствия отказов. Cold-session eval проверяет, найдёт ли Luna процедуру и выполнит реальную творческую задачу по этим входам. Одно не заменяет другое.

## Повторение проверок

Создать отдельный checkout и пустой workspace/database. Дать новой сессии без истории анализа обычное поручение и путь к источникам. Не сообщать диагноз, ожидаемый маршрут, вердикт или исправление. Сохранять фактические команды и результаты инструментов, inputs, точные outputs и hashes, собственный ответ независимого reviewer, blockers и итоговое состояние. Если захвачен только самоотчёт или shell trace без остальных tool calls, явно назвать эту границу.

Проверять конечный артефакт, а не только зелёный receipt. Отдельно оценивать каждый обязательный критерий. Сохранить FAIL/UNVERIFIED и настоящие инфраструктурные вмешательства; не переписывать неудачную попытку после исправления. Новую версию проверять новой сессией на свежих входах. Paid media и публикация не входят в редакторский eval.

Contract tests подтверждают детерминированные переходы, hashes и отказные случаи. Поведенческий прогон подтверждает только наблюдённую задачу на указанной версии. Он не измеряет статистическую надёжность, стоимость, токены, удержание или качество всех будущих роликов.
