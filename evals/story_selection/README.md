# Проверка отбора и зрительского интереса

Владелец правил — [editorial](../../docs/standards/editorial.md#отбор-до-полного-сценария). Это тестовые материалы, не второй стандарт, не очередь выпусков и не разрешение на производство.

## Воспроизведённый дефект

В [PR #13](https://github.com/kleksar/ytvideos/pull/13) автор подготовил 184 слова и 14 сцен о телеграфе без батарей. Его self-review отмечал структуру/факты/петлю как PASS, независимый review — UNVERIFIED. Владелец после чтения отверг историю как скучную и слабую. Это подтверждённая редакторская обратная связь, **не** измеренные просмотры или удержание.

Точный [английский текст](rejected-telegraph.en.txt) скопирован из commit `722beb29e49ff182969d7ac17ffa444de76c07a4`; bytes проверены по Git blob SHA и SHA-256 в [cases.json](cases.json). Исходный PR и его прежние оценки не переписаны как будто такого результата не было.

Авторский разбор дефекта: заявка не сравнивалась с разными сильными историями; несколько реплик повторяют уже раскрытый результат «без батарей всё работает». Техническая проблема и её объяснение получили неоправданно длинную подачу для предложенной широкой аудитории. Это диагноз данной версии, не запрет научных и технических тем. Перенос поворота, новое прилагательное или новая обложка не устраняют отказ владельца.

## Что проверяется автоматически

```bash
python -m unittest discover -s tests -p 'test_story_selection_contract.py' -v
```

Проверяются сохранность исходника, целостность набора, ссылки skill/workflow на существующий общий owner и его присутствие в routing research/script/review. Это **не** автоматическая оценка увлекательности. Слово в Markdown, наличие 12 кандидатов и зелёный CI не означают хороший сценарий.

## Поведенческие пробы: NOT_RUN

[cases.json](cases.json) содержит восемь входов: ложное разнообразие, связный, но слабый для аудитории текст, провисающая середина, выдуманные ставки, спокойное полезное объяснение, неверная интерпретация просмотров, отказ от всего набора и искажающий русский перевод. Учебные сценарии обозначены как вымысел/модель; не использовать их как исторические факты.

Проверяющему выдавать только `case.input` и bytes файла, указанного в `script_file`. `expected_observations`, этот разбор и известный диагноз скрыть до ответа. Нужен ответ с точными местами и причинами; разные аргументированные оценки вкуса допустимы. Кейс с явным отказом владельца проверяет соблюдение поручения, не способность угадать вкус.

## Живой приёмочный прогон skill: NOT_RUN

До снятия draft у изменения сценарного процесса провести ограниченный прогон в доступном независимом модельном runtime:

1. Свежий автор получает обычную задачу «Подготовь сюжетный Draft PR для Paper Detour» и актуальный task context с новым skill, без подсказки «сделай 12 кандидатов» в пользовательском prompt. Повторить на другом канале/жанре с его реальным профилем. Область — текстовый eval; не создавать production media или новые внешние PR из теста.
2. Сохранить фактически прочитанные источники, рассмотренные разные истории, короткий список, причину выбора или отказа, точный EN+RU текст и версию требований. Временной/стоимостной бюджет ограничить заранее. Если профиль frozen, исследование возможно только в разрешённом исключении; статус не менять.
3. Другому проверяющему сначала дать сравнимые краткие заявки без указания победителя; разрешить «ни одна». Потом только начало выбранного текста, затем весь текст, затем seam. Спросить причину продолжать, конкретное место потери интереса, финальную отдачу; после этого отдельно дать источники для фактчекинга. Не выдавать ему самооценку автора.
4. Для сравнения старой/новой процедуры использовать одинаковый бюджет и общую стартовую область поиска; перемешать порядок/скрыть версии. Фиксировать и неудачи. Предпочтение reviewer — качественная проба, не доказанный рост просмотров; нужны несколько разных сюжетов, а не подгонка под один fixture.
5. Владелец сравнивает финальные русские версии. Отказ владельца и отсутствие внятной причины просмотра не усреднять «общим баллом». Неудачный текст не отправлять в производство. Результаты хранить отдельным новым eval result с точными inputs/outputs/hashes и ограничениями.

В этой правке независимый модельный прогон и аудитория YouTube **не проверены**. Нельзя снять draft только на основании статических tests. Авторская проверка patch не является новым независимым first-listener review.

## Внешние основания, прочитаны 2026-11-13

- [YouTube: content performance](https://support.google.com/youtube/answer/16559650?hl=en): платформа различает выбор просмотра, продолжение просмотра и удовлетворённость; рекомендует связывать идею с понятным интересом аудитории. Это основание разделять вопросы, не формула прогноза.
- [YouTube: разговор о Shorts, 28 января 2025](https://blog.youtube/creator-and-artist-stories/youtube-shorts-deep-dive/): практический опыт быстрого хука и компактных mini-stories. Число секунд — рекомендация участника разговора, не закон; не переносить его метрики на наш канал.

Ориентир 8–12 историй и сравнение трёх заявок — проектное решение для снижения выбора первого попавшегося факта, не научно установленный порог. Спрос и эмоциональный интерес оцениваются гипотезой до собственных сопоставимых публикаций. Источники этой заметки не вставлять в narration.
